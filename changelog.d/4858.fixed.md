Restoring a task, or a whole project, from the trash is now refused when it would leave a summary linked to its own subtask. A deleted task keeps its old outline position, so a live task that has since taken the parent position adopts the restored row; if the two were linked, every recalculation of the project then failed. Restore returns a 400 with `code: "cyclic_dependency"` and an `offending` list, and restores nothing. A project that was already unschedulable before the restore is not blocked.
