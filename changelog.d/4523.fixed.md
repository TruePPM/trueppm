- **A start-to-start or start-to-finish lag out of an in-progress task is no longer
  re-added on every status update**: the scheduler measured the link from where the
  task's *remaining* work starts, which moves forward with the data date, so each
  status update pushed the successor out by the lag again — `A -SS+10d-> B` with `A`
  started on 03-02 put `B` on 03-16 at a 03-04 status date and on 03-18 two days
  later, with nothing else changed. A started task (one with a recorded
  `actual_start`) is now measured from that `actual_start` by its SS and SF
  successors, so the successor stays put until the data date itself reaches it. The
  link also no longer marks the started task critical: its start cannot slip, so the
  task now reports the float its remaining work really has. This holds in the Python
  and Rust/WASM engines, in Monte Carlo, in schedule derivations, and in the schedule
  drag preview (#4523).
