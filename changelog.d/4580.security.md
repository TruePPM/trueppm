`revoke_api_tokens --commit` no longer re-dates a token that was revoked concurrently (between the dry run and the commit) or writes a second, contradicting audit row for it, and no longer reports or audits already-expired tokens as revoked. The commit now re-selects live tokens under a row lock; `--user` reuses the same service as password reset and off-boarding.
The self-service token revoke endpoints (`DELETE /me/api-tokens/{id}/` and the project and program token equivalents) likewise no longer re-date a token or write a second audit row when two revocations race; an expired-only account is still swept for its other credentials by `--all-personal`.
