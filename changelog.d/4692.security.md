`trueppm-scheduler`: `monte_carlo()` no longer lets a project with many calendars exhaust memory. Calendars with identical content now share one working-day index, each index is a single int64 array built without a Python day loop (about 95% fewer bytes), and a new `max_index_cells` budget (default `MAX_INDEX_CELLS`, 25M cells) refuses an oversized `(distinct calendars) x (index span)` product with `SimulationCapExceeded` before anything is allocated. Seeded results are unchanged. (#4692)
