- **Scheduler conventions on one page**: a new [Scheduler Conventions](https://docs.trueppm.com/features/scheduler-conventions/) reference, mirrored in the `trueppm-scheduler` README, lists every modeling rule the engine commits to, from lag units and the constraint set to float definitions and Monte Carlo sampling. Each rule links to the issue or ADR that decided it, and the rules that differ from MS Project and Primavera P6 are marked: calendar-day lag, whole-day units, the PERT shape, and rejected start-anchored links from summary tasks (#4136).
- **Monte Carlo documentation corrected**: the PERT sampler is now named precisely. It is a Beta distribution fitted to the classic PERT mean and σ = (P − O)/6, not the λ=4 Beta-PERT, so on a symmetric estimate its band is slightly narrower than @RISK's default (#4133). Seeded reproducibility is now scoped to the same numpy and `trueppm-scheduler` versions (#4099). The "well under 100 ms" timing claim now reads about 60–100 ms on a current laptop CPU, and a benchmark test keeps that figure honest (#3859). None of this changes how forecasts are computed.
- **Finish-to-Finish / Start-to-Finish convention decided**: an FF/SF-driven task stays contiguous and right-aligned on its pinned finish, as in MS Project. So on a network with FF/SF links, a Monte Carlo percentile can land before the CPM finish. This is now documented as a convention, and it is no longer listed under Known Issues (#3806).
