- **Explaining a schedule value is fast again on projects with a milestone**: the
  "why is this date what it is" derivation (`derive_value()`, behind the API's
  schedule explanation endpoint) re-ran the whole forward and backward scheduling
  pass on every call whenever the project contained any zero-duration milestone —
  about 140x slower at 10,000 tasks (1.5 ms → 205 ms per explanation, measured),
  and nearly every real project has a milestone. `schedule()` now keeps the
  milestone pass state it already computed with its result, and the derivation
  reads it instead of replaying the passes. Explanations are unchanged (#4524).
