**Scheduler:** `schedule()`, `monte_carlo()` and `derive_value()` now reject a non-string project `id`, project `name` or task `name` with `InvalidScheduleInput` when you build `Project`/`Task` objects directly, as `from_dict` and the Rust engine already did. Before, a project with `name=None` or a task with `name=5` scheduled without error in Python and failed in the WASM engine.
