A Start-to-Start or Start-to-Finish link out of a summary task can no longer reach the database by a route other than the dependency editor. Before, such a link left the project's schedule failing every recalculation until someone found and deleted it.

- **Structural edits are refused when they would make a task that drives such a link a summary.** Indent, outdent, reparent, and restoring a task from the trash return a 400 (`code: "summary_start_link"`) that names the blocking links. Creating a task or subtask under such a parent returns a 400 on `parent_id`. Undoing an outdent or a reparent that would do the same returns a 409 with the same code; it used to return a 500.
- **Imports skip the link and report it.** MS Project, CSV/Excel and Jira imports and template apply skip it, list it in the import's warnings, and import everything else. Seed loads skip it with a logged warning. Inbound task sync adds the task to the backlog instead of under its parent and says so in a `warnings` field.
- **Restores no longer revive it.** Restoring a task or a project from the trash, or undoing an ungroup, leaves such a link deleted when its predecessor has become a summary in the meantime.
- **A concurrent indent and new link can no longer both commit.** Creating an SS or SF link now takes the same row lock on the predecessor that the structural edits take.
- **CSV import results keep all their warnings.** The result now includes the warnings recorded while saving the import, which it used to discard.
