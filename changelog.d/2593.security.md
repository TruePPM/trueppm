With `web.realIpFrom` set, the Helm web tier passes an upstream `X-Forwarded-Proto` through to the API only when the request came from one of those trusted proxies, and substitutes its own scheme for any other peer. A client that reaches the web Service directly can no longer claim `https` and have Django treat the request as secure. With `web.realIpFrom` empty the header still passes through from any peer, as before. The web tier's `/static/` location now also forwards `X-Real-IP`, `X-Forwarded-For` and `X-Forwarded-Proto` like every other proxied location.
