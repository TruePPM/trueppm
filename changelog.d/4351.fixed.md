- **Helm: explicit `0`/`false` overrides are no longer clobbered back to the chart default**. Sprig's `| default` treats `0` and `false` as unset, so setting `replicas.web: 0`, `podDisruptionBudget.{api,worker,web}.maxUnavailable: 0`, `observability.otlp.{enabled,tracesEnabled,metricsEnabled}: false`, or `demo.backoffLimit: 0` silently rendered the opposite of what was configured. These four values — two related alert thresholds found during the fix (`alerts.thresholds.outboxDepth`, `alerts.thresholds.outboxOldestAgeSeconds`), and four probe `initialDelaySeconds` fields (`probes.{api,web}.{readiness,liveness}InitialDelaySeconds`, where `0` legitimately means "probe immediately") — now render the explicit value. The fix uses a presence-check guard rather than bare dot-access, so the chart's documented null-to-delete override idiom (setting a key to `null` to drop it) still falls back to the chart's own default instead of rendering empty.
