Real-time updates no longer drop an event that arrives just after a later one. Before this fix, an event could be lost when two server workers sent events on the same project in the reverse of the order they were saved. The Gantt could then show stale dates until the next refetch. A board event's `seq` is now a per-project counter with no gaps, in the order events were saved (it was a global id). The client holds a frame that arrives early for up to 750 ms, waiting for the frame before it, instead of discarding that earlier frame. An event later than that is still skipped until gap detection lands (#2848). **Integrators:** `seq` values are now numbered per project, starting above each project's old ids. A cursor saved before this release gets one `resync_required` (re-baseline to its `latest_seq`) the first time you reconnect with it, unless it was fully up to date at the upgrade, in which case you receive exactly the events since. Frame gaps no longer reveal how many events the whole installation produced (#4386).
