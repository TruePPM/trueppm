Real-time updates no longer drop an event that arrives just after a later one. Before this fix, an event could be lost when two server workers sent events on the same project in the reverse of the order they were saved. The Gantt could then show stale dates until the next refetch. A board event's `seq` is now a per-project counter with no gaps, in the order events were saved (it was a global id). The client holds a frame that arrives early until the frame before it lands, instead of discarding that earlier frame. **Integrators:** `seq` values are now numbered per project. A cursor saved before this release gets one `resync_required` (re-baseline to its `latest_seq`) the first time you reconnect with it. Frame gaps no longer reveal how many events the whole installation produced (#4386).
