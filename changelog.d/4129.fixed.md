Monte Carlo runs no longer risk a memory spike from many distinct dependency lags: the lag-delta table is stored as int32 (half the size, identical results) and a synchronous request whose table would exceed `MC_LAG_DELTA_CELL_CAP` (5M cells, about 20 MB) is refused with HTTP 400. `trueppm-scheduler`'s `monte_carlo()` gains a keyword-only `max_lag_delta_cells` (default unchanged).
