Fixed API responses that did not match their published schema, found by the nightly API fuzzer: `Idempotency-Key` refusals now carry `{"detail", "code"}` (`idempotency_key_too_long`, `idempotency_key_conflict`) and are declared beside each operation's own 400/422; response fields the server can omit (`ProgramScheduleTask`, `CostKpi`, `ProjectVelocity`, `SprintPulseTrend`, `SprintScopeChangeBulkResult`, ...) are now published as optional, so a client must not read them unconditionally; role refusals on comment, note, attachment and reaction writes no longer claim a required `code`; baseline decisions admit a blank `reason_code`; the standup walk always carries `reason`. A non-ASCII or control-character credential or connection secret is now a 400 instead of a 500, and three refusals that returned a bare JSON array (allocation `dry_run`, template publish with a malformed project id, read-only retro board) now return an object.
