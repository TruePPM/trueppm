Shell v2 Schedule (behind `shell_v2`): every action of the v1 Schedule toolbar without a control of its own in the v2 bar now sits in its **More** menu (Add milestone, Add phase, Ungroup, Undo last change, bulk Edit selection, Share, Capture baseline, Baselines…, Import from MS Project or CSV, Recently deleted, and Read/Author mode). Focus mode, the canvas CP-only view, task-name placement, progress pills and sprint bands are removed from the v2 page on purpose; v2's Critical only filter is its critical-path view. On a phone the v2 toolbar now sits above the schedule list with the legend beneath it, and its Filter, Critical only, Today and Add task act on the list. A blocked task wears a Blocked pill, the read-only demo takes the v2 opening state, and selecting a row no longer rebuilds the capped row list. When a project's dependency links form a loop, the v2 Schedule page says **Schedule couldn't be computed** and names the tasks in the loop, from a new read, `GET /api/v1/projects/{id}/schedule/feasibility/` (any project member), that asks the scheduler's own cycle check rather than inferring a loop in the browser. In the marker lane the commitment reads **Commit** beside the **P80** tick, and both carry the server's definition and the forecast's as-of date as a tooltip and as screen-reader text.
