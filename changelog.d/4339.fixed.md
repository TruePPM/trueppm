- **Sample reloads no longer fail after days of `demo-reset`**: each reload of a
  bundled sample on a new day added that day's copy of every calendar exception
  (PTO, holidays, shutdowns) beside the previous days' copies, because calendars
  outlive the sample teardown and the exceptions were matched on their resolved
  dates. After a few weeks of daily resets the stale copies formed a solid run of
  non-working days, which pushed a sprint's start and finish onto the same day and
  aborted the import on the `sprint_finish_after_start` check — failing the Helm
  `demo-seed` hook and the `demo-reset` CronJob. A reload now replaces the
  sample's own exceptions instead of adding to them (it also cleans up copies an
  earlier version left behind), so every task date matches a fresh load again.
  As a second line of defense, a seed sprint whose authored window falls entirely
  on non-working days is now imported one working day long instead of failing the
  whole import.
