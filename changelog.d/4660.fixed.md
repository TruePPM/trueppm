`GET /projects/{id}/schedule/derivation/` now declares `task_id` as optional (it is required only for CPM quantities and ignored for `p50`/`p80`/`p95`), and the MCP `get_schedule_derivation` tool takes `task_id` as optional so an agent can ask what drives P80 without inventing a task id. In the MCP tool signature `task_id` moved to the last argument; keyword callers are unaffected, positional callers must update.
