A critical-path edit on a large project no longer forces every connected client to re-fetch the whole task list. Moving the project finish re-anchors every task's late dates and float but moves only a few bars, so the `task_dates_updated` WebSocket event now ships the moved bars in full and every other changed row as a compact `float_tasks` array, where it used to send `truncated: true`. Because the moved bars still arrive as per-task rows, the reforecast panel ("What moved and why") can list them where it could only show a count before.
