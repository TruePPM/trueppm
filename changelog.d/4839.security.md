A personal access token, share link, or other durable grant created by a request that was already running when a password reset committed could survive the reset's revocation sweep, because the sweep cannot see an uncommitted insert. Creating a personal, project, or program token, a share link, a git-automation secret, an outgoing webhook (or editing, re-enabling, or repointing one), or a workspace invite now locks the caller's profile row, the same row a password reset and `revoke_api_tokens --user` / `--all-personal` lock, and re-checks the credential cutoff against the locked row. A grant that commits first is revoked by the sweep, and a request still carrying a credential issued before the reset is refused with a `401`. Project and program tokens remain unrevoked by a reset, as before.
