- **Monte Carlo uses far less memory on large projects (scheduler)**: the simulation's forward pass now runs over chunks of runs and keeps only each run's finish, instead of holding runs × tasks matrices for every run at once. The per-run milestone instant (a date ordinal, a start-of-day flag and a working-time deficit) is held for milestone and zero-duration-with-estimate columns only, not for every task, and above 32M cells (runs × tasks) the sampled-duration matrix is no longer held either: each task's column is redrawn a row block at a time from the generator position its draws started at. Peak memory for 50,000 tasks × 1,000 runs drops from ~2.1 GB to ~475 MB RSS (~785 MB where the sampled-duration matrix is held; 4,000 tasks × 2,000 runs: ~302 MB → ~186 MB traced), and a 5,000-task × 1,000-run project with 2% milestones, the largest the API's default caps admit, from ~261 MB to ~238 MB. Benchmarks assert the peak. Results are unchanged: seeded P50/P80/P95, the distribution and the sensitivity tornado are byte-identical for any chunk size and whether the matrix is held or replayed, checked by SHA-256 of the full result over a 400-project seeded fuzz corpus and the benchmark shapes. The durations stay float64, because three-point draws are continuous and float32 would move seeded percentiles. Above the replay threshold this is a trade of time for memory, not a free win: at 50,000 tasks × 1,000 runs the replayed matrix takes ~9.3 s, against ~5.7–6.2 s with the matrix held (the faster figure is the one the 8M-cell chunk budget entry, #4955, reports), because replaying draws each sampled column three times. Every project within the API's default caps (5,000 tasks × 1,000 runs) is below the replay threshold, holds the matrix, and pays nothing. `MC_TASK_CAP` (5,000) is deliberately left unchanged; re-evaluating it, and the floor still above the 250 MB target, is tracked in #4953. The `MAX_LAG_DELTA_CELLS` table is unaffected: it is keyed on distinct (dependency type, lag, predecessor calendar, successor calendar) and is independent of the run count.
