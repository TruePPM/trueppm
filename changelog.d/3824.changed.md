- **Monte Carlo uses far less memory on large projects (scheduler)**: the simulation's forward pass now runs over chunks of runs and keeps only each run's finish, instead of holding five runs × tasks matrices for every run at once. Peak memory for 50,000 tasks × 1,000 runs drops from ~2.1 GB to ~920 MB RSS (4,000 tasks × 2,000 runs: ~302 MB → ~186 MB traced), and a new benchmark asserts the peak. Results are unchanged: seeded P50/P80/P95, the distribution and the sensitivity tornado are byte-identical for any chunk size. The remaining floor is the sampled-duration matrix, which stays float64 and is sampled in full because three-point draws are continuous (float32 would move seeded percentiles) and the seeded stream is consumed column by column. Very large projects run somewhat slower (50,000 tasks x 1,000 runs: ~4.9 s unchunked → ~5.7 s, see #4955). `MC_TASK_CAP` (5,000) is deliberately left unchanged; re-evaluating it, and the memory floor still above the 250 MB target, is tracked in #4953. The `MAX_LAG_DELTA_CELLS` table is unaffected: it is keyed on distinct (dependency type, lag, predecessor calendar, successor calendar) and is independent of the run count.
