- **Fractional percent complete no longer schedules a day off** ([#5034](https://gitlab.com/trueppm/trueppm/-/issues/5034), [#5015](https://gitlab.com/trueppm/trueppm/-/issues/5015)):
  an in-progress task's elapsed days were float-truncated, so a 375-day task at
  18.4% counted 68 elapsed days instead of 69 and finished a working day late.
  The scheduler now takes the exact decimal floor of `duration × percent / 100`
  in the CPM pass, Monte Carlo and what-if shifts. The Rust/WASM engine applies
  the same rule and now parses percentages to the same value as Python, so a
  value such as `99.99999999999999` no longer reads as complete there.
  Whole-number percents schedule exactly as before.
