- **Scheduler: work before a project-ending milestone shown at the start of a day keeps its float**: when the milestone that ends the project falls on a midnight shown as the start of the next working day (for example `A(4d) -FS+2d-> M` placing it at Sunday midnight, shown on Monday), its predecessor was reported with zero total float and put on the critical path. Slipping the predecessor a day moves the milestone only to Monday midnight, which is still shown on Monday, so the finish does not change. In both the Python and WASM engines, such a milestone may now sit as late as the midnight that opens the next working day, and the predecessor keeps its day of float. A milestone shown at the end of a day (`A -FS+1d-> M`, Saturday midnight shown on Friday) is unchanged: a one-day slip moves its shown finish to Monday, so the predecessor's zero float is correct there. This regression was introduced during 0.4 development and was never in a tagged release (#4174). The float measure this fix uses is the shown day, not the underlying working-time position; a start-of-day milestone overstating a predecessor's float under that measure is fixed separately (#4183).
