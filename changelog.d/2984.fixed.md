Sprint sovereignty is now enforced by the server, not only by the Schedule view's Unscheduled gutter. A write that sets `planned_start` or `planned_finish` on an undated backlog-status task in a planned or active sprint (the rows the gutter shows as read-only) is refused for every role. Committed sprint tasks in any other status stay datable, so Gantt drag and Commit start are unaffected. `PATCH /tasks/{id}/` returns 400 with `sprint_committed_dates_locked`, and `POST /projects/{id}/tasks/bulk/` rejects that row. Rescheduling an already-dated sprint task is still allowed. Tasks now expose a read-only `dates_locked_by_sprint` field that reports the same verdict (#2984).
