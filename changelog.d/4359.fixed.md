- **Helm (web tier)**: the web pod's readiness probe checked `GET /`, which
  the SPA's fallback route answers with `index.html` on any pod that merely
  has nginx up — proving nothing about whether that pod actually serves a
  working bundle or a correctly configured proxy upstream. Readiness now
  checks `GET /asset-manifest.json`, a build-specific file the web
  ConfigMap gives its own `=404`-on-a-miss location so a broken deploy fails
  the probe instead of silently passing it. Liveness stays on `GET /`
  deliberately, since a missing bundle is a static condition a restart
  cannot fix. Also added `worker_shutdown_timeout 20s;` to the web image's
  nginx config: every deployment path proxies `/ws/` with an 86400s read
  timeout, and nginx's graceful `SIGQUIT` shutdown previously waited for open
  WebSocket connections to close on their own, holding a terminating pod open
  until Kubernetes' termination grace ran out and SIGKILLed it — costing
  ~30s per web rollout step and closing live sockets with code `1006` instead
  of a clean `1012`.
