Task write paths that previously broadcast a bare `task_updated` frame (subtask parent, estimate approval, suggestion accept, acceptance criteria, recurrence rules, phase edits, DoR transitions, CI acceptance ingest, retro carryover pull-to-sprint) now carry `changed_fields`, `version` and `actor_id`. `version` is `null` when only a child row changed, and `actor_id` is set only where the editing client already refreshed its own task list, so every other client, including the editor's, still refetches. The suggestion-accept `task_updated` frame no longer carries the `"source": "suggestion_accept"` key; the retro carryover frame keeps its `task_id`, `sprint_id` and `source` keys alongside the standard ones.
