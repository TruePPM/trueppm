- **Start-to-Finish successors are no longer held at the project start**
  (#4218): when every link into a task is SF and its SF anchor falls before the
  project start, the scheduler used to ignore the link silently. The task sat on
  the project's first working day as if it had no dependency. A common case is a
  predecessor starting on day one with an SF successor that should finish the day
  before. The task is now scheduled where the link puts it, before the project
  start if necessary, as MS Project does. The data date, a `planned_start`, and
  a recorded actual start still hold it. Any FS, SS or FF link on the task still
  keeps the project-start floor. The Python and Rust/WASM engines and Monte Carlo
  agree on the new placement. On affected projects, the SF successor's dates,
  its predecessor's free float, and the schedule's earliest date move earlier.
  The data date still floors these tasks, and it is today when a project has no
  status date. So the change is visible only where the SF anchor falls on or
  after the data date, for example in a project that starts in the future.
