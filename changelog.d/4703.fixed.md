Scheduler: closing work recorded after an already-closed milestone's sign-off day no longer moves that milestone's successors in the common case, a single late predecessor, with or without the end-of-day edge the API hands back. The engine used to read completed work whose link placed the milestone on a later day as placing it at the end of its recorded day, so closing out-of-sequence work slipped the gate's successors, and possibly the project finish, by a working day. Both the Python and the Rust/WASM engines apply the fix (#4703). The rule itself was replaced before release by #5017: a closed milestone's edge no longer reads any predecessor, so closing out-of-sequence work moves nothing in every case, not only the common one (see that entry).
