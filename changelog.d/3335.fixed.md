Bulk-applying a program settings change no longer issues ~10 database queries per targeted project. The surface-change notice now hoists every read above its per-project loop (`project_id IN (...)` + `GROUP BY project_id`), so a 200-project apply costs a fixed nine queries instead of roughly two thousand — all of which ran inline in the `POST /programs/{id}/bulk-project-fields/` response. Recipients and message bodies are unchanged, and one project failing to render still cannot drop the rest of the batch's notices. The notification fan-out's `bulk_create` also now declares an explicit batch size, so a batch spanning many projects cannot silently exceed PostgreSQL's bind-parameter ceiling and drop every notice.
