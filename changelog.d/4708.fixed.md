Closed three Python/Rust document-contract splits (#4708). The Python engine now refuses `percent_complete: null` (it previously scheduled it as 0%; the Rust engine already refused it), so a hand-written document carrying an explicit null is now rejected by `Task.from_dict`/`Project.from_json` — a library behavior change; omit the key for the 0% default. The Rust/WASM engine now refuses `delivery_mode` values other than `waterfall`/`scrum` and a non-integer `sprint_length_days` (including a float token such as `10.0`), as Python already did.
