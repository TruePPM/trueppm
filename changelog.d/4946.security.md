The demo compose stack (`docker-compose.demo.yml`) no longer ships a public, hard-coded `SECRET_KEY` and `INTEGRATION_ENCRYPTION_KEY`. A one-shot `secrets-init` service generates a unique value for each install on first boot, stores it with mode 0600 on a `demo_secrets` volume, and shares it across the api-init, demo-seed, and api containers. Zero-config `docker compose -f docker-compose.demo.yml up` still works. The compose file's safety rationale also no longer claims the stack has no accounts; the read-only middleware is the real write fence.
