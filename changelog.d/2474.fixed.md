Offline sync pulls no longer silently keep rows that were deleted while a client was
offline for longer than the tombstone-retention window. The project and program delta
pulls now answer `resync_required: true` when `since` predates the newest tombstone the
reaper has hard-deleted, and the client must discard its local store and re-sync from
`since=0` (#2474).
After the upgrade every offline or sync client is asked to re-sync once, because
tombstones reaped before this release never recorded a floor.
Monte Carlo forecasts that were current before the upgrade stay current. Stop
`celery-beat` before running the migration; see the 0.5 upgrade notes.
