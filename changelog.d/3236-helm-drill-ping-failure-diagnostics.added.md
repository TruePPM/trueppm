The `helm:install` deploy drill's celery worker control-plane ping check (#3236) now captures three additional diagnostics when the ping fails: `inspect ping` re-run from a separate pod (the api pod) to rule out the prober's own cgroup contention, the broker's pidbox/reply-queue state (`PUBSUB CHANNELS celery*`, `KEYS *reply*`/`celery*`) to tell a lost reply apart from a dead consumer, and the worker container's cgroup `cpu.stat` throttling counters. A prior investigation reproduced the ping's failing precondition exactly but could not reproduce the failure itself in Docker or kind, so a real recurrence now needs these captures to make progress rather than restarting the investigation from the same evidence.
