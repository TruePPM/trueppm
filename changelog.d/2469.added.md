- **Monte Carlo reports when the velocity horizon clamped a run**: a sprint-delivered task's velocity draw that has not burned down by the sprint horizon is clamped to it, which makes that run's duration a lower bound. The scheduler's `MonteCarloResult` now carries `velocity_saturated_runs` (and `velocity_tail_truncated`), the project Monte Carlo forecast response carries the same `velocity_saturated_runs` on a live run or a cached read, and the backlog forecast response (`GET /api/v1/projects/{id}/sprint-forecast/`) carries `horizon_saturated`, so a caller can tell a truncated P80/P95 from an ordinary estimate. Seeded percentiles are unchanged. The entry for this gap is removed from Known Issues. The project Monte Carlo forecast exposes `velocity_saturated_runs` to every project member, unlike the audience-gated `horizon_saturated` on the sprint forecast: it is derived from the same velocity-driven result whose percentiles that endpoint already serves to every member, so it reveals nothing they do not, whereas the sprint-forecast view is a separate ADR-0104 signal surface. The entry stays in Known Issues, annotated "partly fixed in 0.5", because the clamp's bias is reported, not removed.
