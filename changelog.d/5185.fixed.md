`trueppm_scheduler.forecast_velocity_delivery` now returns the same P50/P80/P95 dates as `monte_carlo()` for the same backlog, velocity history, sprint length and seed. It runs `monte_carlo()` on a one-story project instead of counting whole sprints with the per-task sampler `monte_carlo()` no longer uses, so a backlog that needs part of a sprint finishes part of the way into it.
