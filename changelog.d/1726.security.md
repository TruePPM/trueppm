Task-run endpoints (`/projects/{id}/task-runs/`, `/task-runs/`) no longer expose the raw `initiated_by` user id (use `initiated_by_username`), and they and `/projects/{id}/scheduler-runs/` return a blank `error_detail` to callers below the Admin role. The `task_run_failed` WebSocket event now carries a generic failure message instead of the raw exception text, so Viewer-tier members cannot read user ids or internal worker error text.
