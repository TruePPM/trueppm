- **Metric provenance**: the project figures the shell v2 header and homes show now
  each have one owning API endpoint (ADR-1314): health band and task counts
  (status summary), P50/P80/P95 and P80 against the commitment (Monte Carlo
  forecast), per-project person load (utilization), open risks, team utilization
  and schedule performance (overview), the burn series and S-curve (burn), and a
  task's slip (task baseline comparison). Those payloads return a `definitions`
  map with one sentence per figure and an `as_of` timestamp; for the forecast,
  `last_run_at` is the as_of. The forecast also compares P80 with a commitment: the
  active baseline's finish, else the program's target date. It returns
  `commitment_date`, `commitment_source` and `p80_delta_vs_commitment_days`, and the
  delta is null with a reason when it cannot be computed. The status summary gains
  a full `blocked_count`. Its `monte_carlo_p80` and the overview's forecast fields
  now match the forecast endpoint. The shell v2 P80 tooltip shows the server's
  definition. See the new Metric vocabulary page. Not covered yet: load across
  several projects (#4777), the My Work and sprint burn sources (#4778), and the
  program rollup's metrics (#4779).
  When the commitment is the program's target date, every project member who can
  read the forecast now sees that date, including members who are not in the
  program. Only the date is shown.
