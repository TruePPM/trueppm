The Helm web tier gains `web.realIpFrom`, a list of trusted proxy CIDRs (usually your ingress controller's pod CIDR). When it is set, nginx recovers the client address from `X-Forwarded-For`, so `web.adminAccess.allowCIDRs`, the admin login rate limit, and the `X-Real-IP` / `X-Forwarded-For` sent to the API name the real client rather than the ingress controller pod. Behind an Ingress, an admin allowlist matched against the pod IP either matches nobody or, with the pod CIDR added, everybody, so the chart now **refuses to render** a non-empty `web.adminAccess.allowCIDRs` with `ingress.enabled: true` and an empty `web.realIpFrom`. If your values set an allowlist behind an Ingress, add `web.realIpFrom` before upgrading. The `nginx -t` CI check of the rendered web config now also covers a render with both values set. The chart also refuses over-broad `web.realIpFrom` CIDRs (shorter than IPv4 /8 or IPv6 /16), since trusting a huge range lets any client spoof its address.
