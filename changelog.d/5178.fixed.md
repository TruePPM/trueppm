Once a program has an accepted cross-project dependency, the program-scoped schedule pass no longer places a member project's tasks at the earliest member's start date or leaves its unstarted work before the data date. Each member's tasks are floored at its own start date and its own data date (its status date, or today), as on its own schedule, so accepting a cross-project dependency moves only the work that dependency drives. The program pass's `cpm_complete` event now carries each member's data date instead of `null`. Two edge cases still differ from the single-project pass: a positive-lag successor of a milestone held only by a later-starting project's start, and a task marked complete with no recorded dates whose duration runs past the data date (#5204). As on a project's own schedule, the first program pass that floors a member with no status date at today records that one-time correction without per-task movement activity or date-change broadcasts.
