A workspace **Agents** page, always linked from the shell v2 rail, lists every agent you can see across your programs, filtered by the server to your project memberships. Its controls work against the server: **Pause** refuses every call the agent makes until it is resumed, **Edit scope** sets Read and Dry run per area (Write is shown disabled and refused by the server until 0.6); each area governs named endpoints — Resources covers project cost, utilization, allocation, the resource heat map and a program's resource contention, and an agent without it reads tasks without their resource assignments, while Dependencies covers dependency links, the driving chain and date derivations; the project and program exports carry every area, so an agent needs Read on all four to use them. A few fields embedded in other reads (task baseline fields, dependency edges in history, program schedule links, overview utilization, program rollup cost and sprint member hours) are still served under Schedule & tasks; moving them under their own areas is tracked in #5118. **Revoke token** stops the agent on its next call. An agent can never exceed the person it acts for, checked against that person's current roles on every call. Only that person or a workspace Admin can change an agent, never with an API token, and every change is recorded in the agent action log's hash chain. Workspace Admins see an "Action log verified" line, and a refused or paused agent call puts one coalesced item in its owner's Inbox. (#4814, #4757)
