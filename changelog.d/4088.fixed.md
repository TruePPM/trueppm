- **WebSocket payloads name their subject as `id` across every event family**:
  `suggestion_created` now carries the suggestion as `id` (as `suggestion_declined`
  and `suggestion_revoked` already did), `project_calendar_changed` carries
  `actor_id` beside its `actor` display label, and `sprint_reranked`,
  `sprint_retro_updated`, `sprint_scope_changed` and `demo_reordered` carry the
  sprint as `id`. Every change is additive — the older `suggestion_id` / `sprint_id`
  keys stay — so an MCP or integrator consumer keyed on `payload.id`, as the
  WebSocket reference says to, can now find the subject of each event. The API test
  suite enforces the rule over every row-subject broadcast, with three reasoned
  waivers.
