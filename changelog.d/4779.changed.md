- **Program rollup metric provenance**: `GET /programs/{id}/rollup/` now owns the
  program-level figures the way ADR-1314's project endpoints own theirs. It returns
  an `as_of` timestamp and a `definitions` map with one sentence for program health
  and one for each enabled KPI. **Program health is now the project health band
  rolled up**: each project's band (its project manager's report, else its
  critical and at-risk task counts, the same band its own health chip shows)
  combined under the program's aggregation policy. A program manager's own health
  report on the program is the band when one is set, and `program_health_source`
  says which (`reported` or `derived`). Previously the band rolled up each
  project's schedule performance (SPI), which is still available as the Schedule
  health KPI. The weekly program-health digest and the project it names follow the
  same band. **P80 completion now computes**: it is the latest P80 among the
  projects' own Monte Carlo forecasts, with the project that sets it, the age of
  the oldest forecast it read, and a count of projects without a forecast. It is
  no longer locked in the Rollup KPIs picker. A KPI that is enabled but has no
  data now keeps its null (or `unknown`) value and carries a `reason`
  (`no_projects`, `no_planned_work`, `no_milestones`, `no_baseline`,
  `no_completed_work`, `no_forecast`). Single program only; nothing aggregates
  across programs.
