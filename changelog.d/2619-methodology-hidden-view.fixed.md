- **Methodology-hidden views no longer invite the deviation they're meant to discourage**: `/sprints` and `/backlog` on a Waterfall project (and `/schedule` and `/calendar` on an Agile one) are hidden from the nav but reachable by direct URL — that policy is unchanged. What was wrong was landing on one: it showed the generic cold-start empty state, primary "start using this" CTA included, with no signal the project is configured otherwise. It now names the mismatch, points the primary action at the view the project's methodology actually uses, and demotes "use it anyway" to a secondary action into Settings → Methodology.
- **A methodology flip no longer orphans existing sprints**: switching a project to Waterfall hides the Sprints nav entry but never touched the sprint data itself — a team's already-committed sprints became reachable only by URL with no on-screen sign they still existed. The Sprints view now renders them with a banner explaining the mismatch instead of a "No sprints yet" empty state, and the Settings → Methodology picker warns before a save that would hide existing sprints.
- **Inherited-vs-explicit methodology is now distinguishable in the shell**: the rail subtitle, the compact methodology badge, and the location-switcher subtitle used to render `"{Methodology} workspace"` regardless of whether that value was the workspace-wide default or this project's own override — mislabeling a per-project value as the workspace's. They now read `"{Methodology} methodology"`, with a `"(workspace default)"` qualifier only when the project's resolved methodology actually matches the workspace default.
