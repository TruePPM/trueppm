Normalized the `trueppm-wasm-scheduler` JavaScript API to `camelCase`, matching every other TypeScript surface in the repo. The generated `.d.ts` now exposes `computeSchedule`, `incrementalUpdate`, `SchedulerSession.setTaskStart`, and `SchedulerSession.recalcIncremental` in place of their previous `snake_case` spellings. Rust-side names are unchanged — only the `wasm_bindgen` binding names moved — so the CPM engine, its output, and the cross-engine conformance fixtures are untouched. The package has no consumers yet (nothing in `packages/web` imports it), which is why this rename is a no-op today and would have been a permanent breaking change once the first consumer landed. A new `wasm:build` step (`scripts/check-dts-camelcase.sh`) now fails the pipeline if a future export reaches the JS surface without a `camelCase` `js_name`. (#2602)
