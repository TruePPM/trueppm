- **Email & SMTP settings: a relay with no SMTP AUTH can now be configured in-app**: Workspace → Settings → Email & SMTP had no way to save a Custom SMTP relay that doesn't use authentication — a trusted internal relay on a private network (Postfix `mynetworks`, an in-cluster relay), which the docs page has always named as a valid use for **Security: None** without any way to actually set it up here. Depending on what was entered, the save was rejected with "Re-enter the password when changing the transport" or "A username is required for this transport", or (with both fields filled against a relay that doesn't advertise AUTH) failed the connection probe with a generic "could not connect". Custom SMTP may now be saved with **both** Username and Password left blank; TruePPM skips SMTP AUTH entirely for that config, matching what the `EMAIL_*` environment fallback already supported. SendGrid and Amazon SES are unaffected and still require a credential — they have no unauthenticated mode. Switching an already-credentialed Custom SMTP config to no authentication also clears the stored secret, so it can't resurface later if a username is re-added without a new password. A password submitted with no username is still rejected (the pair is required together, or not at all).
