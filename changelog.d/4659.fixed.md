- **Gantt bars no longer stay stale after the first data-date recalculation**: the
  first recalculation that sets an established project's data date to today corrects
  task dates without publishing per-task movement, and a collaborator with the
  schedule open kept the old dates until a reload — and could commit a drag against
  them. That run's `cpm_complete` event now carries `"dates_changed": true` (only when
  some task moved), and the web client re-reads the task list when it sees it. The
  flag names no task and no date, so no movement is published.
