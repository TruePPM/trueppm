- **The Schedule reads its tasks with keyset pagination (api, web)**: `GET /tasks/` accepts an opt-in `?pagination=keyset`, which seeks in the default WBS order (numeric per level, then name, then `id`) instead of skipping rows with an `OFFSET`, and returns `{next, previous, results}` with no `count`. A deep page now costs about what the first page does, where before the last page of a 32,000-task project paid for producing all 32,000 rows to return 200, and a walk no longer repeats or skips a row when a collaborator adds or removes tasks mid-load (a structural move such as indent, outdent, reparent, group, or ungroup, or a rename, mid-load can still shift a row across a page boundary; the Schedule detects a repeated task and refetches). The Schedule follows the `next` cursor in 500-row pages. Callers that do not pass the parameter keep the page-number envelope unchanged.
