- **Web image release gate now boots the image and loads its assets**: every
  web image build in CI (the release publish legs, the multi-arch probes, and
  the per-commit image the deploy drills use) now starts the just-built
  container and fetches every script, module preload, and stylesheet its
  `index.html` references before anything is pushed. A missing or mismatched
  asset fails the build instead of shipping. Previously a missing asset got
  nginx's SPA fallback: `index.html` returned with a 200 status, which the
  browser refuses to run as a script, so the app showed a blank screen while
  every server-side signal stayed green. The new check is
  `scripts/check-served-assets.sh <url>`, which can also be pointed at a
  running deployment. On try.trueppm.com the 0.4.0-beta.7 blank screen was not
  an incomplete image: both architectures of the published image contain and
  serve every asset. The failing asset set exactly matches 0.4.0-beta.6 and
  0.4.0-beta.7 replicas serving behind the same load balancer.
