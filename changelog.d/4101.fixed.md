The WASM scheduler's incremental recalc (`incrementalUpdate`, `SchedulerSession.recalcIncremental` and `recalcIncrementalTyped`) now returns every task whose dates or float moved, not only the tasks downstream of the changed one. Lengthening work that moves the project finish changes the late dates and float of upstream and parallel tasks too, and those rows were left showing the previous values. On the stateless `incrementalUpdate` path, a caller that passes its previous run's output back gets just the changed rows; one that does not gets every task. A `SchedulerSession` compares each frame against the input it was built from, not the previous frame, so the caller draws that input and overlays each frame's rows on it rather than accumulating deltas.
