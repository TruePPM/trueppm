Backlog item pull now serializes the created task through the shared annotated task queryset with the request in context, so `can_edit`, `can_delete` and `can_log_time` in the response reflect the caller instead of failing closed to false, and stray per-field queries are removed.

The web client reads only `task.id` from this response, so the fix mainly benefits API consumers (MCP and third-party clients), not the web UI. The retro action-item promote and carryover pull-to-sprint responses get the same correction.
