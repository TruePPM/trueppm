A password reset, member off-boarding, and `revoke_api_tokens --user` / `--all-personal` now stamp a per-account credential cutoff, and every access token and refresh token issued at or before it is refused with a `401`. A WebSocket ticket issued before it is refused by closing the socket with code `4001`. Before this, a stolen access token stayed valid for the rest of its 15-minute lifetime after a reset. In that window it could mint a WebSocket ticket and open a new socket after the reset's eviction had already run, or mint a personal token, project token, or share link that outlived the reset. The check lives in the JWT authenticator, so it covers every endpoint, and it adds no query per request. The cutoff is set one second past the reset to absorb clock skew between replicas, and the comparison is strict to the second, so a sign-in that completes within about two seconds of the reset has to sign in again. This assumes the nodes' clocks are NTP-synchronized. `revoke_api_tokens --user` and `--all-personal` now say that the targeted accounts are signed out everywhere, and `--user` stamps the cutoff even when the account has nothing else to revoke. Only `--all` still advises rotating `JWT_SIGNING_KEY`.
