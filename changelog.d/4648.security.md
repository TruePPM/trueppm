The development Compose stack (`docker-compose.yml`) now publishes the API (`:8000`) and web (`:5173`) ports on `127.0.0.1` only, and generates a random JWT signing key on each API container start, so access tokens can no longer be forged from the repo text. Previously `docker compose up -d` exposed a `DEBUG`, `AllowAny` API with a forgeable token key on every host interface. The dev `SECRET_KEY` (Django sessions and CSRF signing) is still a fixed, public value, which is why the stack must stay on localhost. The perf capacity compose file's ports are loopback-bound too. If you reached the dev stack from another machine, use `docker-compose.prod.yml` or Helm; `TRUEPPM_DEV_BIND_ADDR=0.0.0.0` restores the old bind for isolated hosts only. A new `compose:ports` gate fails any non-loopback port publish in the repo's compose files.
