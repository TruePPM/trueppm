Scheduler: a data date at or before the project start no longer moves any work, and neither does a start-no-earlier-than date (`planned_start`) at or before the start on a task with no Start-to-Finish link. A free or completed milestone used to measure its outgoing lags from that earlier day, and because a project with no status date uses today as its data date, every project starting in the future had its kickoff milestones' successors, forecast finish and critical path pulled up to (start - today) days early. A data date on or before the start no longer holds a Start-to-Finish-linked task either; such a task's own `planned_start` still holds it wherever it falls, so snapping it to the project start keeps working. A data date or `planned_start` after the start, and a recorded `actual_start`, bind as before. Both the Python and Rust/WASM engines changed. After upgrading, the next recalculation can move these dates; see the upgrade guide.
