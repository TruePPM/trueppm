- **Scheduler: total float no longer lets a start-of-day milestone slip onto an end-of-day finish**: when the project ends at the end of a day (for example `W(5d)` finishing on Friday) and a milestone is placed by a start-to-start link from work (`X(2d) -SS+3d-> M`), `X` was reported with two days of total float, but slipping it two days put the milestone at the start of Monday and moved the project finish. In both the Python and WASM engines, float through such a link now stops at the last working day of the finish, so `X` has one day. A finish-to-start predecessor of the same milestone keeps its full float, because it places the milestone at the end of Friday. This was never in a tagged release (#4183).
- **Scheduler: a milestone's own total float is now measured to the reading it is shown with**: this is a broader clarification of what a milestone's own total float means, not only a fix to the reported case. A milestone read as the start of a day now floats only as far as that reading can go without moving the shown project finish, so its total float equals the working days between the early start and late start it is shown with, as the scheduler conventions page states for every task. It changes results beyond the reported network: a lone milestone held by a floor and a milestone reached by a start-to-finish link from work (`X -SF-> M`) can each report one day less float than before (5 → 4 in the cases found), and some such milestones now become critical and appear on the critical path. It holds near the project finish, not everywhere: a start-of-day milestone whose late date falls on a weekend earlier in the schedule can still report a float one day wider than its shown dates (#4183).
- **Scheduler: free float stops before a slip changes how a milestone is shown**: a milestone shown at the end of a day (`A(3d) -FS-> M`, shown at the end of Wednesday) is shown at the start of the next day when a start-to-start link from work reaches the same instant (`X(2d) -SS+1d-> M`), even though the milestone's instant does not move. `X` was reported with two days of free float, and slipping it two days moved the milestone's shown date. In both the Python and WASM engines, free float through such a link now stops a day before that tie, so `X` has one. The same applies when the start-of-day reading is carried over a zero-lag link from another milestone. This came with the milestone-instant change made during 0.4 development and was never in a tagged release (#4183).
