The largest JSON body any API endpoint will parse drops from 100 MB to 2 MB, including the unauthenticated sign-in, invite-accept, password-reset and share endpoints, which used to parse a 100 MB body in full before checking a credential. The few routes that legitimately need more get a raised ceiling from one table in `core/request_body_limits.py`: 10 MB for offline sync push, task bulk operations, inbound task push, the seed import and its dry run, and the workspace logo; 110 MB of file upload (JSON still 2 MB) for attachments and the MS Project, Jira, CSV/Excel and risk-CSV imports. The API refuses a declared body over its route's ceiling with `413` and `code: "request_body_too_large"` before authentication or any database work, so the limits hold even where the Ingress bypasses the web tier. All four shipped nginx configs now carry the same tiers as per-location `client_max_body_size` (server default `2M`), and an API test fails if they drift. Feature caps (`MSPROJECT_MAX_UPLOAD_MB`, `SEED_MAX_UPLOAD_MB`, …) are unchanged and still name their limit in a `400`. If you raised an import cap above 110 MB, or `SEED_MAX_UPLOAD_MB` above 10 MB, the larger request is now refused at the transport. See [Request body ceilings](https://docs.trueppm.com/administration/configuration/limits/#request-body-ceilings).
