**The operator egress allow-list is now scoped per surface, so a host trusted for single sign-on can no longer be reached from a webhook or git-link URL** (#2851, #3561). `TRUEPPM_EGRESS_ALLOWLISTED_HOSTS` exists so that SSO can reach an identity provider running inside your cluster. Before this release it exempted the listed host for **every** outbound caller. A project Admin could therefore register a webhook at the in-cluster IdP (for example `https://keycloak/admin/...`) and read its responses. A pasted git link or a Connected Account base URL could reach the same host. Each surface now has its own list, and a host on one list is not exempt for any other. The lists are `TRUEPPM_EGRESS_ALLOWLISTED_HOSTS_SSO`, `_SMTP`, `_INTEGRATIONS` and `_WEBHOOKS`. The scoping applies at registration, at the pre-flight check and at connect time.

**Upgrade action:** `TRUEPPM_EGRESS_ALLOWLISTED_HOSTS` keeps working, but now for single sign-on only. If you listed an internal SMTP relay, a self-hosted GitLab or Jira, or a webhook receiver in it, move that host to `TRUEPPM_EGRESS_ALLOWLISTED_HOSTS_SMTP`, `TRUEPPM_EGRESS_ALLOWLISTED_HOSTS_INTEGRATIONS` or `TRUEPPM_EGRESS_ALLOWLISTED_HOSTS_WEBHOOKS` before you upgrade. Otherwise that surface is refused as a private address after the upgrade.
