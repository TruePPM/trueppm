- **Monte Carlo no longer under-reports risk on projects with per-task calendars
  (#4429)**: when a task's calendar was sparser than its successor's (a member
  project on a four-day week feeding a five-day project, a Monday-only calendar, or
  a plant calendar with a long shutdown), `monte_carlo()` reported P50/P80/P95
  dates days to months *before* the deterministic `schedule()` finish, with no
  error. It sized every calendar's working-day index by one working-day count,
  which ran short on the denser calendars, and silently clamped the overflow to
  the index's last date. The index is now sized from a calendar-date bound
  counted in each calendar's own working days. Every Monte Carlo lookup that used
  to clamp a past-the-end offset or date onto the last indexed day (lag deltas,
  ES floors, actuals, milestones, the reference ruler, the finish read-out) now
  raises instead, so an undersized index can no longer pass for a date. The program P80 rollup and MCP forecasts
  inherited the error and are corrected with it.
