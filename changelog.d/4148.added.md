Projects and programs now have unique **keys** that can be used in links and references. A key is the short name in `/projects/PLAT/…`, and task, sprint and risk references such as `PLAT-T-10`, `PLAT-SP-3` and `PLAT-R-7` include it. The API field is still called `code`. When you create a project or program, the key is suggested from its name and checked for availability as you type. If you leave it blank, one is derived for you. You can rename a key from the General settings page, and links that use the old key keep working. A key is never given to another project, including after the project it belonged to is permanently deleted. Two new endpoints support this: `GET /api/v1/resolve/` turns a key, retired key, UUID or `PLAT-T-10` reference into ids, and `GET /api/v1/keys/` suggests and checks keys. On upgrade, projects and programs with a blank or duplicate code get a derived or suffixed key; the upgrade notes explain how to list them. Task references now read `PLAT-T-8`, matching risk IDs like `PLAT-R-7` and the form the resolver accepts.
