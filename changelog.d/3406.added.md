Zero-downtime secret rotation: `SECRET_KEY_FALLBACKS`, `TRUEPPM_JWT_SIGNING_KEY_FALLBACKS` (verify-only) and `TRUEPPM_INTEGRATION_ENCRYPTION_KEY_FALLBACKS` (`MultiFernet`, decrypt-only) let an operator roll a new primary key while values signed or encrypted under the old one keep working. Every fallback is validated at boot like its primary, and `manage.py reencrypt_integration_secrets` (`--dry-run`, batched, idempotent) moves stored secrets onto the new primary so the old key can be dropped.
