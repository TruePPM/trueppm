- **A zero-duration milestone no longer takes up a working day (#4079).** Every
  milestone on a path used to push everything after it back by one working day,
  so schedules with milestones finished later than MS Project or Primavera P6
  would compute for the same network, and imported MS Project plans drifted from
  their source file. A milestone is now a point in time: it sits on the day its
  driving work finishes, and inserting one into a finish-to-start link leaves
  every other date unchanged. The CPM engine, Monte Carlo forecasts, the schedule
  derivation ("why this date"), and the offline WASM engine all follow the same
  rule. After upgrading, dates move earlier by one working day per milestone on
  the path the next time each project recalculates — see
  [Upgrading](/getting-started/upgrade/#milestone-date-shift-after-recalculation).
