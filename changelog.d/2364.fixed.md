Deleting a working calendar that is still in use now returns `409 Conflict`
instead of a `500`. Every foreign key into `Calendar` is `PROTECT` — a project's
base calendar, a project overlay, a program default, or the workspace default —
so a calendar can never be deleted out from under a live schedule. That refusal
was correct but surfaced as an unhandled `ProtectedError`, i.e. a server error.
`DELETE /api/v1/calendars/{id}/` now answers with a conflict whose body carries
`reference_count` and a `references` sample naming what still applies the
calendar, so a client can tell the user which projects or programs to detach
first (#2364).
