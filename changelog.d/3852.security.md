The shipped nginx configs now rate limit the unauthenticated sign-in, token, password-reset, SSO and invite-accept endpoints, and `/ws/` handshakes, per source address (20 requests/second, burst 100 and 200), and apply a much looser limit to the rest of `/api/`, share links and the Git-event receiver included (100 requests/second, burst 1000). Refusals answer `429`. This backs up the application's own throttles. The limits apply only where nginx can see the real client, so that one client behind a shared proxy address cannot lock everyone out: the Docker Compose TLS config, the Compose HTTP config once `NGINX_TRUSTED_PROXY_CIDR` names your load balancer, and Helm once `web.realIpFrom` is set. The Compose demo, the published `web` image, and Helm without `web.realIpFrom` render no edge limit. In Helm the settings are `web.rateLimit`, and they apply only to traffic routed through the web tier, which the default Ingress does not do for `/api` and `/ws`.
