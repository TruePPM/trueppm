**The SMTP relay connection now refuses a DNS-rebinding answer at connect time** (#4647). The relay host was checked against the private-address deny-list when you saved the settings and again before each send, but Django then resolved the name a second time to connect, so a low-TTL DNS record could pass the check with a public address and connect to an internal one. Mail now goes through the same connect-time guard as webhooks: the name is resolved once, refused if any answer is non-public, and only those addresses are dialed, before STARTTLS or any SMTP byte. `TRUEPPM_EGRESS_ALLOWLISTED_HOSTS_SMTP` still exempts a trusted internal relay by exact hostname and is not widened.
