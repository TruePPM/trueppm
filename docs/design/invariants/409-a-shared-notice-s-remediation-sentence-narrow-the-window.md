# Rule 409 — A shared notice's remediation sentence ("narrow the window", "use the filter", "try searching") is a claim …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Product boundary*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A shared notice's remediation sentence ("narrow the window", "use the filter", "try searching") is a claim about the CALLER's affordances, not the component's — parameterize it per mount, never hardcode one sentence for all of them.** A component that says *what to do* is making a promise on behalf of whatever screen renders it, and nothing in the type system notices when the second mount has none of the controls the first one had. `AllocationTruncationNotice` shipped its first draft telling every reader to "narrow the window or filter to specific resources": true on `ResourceView`, whose toolbar carries window nav, Fit-to-project and a resource search box — and false on `ProgramResourcesPage`, which has a `useMemo`-frozen window, no toolbar and no search, so the one surface where the user could do *nothing* was the one being told to do two things. That is the ux-review §6.3 "a destination or action that does not exist" failure wearing a reusable component's clothes, and it is invisible to the component's own tests, which necessarily pass a remedy string in. **Three obligations.** **(a) Make the remedy a REQUIRED prop**, not an optional one with a default — a default is the hardcoded sentence again, just further away, and the second mount inherits it silently. **(b) Grep every mount point before writing the sentence** and confirm the control it names is reachable *on that screen*; where it genuinely is not, say so plainly and point at the surface that does have it rather than inventing a softer phrasing of a control that is absent. **(c) The same applies to a notice's SPACING** — `mx-4` baked into a shared notice double-insets it inside a page that already pads its container, so the banner sits visibly narrower than every sibling; take spacing from the mount site (the `QueryErrorState` shape) rather than from the component. This is rule 404's sibling: 404 is about a disclosure gated on the wrong *condition*, this is about a disclosure making the wrong *promise*. Reference: `features/resource/AllocationTruncationNotice.tsx` and its two mounts, `features/resource/ResourceView.tsx` + `features/programs/resources/ProgramResourcesPage.tsx` — #3576, ADR-1118, surfaced by `ux-review`.
