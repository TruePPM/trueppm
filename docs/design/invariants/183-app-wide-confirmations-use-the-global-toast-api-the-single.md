# Rule 183 — App-wide confirmations use the global `toast()` API + the single `ToastHost`; board-local transient notices …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Controls and composition*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**App-wide confirmations use the global `toast()` API + the single `ToastHost`; board-local transient notices stay in `BoardDropNotice` (rule 170).** The toast system (`components/Toast/`) is a Zustand store (`toastStore`, pure — auto-dismiss timing lives in the host) + an imperative `toast.success/info/error/warm(message, durationMs?)` API callable from anywhere (mutation `onSuccess`, event handlers, plain modules — it reads the store via `getState()`, no hook) + ONE `ToastHost` mounted once in `AppShell`. The host is a bottom-center pair of **two fixed slots** (rule 356 — not a queue) rendered as inverse **ink pills** (`bg-neutral-text-primary text-neutral-text-inverse`, always high-contrast against the canvas in both themes), each rising in via `motion-safe:animate-toast-rise` (rule 181) with a decorative sage `✓` on success/info (`aria-hidden` — the message text carries the announcement), auto-dismissing after `durationMs` (default ~2.6s; ~8s for an actionable one). The wrap is `role="status" aria-live="polite" aria-atomic="false" pointer-events-none` so toasts are announced without stealing focus and never block the UI beneath; individual pills re-enable pointer events. `shadow-pop` is allowed (a toast is a pop surface — rule 1's standing exception). **Fire it only for genuinely app-wide events** (task created/completed/saved, pin/unpin, theme); do NOT route board-local pending-state notices here — rule 170 keeps `BoardDropNotice` board-scoped, neutral-toned, and off the global toast library.
