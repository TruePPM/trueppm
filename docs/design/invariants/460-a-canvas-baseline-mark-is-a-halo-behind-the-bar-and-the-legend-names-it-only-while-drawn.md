# Rule 460 — A canvas baseline mark is a halo behind the live bar, and the legend names it only while it is drawn

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md). The index carries the headline; this file carries the full text (#3821).

**The active baseline's ghost bar is a hollow outline (`ghostFill` / `ghostBorder`, the tokens that already carry the #2207 contrast fix and the forced-colors `Canvas`/`GrayText` mapping) painted BEHIND the live bar and bleeding `BASELINE_GHOST_BLEED` px above and below it.** It is not a second bar underneath: at the 28px fine-pointer row there are ~4px below the bar and the actual-date overlay already owns them. The mark is carried by outline vs fill, never by color alone (WCAG 1.4.1), and a baseline that equals the live bar is correctly nearly invisible.

**The control and the legend row exist only while there is something to draw.** "Baseline bars" is a Display-menu `menuitemcheckbox` in the Chart section, offered only when the project has an active baseline (an inert checkbox is a control that lies), and the legend's "Baseline (planned)" row renders only while the canvas is drawing it — a legend names marks that are on screen. The canvas flag (and so the legend row) therefore also waits for the baseline detail to load (`dates !== null`); while it is loading or errored the menu item stays but nothing is drawn or named. Baseline x positions come from the memoized date→x map (#1539); no date is parsed per frame.

**Summary rows and milestones get a slip mark, not a ghost bar, and only where they moved (#5065, ADR-1485).** A phase row draws a whisker along its centerline from the baseline finish edge to the live finish edge, an end tick at the baseline end and a signed day label (`+5d` / `−3d`, true minus sign, secondary text token for 4.5:1, label halo like other canvas text) — never a hollow outline of the summary bar, which doubles the ink on on-plan phases. A milestone draws a hollow baseline diamond at its baseline date, a whisker, then the filled live diamond on top. Both draw only when the Δ is at least `BASELINE_MARK_MIN_DAYS` (1 calendar day, the variance read's default `min_days`); an on-plan row draws nothing. The legend's "Baseline slip" row is gated on `hasBaselineSlipMarks` — a mark must be on screen, not merely a baseline active. Hollow vs filled, whisker length and the sign carry meaning; hue never does (WCAG 1.4.1).

**At-rest baseline name on Read surfaces (#3757).** The Read-mode chip and the View-only badge name the active baseline plainly (no `vs`, which means "edits are measured against it" and belongs to Author), width-capped with the full value on `title`, in the accessible name too (WCAG 2.5.3). While baselines are loading, failed or none is active they show nothing and claim nothing (rule 392). Below 1280px the Read chip hides its "Switch to Author to edit" hint and shortens the name (6rem cap) so the toolbar still fits; both remain in the accessible name.
