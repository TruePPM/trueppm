# Rule 217 — Every dialog/drawer/modal/panel that edits existing information or collects new information presents an …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**Every dialog/drawer/modal/panel that edits existing information or collects new information presents an explicit, consistent commit/discard affordance — Save (primary) + Cancel (secondary), Save disabled until dirty, a Cancel that reverts to the original values, and an unsaved-changes guard on any dirty dismiss — composed from the shared `@/components/dialog` primitives, never re-decided per surface.** The contract (issue #1361, generalizing web-rule 164 from the backlog drawers to all editable surfaces):
- **Save is disabled until the form is dirty** (a field actually changed vs. the last-saved snapshot) and re-disabled after a successful save. Dirty is a structural `JSON.stringify(draft) !== JSON.stringify(baseline)` compare of flat scalars.
- **Cancel discards pending edits and restores the baseline** — it never mutates.
- **Dismissing while dirty** (Esc, scrim/backdrop click, close ✕) opens the **unsaved-changes guard** (`role="alertdialog"`, focus-trapped, default focus on the safe "Keep editing") instead of silently committing OR silently discarding. A clean dismiss closes immediately with no prompt.
- Compose these, do not hand-roll them: **`useDirtyDraft<T>(initial)`** owns draft/baseline/dirty + `reset()` (Cancel) + `commit()` (post-save re-snapshot); **`useUnsavedChangesGuard({ dirty, onClose })`** owns the close-vs-guard decision, the guard's open state, and the document Escape listener; **`DialogFooter`** renders the Save/Cancel bar (shared `Button` primitive, ghost Cancel + primary Save, the muted "Unsaved changes" status, an inline `role="alert"` for validation/save errors); **`UnsavedChangesDialog`** is the discard prompt. Two valid compositions: a **deferred drawer** mounts `{dirty && <DialogFooter/>}` so the bar appears only while dirty (backlog drawers, rule 164); an **always-on modal** renders the footer for its whole lifetime and passes `dirty` so Save stays inert until a change. Reference implementations: `EpicDetailDrawer.tsx`, `StoryDetailDrawer.tsx`.
- **Instant-toggle carve-out (must be visually distinct, never batched behind a Save bar):** a single non-destructive control whose change *is* the action — a lone switch/checkbox that optimistically PATCHes on toggle, a child-collection row on its own flat endpoint (acceptance criteria), a server-gated semantic toggle the surface reflects live (Definition of Ready). These commit immediately and correctly have **no** Save/Cancel/guard, because there is nothing staged to lose. The line: *does a dismiss risk losing staged edits?* If yes → the surface needs the footer + guard; if the change already persisted on interaction → it is an instant toggle and is exempt. Never give an instant toggle a Save bar (implies a batch that isn't there), and never let a surface that stages multiple scalar edits commit-on-dismiss without a guard.
- **Settings pages are the shell-scoped specialization:** inside `/settings` the equivalent contract is provided by `useDirtyForm` → `useSettingsSaveStore` → the `SettingsShell` save bar + its own `ConfirmDiscardDialog` (rule 115). Settings forms use *that* mechanism, not `@/components/dialog`; the two are parallel implementations of the same rule for different mount contexts.
- **The Schedule `TaskDetailDrawer` is on this contract for its own scalar columns (#1977).** Its **name** and **description** stage in a `useDirtyDraft` and batch into one `PATCH /tasks/{id}/` behind the shared `DialogFooter`, with the `UnsavedChangesDialog` guard on Esc / close ✕ / backdrop and on Expand (Discard navigates to the full page). There is **no auto-flush** — the old #962 "B-lite" flush-on-blur/tab-switch/close was replaced; blur returns the Markdown field to read mode but never saves, and switching tabs keeps the draft intact. The name and description stage inline; the **three-point estimate** (O/M/P) also stages into the *same* draft (#1985) — but it renders through the `EstimatesSection` registry section, so it receives its draft slice via the **`TaskDraftContext`** binding (ADR-0439), NOT through `DrawerSectionProps` (which stays frozen for Enterprise). A section binds only when `binding.taskId` matches its own task; absent the binding (the full-page `TaskDetailPage`, no Save bar) it falls back to immediate blur-PATCH. Everything else stays immediate as the instant-toggle / relational carve-out above: **STATUS** (single-select whose change is the action; also commits via board drag), **PROGRESS** (direct-manipulation slider, commits on release), **ASSIGNEES** / **LABELS** (relational controls with their own mutations), sprint **Remaining (pts)** (sprint-scoped, active-gated), the **DURATION** cell in the schedule vitals strip (`TaskScheduleStrip`, #2106/ADR-0515 — a deliberate instant-commit scalar, NOT staged: it PATCHes `duration` immediately via `useUpdateTask` because Start/Finish/Float are server-computed by CPM and only meaningful *after* the recompute, so a staged duration would leave the strip's other three cells stale; it honors the ADR-0151 recalc-% policy and never joins `ScalarDraft`/`buildScalarPatch`), and every other registry section — dependencies, sprint, blocker, recurrence, comments, attachments — which self-mutate through their own endpoints. The three estimate keys diff into the one PATCH via a shared `buildScalarPatch` used by Save, the #1978 "Save & open" swap verb, AND Cmd/Ctrl+S so no path drops an estimate edit; an out-of-order complete triple (`optimistic ≤ most_likely ≤ pessimistic`, server-enforced #1982) sets `DialogFooter` `saveDisabled` + a validation message so the drawer never Saves-then-400s. The bar's `statusText` names the changed fields, collapsing O/M/P to one **"Estimates"** token ("Unsaved changes: Name, Estimates") while each changed field carries its own `aria-hidden` **`UnsavedDot`** "•" (the shared marker, `@/components/dialog`); a visually-hidden `role="status"` region announces the same for AT. PERT E/σ recomputes from the **draft** live, suppressing σ to `±—` with a non-blocking ordering hint while the triple is out of order; velocity **Accept/Dismiss** is disabled while the estimate draft is dirty (and re-baselines Most Likely via `useDirtyDraft.commitField` on a clean accept). `Cmd/Ctrl+S` saves when dirty. The desktop container is a true non-modal inspector (rule 264, ADR-0437).
