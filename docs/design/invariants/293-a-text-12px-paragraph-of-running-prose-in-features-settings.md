# Rule 293 — A `text-[12px]` paragraph of running prose in `features/settings/` carries a measure cap of …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Iconography*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A `text-[12px]` paragraph of running prose in `features/settings/` carries a measure cap of `max-w-[440px]`–`max-w-[480px]`.** The settings shell's content column is `max-w-[920px]`, so an uncapped 12px paragraph sets ~145 characters per line at desktop width — roughly double the 45–75 character comfortable range, at the page's *smallest* type, on the surface where an admin actually reads prose. Desktop is the primary device for these pages (rule 118's own rationale), so this is the viewport that matters. Already the de-facto convention: `WorkspaceMethodologyPage.tsx` (`max-w-[480px]`), `ProjectMethodologyPage.tsx` (`max-w-[440px]`), `ProgramCadencePage.tsx` (`max-w-[460px]`), `StakeholderReachSummary.tsx` (`max-w-[480px]`). This is about *prose* — a 12px label, chip, or table cell needs no cap. Surfaced by the #2529 ux-review.
