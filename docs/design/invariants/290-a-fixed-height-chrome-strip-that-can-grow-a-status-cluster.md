# Rule 290 — A fixed-height chrome strip that can grow (a status cluster, a tab rail, a filter row) gets an explicit …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A fixed-height chrome strip that can grow (a status cluster, a tab rail, a filter row) gets an explicit overflow rule — it scrolls; it never pushes its neighbours — and the rule is the whole contract below, not just `overflow-x: auto`.** A row of `shrink-0` segments with `white-space: nowrap` and no overflow rule does not wrap and does not scroll: it *pushes*, silently, at whatever viewport the user happens to be on, and the thing it pushes is whatever sits next to it (in the shell bar, the breadcrumb, and then the account chip straight off the screen). "It fits today" is not a rule — the first surface to add a segment breaks it, and nobody measures. Seven parts, all load-bearing: (a) **`min-w-0` + `overflow-x-auto`** on the strip, with **`[&>*]:shrink-0`** on its children — without the child rule the flex items compress instead and the overflow never happens, so the strip silently degrades to unreadable segments (the #2208 trap read from the other side); (b) a **`min-w-*` floor** on the strip, because a `min-w-0` box under shrink pressure is driven to *zero* before a rigid neighbour yields a pixel — with no floor the strip vanishes, taking with it the scroll affordance that was supposed to save it; past the floor the neighbour truncates, which is the correct order of sacrifice; (c) **hidden scrollbar** (`[scrollbar-width:none] [&::-webkit-scrollbar]:hidden`) so overflow appearing reserves no gutter and shifts nothing; (d) **both edge fades**, `aria-hidden` + `pointer-events-none`, each rendered only while that side actually overflows — a right-only fade is only correct for a strip that always scrolls from a fixed left origin (the board), and a strip whose offset moves when Tab focuses a segment is not that; (e) **`tabIndex={-1}` chevron nudges as the pointer-only path** — with the scrollbar hidden, a vertical-wheel mouse has *no* way to scroll the strip, so without chevrons a scrolled-out control is unreachable for a large share of desktop users; they are never the keyboard path, which is Tab; (f) **no `tabindex` on the region itself** — axe's `scrollable-region-focusable` is satisfied by focusable children, and a `tabindex` there mints a redundant tab stop; the corollary is that **every child must be focusable**, or the region becomes both unreachable and an axe failure; (g) **motion gated** — `scroll-smooth motion-reduce:scroll-auto` plus `behavior: reducedMotion ? 'auto' : 'smooth'` on the nudge (rule 70: motion only, never function). **Overlay corollary (the rule that bites):** `overflow-x: auto` establishes a clipping context on *both* axes and `z-index` does not defeat it, so **only children whose popovers portal to `document.body` or are `position: fixed` may live inside such a strip** — an in-flow `absolute` panel (the pre-rule-253/260 shape, e.g. `QuickLogTime`, `CreateMenu`) is clipped the moment it opens and must stay outside the scroller. **(h) The rule holds at EVERY width, and a breakpoint exemption is the bug (#3505).** The shell bar shipped `shrink-0 md:shrink-[9999]` on the region holding the strip: the scroll container existed on a phone but was inert there, because the region could not be squeezed, and the stated reason was that the phone bar had been *tuned to fit* rigidly at 375px (#1788). It had not — once the breadcrumb is truncated to zero, which it is on any project route at that width, a rigid region just keeps growing past the bar. So the one width with the least room to spare was the one width where "it scrolls, it never pushes" was suspended, on the strength of a fit nobody re-measured after the strip's contents changed. **What a breakpoint may vary is the ORDER of sacrifice, never whether the strip can give**: below md the location switcher carries the 9999 weight so the non-interactive wayfinding collapses first; at md+ the region carries it so the breadcrumb keeps its natural width. Both orders end with the strip absorbing the residue. Corollary on the floor from (b): once the region deliberately keeps its automatic minimum size, that minimum already includes the strip's own min-content, so a **second** `min-w-*` floor on the strip for the narrow band is dead CSS — verify a floor binds before writing one, and prefer the structural floor, which cannot drift out of step with the sibling it protects. Reference: `features/shell/StatusClusterScroller.tsx` (the implementation), `features/shell/TopBar.tsx` (the scroll/pinned split and the `shrink-[9999]` weight that makes the strip, not the breadcrumb, absorb the squeeze), `hooks/useHasScrollRight.ts`. `features/shell/ShellNavScroller.tsx` — the nav-tab scroller this rule was generalized from — was deleted unused in #3369; `StatusClusterScroller` is the sole surviving implementation of the contract.
