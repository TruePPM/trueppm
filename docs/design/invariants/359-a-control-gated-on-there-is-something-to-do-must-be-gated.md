# Rule 359 — A control gated on "there is something to do" must be gated on a fact the server owns or the client can …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A control gated on "there is something to do" must be gated on a fact the server owns or the client can always re-derive — never on a counter that only counts this session's own mutations.** A `useState(0)` version bumped from one mutation path is a truth about *this component instance's lifetime*, not about the data: it misses every sibling write path, every collaborator's change over the WebSocket, and it resets to zero on reload and on route re-entry. That is tolerable while the control is merely a *notice* — the user still has the action. It becomes a defect the moment the counter decides whether the **action exists**, because the state the user most needs the button in is precisely the state that reads as "nothing to do". **Falsification, and the one-line review test: open the surface in the state that should show the control, then reload — if the control disappears, the predicate is a session artifact and the gate is wrong.** Prefer a server-declared discriminant; where none exists, keep the action permanently available and let the *notice* carry the session signal. Two riders once you have the server fact. **(a) Default an absent discriminant toward offering the action, never toward hiding it** — a client that cannot tell must not assert the surface is fine, and the mapping default is where that is decided (`useMonteCarloResult`'s `mapStaleness` returns `unknown`, not `current`). **(b) Split the *action* from the *claim*.** A server value that is a sound trigger is often an unsound assertion: `forecast_staleness: project_changed` comes from a counter that any write in the project advances, so the bar offers Rerun but says only "Edited since this run" — never "your plan changed". Reference: `features/schedule/ScheduleForecastBar.tsx` (`useForecastStaleness`), `hooks/useMonteCarloResult.ts`, `apps/scheduling/forecast_staleness.py` — ADR-0954, #3140, sibling of #3132.
