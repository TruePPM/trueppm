# Rule 360 — A scroll container with no focusable descendant needs `tabIndex={0}` and a `focus:` ring — otherwise it is …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A scroll container with no focusable descendant needs `tabIndex={0}` and a `focus:` ring — otherwise it is unreachable by keyboard, and the two attributes you added for accessibility are what hide the fact.** An `overflow-y-auto` region scrolls from the keyboard only when focus is inside it or on it. A *form* panel gets that for free — its inputs are the seats — which is why the pattern looks safe everywhere it is used. An **outcome** panel does not: it is pure prose, and rule 335 deliberately puts its actions (Retry / Done / Close) in a **sibling footer**, so nothing inside the scroll box can take focus and the arrow keys scroll nothing. Rule 335's own `aria-describedby` then masks the gap, because AT reads the whole described node regardless of scroll position — so a screen-reader pass comes back clean while a **sighted keyboard-only** user on a short viewport simply cannot reach the overflowed half (WCAG 2.1.1). Three obligations. **(a)** Give any focusable-free scroll container `tabIndex={0}` — with an `eslint-disable-next-line jsx-a11y/no-noninteractive-tabindex` carrying the reason, since the rule is right about the general case and wrong about this one. **(b)** Pair it with the rule-4 ring as **`focus:`**, never `focus-visible:` (rule 288(c)) — a scroll seat with no visible ring strands the same user at an invisible location. **(c)** Order it **after** the phase's scripted seat effect (rule 245/335) so the container never captures the initial focus that belongs on the primary action. The general form: **a region that AT can read and a pointer can scroll may still be unreachable by keyboard, and the mechanisms that make it look fine are precisely the ones you added on purpose.** Reference: `features/schedule/buildMode/bulkEdit/BulkEditSheet.tsx` (`RESULT_PANEL_ID`), `features/sprints/StoryPickerModal.tsx` (`CommitResultPanel` — same shape) — #3152.
