# Rule 325 — A copy helper that writes a user-facing sentence is not shipped until something imports it — and on a surface …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A copy helper that writes a user-facing sentence is not shipped until something imports it — and on a surface where N gestures route a sentence, all N do, or the one that does not is the frequent one.** `insertSentence()` was written with its siblings, reviewed with them, tested with them, and imported by nothing for three releases (#3018): seven of the outline's eight structural gestures announced themselves through the live region and joined the session trail, and the eighth — **insert, the most frequent act on the surface** — was silent to a screen reader and left no record. That inverts the contract's own intent, since the acts performed constantly are the ones whose feedback matters most, and it is invisible to every gate we run: the helper had unit tests (they pass on a function nobody calls), the integration tests covered the four gestures that *were* wired, and a11y scans see a live region that is present and correctly formed but never written to. Four obligations: **(a)** route the sentence through **one helper**, and make its argument **required** — the recurrence guard is the type system, not a review, because an optional "and also announce it" parameter is exactly what the next insert path will omit; **(b)** record on **success**, not on the gesture — a trail entry for a row the server refused is worse than no entry, so bind it in the mutation's `onSuccess` the way delete does, and cover it with a mock that can *refuse* (a mock that only ever succeeds cannot tell a click-time record from a success-time one); **(c)** the sentence must be derived from **the same source as any statement the control already made** about where the act will land — `insertBelow` appends at the end of the parent's children, so a trail entry naming the *focused* row would contradict the toolbar sentence the user read before pressing the button; two descriptions of one mutation, disagreeing, is worse than one; **(d)** assert **each** path individually — a shared assertion over "an insert announces" lets three of four regress behind the one that still passes, which is how a suite covering indent/outdent/drag/delete stayed green through this. The general form: **when a module exports a family of related pure functions, an unimported member is a defect, not dead code** — the family exists because a contract said "every one of these", so the gap is the contract being broken, not an unused export. Reference: `features/schedule/trail/structuralActs.ts`, `ScheduleView.tsx` (`createNewTask`'s required `sentence`), `buildMode/insertTarget.ts` (`landingSiblingOf`, shared by the toolbar statement and the trail sentence).
