# Rule 340 — A word the product must not say is not enforced by asking people not to say it — put the word in ONE module, …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A word the product must not say is not enforced by asking people not to say it — put the word in ONE module, brand its type, and let `tsc` refuse the literal.** A row in the outline may be a task, a phase, a milestone or a subtask, and `structure_role` is *declared*, never assumed (ADR-0843) — so on the surfaces that exist **before** the type does (column headers, create affordances, placeholders, and the name a create path mints) the noun must be **item**, because any other noun is a claim about a row nobody has made yet. That rule was swept by hand in #2952 and again in #3027, and rule 300 says a rule needing a second sweep has no mechanism. Four obligations. **(a) The enforcement is the TYPE SYSTEM, not a scan.** Governed copy is a branded `VocabularyToken` whose minter is not exported, so `<Footer label="Add a task at the end" />` is a compile error at the call site, there is no roster to maintain, and nothing can go vacuous — `tsc` cannot match nothing. A scan of the same shape would have to ask "is this word correct here?", which is unanswerable mechanically: **`task` is the right word wherever the type IS known, which is most of the product**, so a "no `task` in user-facing strings" gate would fire almost entirely on correct copy and demand wrong fixes. Make the governed prop **required**, never a defaulted `string`, for rule 325's reason — an optional "and also use the right noun" parameter is exactly what the next surface omits. **(b) A row's own NAME is a stronger type claim than any label, and it is where the sweeps kept failing.** #3027 found `+ Item` creating a row literally named `New task`: the user is asked to fill a Name cell that already asserts the type, and pressing Escape commits it into the plan, the WBS and the Σ rollup. Two shapes reach that slot and both need catching — `name: 'New task'` **and** the blank-name fallback `row.name || 'Untitled task'`, which is not an assignment and which a `name:`-only pattern misses (two were live). **(c) Sweep the ACCESSIBLE tree, not the painted one.** The name column headed `Item` had a resize handle announcing "Resize **task** column", because the handle built its label from the internal `colKey`; #3027 saw it, recorded it in a spec comment, and deferred it. A rendered-DOM guard that reads `aria-label`, `title` and `placeholder` — not just text — re-found it without being told to look, which is the whole difference between a note and a mechanism. Any control describing a column by a different noun than its heading is the same defect arriving where no visual review goes. **(d) State what the mechanism CANNOT see, in the mechanism.** Types cover governed props; the scan covers copies within the outline's tree; the DOM guard covers what the outline renders. A brand-new component with brand-new wrong wording is caught by none of them, and every layer here asserts its own non-vacuity (a token floor, a per-surface "found ≥1 string" check, a self-test that plants each violation) because a guard that reports green after its query stops matching is how the sub-12px lint gate survived six sweeps. A stale allowance is the same hazard in miniature: assert each exception still names the thing it excuses — one of this change's four did not, and the check deleted it.
