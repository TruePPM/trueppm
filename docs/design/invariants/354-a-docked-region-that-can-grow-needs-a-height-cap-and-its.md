# Rule 354 — A DOCKED region that can grow needs a height cap and its own scroller — and the ancestor that would otherwise …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A DOCKED region that can grow needs a height cap and its own scroller — and the ancestor that would otherwise clip it cannot scroll, which is why nobody notices.** Rule 351 covers the *floating* panel; this is its sibling for the in-flow one, and it is the more dangerous half. A popover that overruns the viewport at least spills where the page's own scrollbar might reach it. A strip, bar, or dialog body that overruns an `overflow: hidden` ancestor is **painted nowhere**: no scrollbar appears, the wheel does nothing, `scrollIntoView` is a no-op, and a keyboard user Tabs to a control that exists in the accessibility tree and at no visible coordinate. The class has now shipped four times — #539 (settings at 375px), #2665 (`NewProjectModal`, the Create button clipped off the bottom), #2674 (`ImportModal`, which #2665 *identified* and left live), #3166 (`ScheduleForecastBar`) — each found by a person looking at a screen, each fixed only at the site that was reported. Five obligations. **(a) The shape is fixed, and `min-h-0` is the half that gets dropped.** `max-h-[Nvh] overflow-hidden flex flex-col` on the shell, `shrink-0` on the pinned header and footer, `flex-1 min-h-0 overflow-y-auto` on the body. A flex item defaults to `min-height: auto` and so refuses to shrink below its content — without `min-h-0` the scroller never engages and the overflow is simply handed back to the clipping ancestor, so the cap alone just moves *where* the content is lost. `SettingsShell.tsx` carries this comment on both of its scrollers because it is where the rule was learned. **(b) Cap in `vh`, not `%`.** A percentage max-height resolves against the containing block only while every link in the height chain stays definite; the moment one stops being so it computes to `none` and fails back to exactly this bug with no signal anywhere. **(c) Scope the cap to what the surface is FOR.** `ScheduleForecastBar` caps at `40vh` rather than half its column because the Gantt is the product and the forecast is a strip about it — a fix that leaves a secondary surface larger than the primary one has traded a broken screen for a wrong one. Note the collateral damage runs the other way too: a `flex-shrink-0` region with no cap starves its siblings, and #3166 drove `ScheduleMainArea` to a **zero-pixel canvas**. **(d) The breakpoint-scoped fix is the recurring near-miss.** `ImportModal` had the entire correct shape behind `max-md:`, so the phone sheet scrolled and the ordinary desktop dialog had neither a cap nor a scroller. If the mobile sheet needs to scroll, so does the desktop card; only the *chrome* (edge-to-edge, rounding, safe-area padding) is breakpoint-scoped. **(e) A vitest assertion pins the mechanism and a browser pins the value.** jsdom computes no layout at all — `scrollHeight` is 0 everywhere — so a unit test can assert the classes and nothing else, and reading it as coverage of the behavior is rule 300(a)'s failure. The measurement is `e2e/clipped-content.spec.ts`, which sweeps the primary surfaces at **1280×720 and 375×667** (every instance of this class is invisible at 1080p, which is exactly why they reach users and not reviewers) and asserts the invariant directly: *no clipping container may hold content taller than itself*. Its one escape hatch is a `data-clip-ok="<reason>"` attribute on the element — on the element rather than in a list inside the fixture, for rule 351's reason, so the marker moves with the code it excuses and cannot be edited without landing in the same diff hunk; the reason may not be empty. Do **not** add an "unless some descendant scrolls" exemption to the detector: a correctly-built inner scroller already makes its parent measure clean, and the first draft's version of that let the Schedule's unrelated task-list scroller cancel the #3166 finding, reporting green against the unfixed tree. Reference: `features/schedule/ScheduleForecastBar.tsx`, `features/schedule/reconcile/ScheduleReconcileStrip.tsx`, `components/import/ImportModal.tsx`, `features/settings/SettingsShell.tsx`, `e2e/fixtures/clipped-content.ts` — #3166, closing #2674.
