# Rule 338 — Demoting a creation surface means deleting its FORM, not its affordance — and an affordance that carries …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**Demoting a creation surface means deleting its FORM, not its affordance — and an affordance that carries context a route cannot express must keep its own control.** Case 18's disposition table said to demote the board's lane `+` into the Designer via `?author=`, and following that literally would have dropped three facts silently: the synthetic phase-less lane commits `BACKLOG` while a real phase commits `NOT_STARTED` (#387's VoC outcome, decided on purpose), and since #2967 a cell also carries a named lane. `?author=` has no representation for any of them, and widening it would turn a **hand-editable URL into a board write path** — `parseAuthorIntent` is strict precisely because the consumer's job is to create a row. So the lane keeps its control and loses its `TaskFormModal`, which is what the table was actually objecting to; the empty board, which has no lane and therefore no status, container or lane to preserve, is the one case the table is right about unamended. Four obligations. **(a) Ask what the affordance CARRIES before demoting it, not what it looks like.** Two buttons that both "create a task" are different surfaces if one of them knows where the row goes. The test is whether the destination route can express every fact the position implied; if it cannot, demoting is a silent data change wearing a refactor's clothes. **(b) The replacement shares the ORIGINAL's behavior through a hook, not through a copy.** `useRapidCompose` owns the optimistic clear, the error restore that never clobbers a half-typed replacement, the container-bound Escape (an input-bound one stops honoring the `aria-keyshortcuts` it advertises the moment focus tabs to Add), and `readOnly`-never-`disabled` (a disabled input is blurred by the browser, closing the soft keyboard, and nothing re-focuses). Two capture surfaces that drift are worse than one modal. **(c) Carry the old surface's DEFAULTS across, and assert the write rather than the widget.** `duration: 1` is what the modal created here — the backlog rail's `0` is the milestone definition in the locked vocabulary, so reusing it would have minted a zero-duration row for every task added to a phase. Once the status is no longer a select the user can see, the only honest assertion is what the POST body carries. **(d) A field on the payload TYPE is not a field on the wire.** `board_lane` was declared on `CreateTaskPayload` and type-checked green while `useCreateTask`'s `mutationFn` — which builds its body key by key — dropped it before the request; the spread that passed it in defeated excess-property checking too, so nothing anywhere complained. Grep the mutation body, not the interface, and pin both arms: forwarded when set, **absent** when not, because an unconditional spread puts `undefined` on every create the app makes. Corollary — when the demotion strands tests, check whether the assertion was ever a journey: three of this change's e2e casualties were duplicating `TaskFormModal.test.tsx` through a browser, one would have passed vacuously against a dialog that no longer renders, and only the genuinely-different ones were re-homed. Reference: `features/board/useRapidCompose.ts`, `features/board/LaneComposeField.tsx`, `features/board/BoardView.tsx` (`handleAddTask`, `handleComposeCommit`), `hooks/useTaskMutations.ts` — #2952.
