# Rule 437 — Mute text with a solid text token — never `opacity-*` over text

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Color and tokens*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**Mute text with a solid text token — never `opacity-*` over text.** `opacity` composites whatever color is underneath it with the surface behind, so the resulting contrast is a product of two things no token documents. The Calendar weekend mute was `opacity-60` over `text-neutral-text-primary` and rendered `#767F92` on white: **4.02:1**, below WCAG 1.4.3's 4.5:1 — and swapping in `text-neutral-text-secondary` under the same opacity would land near 2.6:1, so the token swap alone does not fix it. To read as "less important", pick a solid token that already clears 4.5:1 on the surface it sits on (`text-neutral-text-secondary`, or `text-neutral-text-disabled` for out-of-month/inert text, both AA-tuned in `globals.css`) and, if more separation is needed, lighten the weight. Opacity on non-text decoration (dots, rules, icons that carry no information alone) is unaffected. Opacity on a container also dims every child, including chips and marks that should stay full strength. Reference: `features/calendar/CalendarGrid.tsx` — #3879.
