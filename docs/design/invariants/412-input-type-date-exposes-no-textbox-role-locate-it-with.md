# Rule 412 — `input[type="date"]` exposes NO `textbox` role — locate it with `getByLabel`, never `getByRole('textbox')`, …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Controls and composition*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**`input[type="date"]` exposes NO `textbox` role — locate it with `getByLabel`, never `getByRole('textbox')`, and pass `{ exact: true }` in Playwright.** A date input maps to no ARIA role in any engine we test, so `getByRole('textbox', { name: … })` matches nothing and the spec fails at CI runtime with a timeout that names the locator rather than the cause. `tsc` cannot see it and lint cannot see it — this is the wrong-locator-role class the root `CLAUDE.md` warns about, in its most reliable instance. Two obligations. **(a)** Give the input a real `<label htmlFor>` rather than an `aria-label`, so the accessible name equals the visible text and WCAG 2.5.3 (Label in Name) cannot drift; then `getByLabel` is the locator on both vitest (`getByLabelText`) and Playwright. **(b)** Playwright's `getByLabel` is a **substring** match by default, so a section whose own explanatory copy repeats the field names will match more than one node — pass `{ exact: true }` on every date-field locator. Reference: `e2e/actual-dates-drawer-edit.spec.ts`, `features/schedule/sections/ActualDatesSection.tsx` — #3529, surfaced by `ux-review`.
