# Rule 394 — A `QueryErrorState` inside a COLLAPSED `<details>`, accordion, or hidden tab panel satisfies rule 246 and …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Foundations*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A `QueryErrorState` inside a COLLAPSED `<details>`, accordion, or hidden tab panel satisfies rule 246 and defeats it — a failure must reach the always-visible chrome.** Rule 246's requirement is that a dead request be *visually distinct* from "nothing here yet". A collapsed summary row is byte-identical whether the fetch succeeded, returned nothing, or died, so the one reader who needs the signal is the one with no reason to expand — and two mechanisms fail together: the `inline` variant's `role="status"` mounted inside a `display:none` subtree announces **nothing, ever** (rule 335's hazard one step worse — hidden at mount, not merely co-mounted with its text), and the `Retry` control is unreachable behind an interaction nothing prompts. So force the disclosure open on failure (`<details open={q.isError}>`) or mark the summary itself; never render the failure only into the collapsed body. **The loading half is the same argument.** A container gated on `.data` is absent while the query is in flight, so it pops in and reflows a column whose ghosting siblings did not — render the container in every query state and branch its BODY (rule 248). **And fix the population, not the instance (rule 300).** The class rule 300 already names — "page swallows a fetch error as an empty state", fixed one page at a time across #1764/#1937/#1942 — recurs because the remaining sites are usually adjacent lines in the same function, not another file: `grep -n '\.data ?' <file>` is the whole population and it costs one command. A column where one widget offers Retry and its neighbours pulse forever is *worse* than one where none does, because it teaches that a pulse means "loading". The general form: **a state is not handled because the right component is mounted; it is handled when the state is reachable from where the user is standing.** Reference: `features/sprints/SprintsView.tsx` (the planned-surface velocity `<details>`, and the four `.data ?` widgets swept with it) — #3472, surfaced by `ux-review`, extending rules 246/248/300.
