# Rule 306 — A security-relevant escaper (CSV cell, HTML, filename, shell) has exactly ONE implementation in this tree, …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Placeholders and operator surfaces*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A security-relevant escaper (CSV cell, HTML, filename, shell) has exactly ONE implementation in this tree, and the thing that keeps it that way is a source-scanning test — not a code review.** CSV/formula injection was fixed in `utils/exportCsv.ts` and `features/risk/riskExport.ts` by #2762, and then found again at `WorkspaceMembersPage` and `WorkspaceRolesPage` (#2892), because each surface that needed a CSV cell had written its own `csvCell` doing RFC 4180 quoting only — no formula-prefix neutralization and no `\r` in the quoting regex, so a member display name beginning `=`/`+`/`-`/`@` executed on open in Excel and an interior lone CR could split the record and smuggle a live formula past the guard. Every one of those copies passed its own unit tests; what a per-file test structurally cannot see is that a *sibling* file has a weaker guard, which is why two rounds of site-by-site fixes did not end the class. Three obligations: **(a)** a new CSV surface imports `escapeField` and `downloadCsv` from `@/utils/exportCsv` and adds nothing of its own — widen the shared helper for a new cell type (`riskExport`'s one-line `String(value ?? '')` wrapper is the allowed shape) rather than reimplementing quoting beside it; **(b)** the guard and the quoting must **compose in that order** — prefixing never removes the need to quote, and quoting alone does not stop evaluation; **(c)** the invariant under test is *"there is only one"*, not *"this one is correct"* — `src/utils/exportCsv.conformance.test.ts` source-scans the tree for a second `FORMULA_PREFIX_CHARS`, a hand-rolled `replaceAll('"', '""')`, or a `new Blob` carrying `text/csv`, and asserts its own scan is non-vacuous so a broken glob cannot pass by finding nothing. Do not replace it with a hand-maintained list of sites to check: that enumeration is precisely what let the class survive #2762. This is rule 300 applied to an injection class — a rule that needed a second manual sweep did not have a working mechanism.
