# Rule 245 — A dialog that stays open while its content swaps state passes that state as `useFocusTrap`'s `focusKey`; a …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A dialog that stays open while its content swaps state passes that state as `useFocusTrap`'s `focusKey`; a confirm dialog nested inside a modal whose parent trap yields must run its own `useFocusTrap` — never ship a modal surface where Tab can reach the background page (WCAG 2.4.3 / 2.1.2).** Two failure shapes, one hook. (a) **Multi-state dialogs**: `useFocusTrap(active, onEscape)` seats initial focus only when `active` toggles, so a wizard/phase dialog (ImportModal's picking → uploading → success/error, PromoteMilestoneDialog's conflict ↔ form) drops focus to `<body>` when the phase unmounts the focused control — and Tab then escapes the "modal." Pass the phase/mode as the third `focusKey` param; the trap re-seats on change (first focusable, else the container — give the container `tabIndex={-1}` so a control-less phase like a progress screen still has a seat), skips the re-seat when focus is still inside (so swaps that keep the focused control mounted don't yank it), re-seats off the container itself once controls reappear, and still restores the *activation-time* trigger on close. A consumer wanting a nicer target than "first focusable" keeps a small `useEffect` focusing its preferred ref *after* the hook (call order = effect order), like PromoteMilestoneDialog's first-form-field seat. Do **not** hand-roll trap/Escape/restore logic in a component — convert it to the hook. (b) **Nested confirm dialogs**: a parent modal that disables its trap while a child `alertdialog` is open (TaskFormModal's `!showDeleteConfirm && !showDiscardConfirm` gate) is only safe if **every** such child runs its own `useFocusTrap` — an untrapped child (the old DeleteConfirmDialog: autofocus + Escape only) leaves Tab free to tunnel into the background form. Order the child's buttons so the safe action is the first focusable (the trap's default seat) — destructive actions never autofocus the destructive button. Reference: `hooks/useFocusTrap.ts` (`focusKey`), `components/import/ImportModal.tsx`, `features/sprints/PromoteMilestoneDialog.tsx`, `features/board/TaskFormModal/DeleteConfirmDialog.tsx` vs `features/settings/components/ConfirmDiscardDialog.tsx`.
