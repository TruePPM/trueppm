# Rule 369 — Merging two controls into one transfers two things, and the second is the one that gets missed: every ACT the …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**Merging two controls into one transfers two things, and the second is the one that gets missed: every ACT the retired control performed, and every SENTENCE elsewhere in the product that described its shape.** #3263 merged `BuildModePill` and `AuthorModePill` into `ScheduleModeChip` and handled the acts deliberately — the pill's only job was opening the cheatsheet, so a `Keyboard shortcuts…` row shipped in the same change rather than being owed (the #3115 failure, where a toolbar button was removed on the strength of a replacement that never arrived, is what that care is for). What it did not transfer was the *description*: the Display popover's locked row still read `Zoom, mode, engine status` / "Always present; collapse to a chip when narrow", which the merge made false — while the same MR's docs page was edited to say the opposite, so the product and its documentation disagreed **inside one commit**. Three obligations. **(a) Grep for the retired control's SHAPE, not its name.** A name grep finds `BuildModePill` and comes back clean because every survivor is prose; the sentences that break say "collapses", "merge into", "two pills", "when narrow" — the behaviour, in copy that never names a component. **(b) The surface that answers "where is this control" is the first place to check, and it is the one with no test.** Rule 343(f)'s corollary makes the Display popover the product's authority on control location; a wrong sentence there sends someone resizing a window for a shape change that will never come. Those rows are bare string literals with nothing asserting them, which is why a 15,697-test green run proved nothing about them — assert the locked rows whenever the ladder or the inventory changes. **(c) A merge that falsifies a DESIGN RECORD's premise needs a dated Superseded note in the same MR.** `docs/design/decisions/194` justifies the hint strip carrying no live region on the grounds that "the AT signal for build mode is the always-on pill"; deleting the pill removed the load-bearing half of an accessibility argument that is still shipped. A corollary on the interaction budget: a merged control that hides its act behind a popover makes the KEYBOARD path primary, so the chord it now steers people to must announce its outcome — and the popover must close on a single-checkbox toggle, or the pointer path is three interactions and the trade stops being defensible. Reference: `features/schedule/toolbar/ScheduleModeChip.tsx`, `features/schedule/ScheduleView.tsx` (the `locked-state` pin row), `components/toolbar/ToolbarOverflowMenu.tsx` (`closeOnChange`), `docs/design/decisions/194` — #3263, after #3076.
