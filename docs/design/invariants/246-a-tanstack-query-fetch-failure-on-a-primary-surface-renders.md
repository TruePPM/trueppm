# Rule 246 — A TanStack Query fetch failure on a primary surface renders the shared `QueryErrorState` …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A TanStack Query fetch failure on a primary surface renders the shared `QueryErrorState` (`components/QueryErrorState.tsx`), never an empty or perpetual-skeleton state — a dead request must be visually distinct from "nothing here yet".** A page that destructures only `data`/`isLoading` and ignores `error` renders a failed fetch as empty (Board) or a skeleton that never resolves (Overview) — indistinguishable from a genuinely empty or slow surface, which corrupts beta feedback and support triage (#1764). Wire `error`/`isError` into the query hooks and render `QueryErrorState` in place of the empty/skeleton branch. Two variants: **`fill`** (`role="alert"`, `bg-neutral-surface`, `h-full`, centered) for a whole-page/pane failure the user navigated to (Board, Grid, Schedule) — assertive because the surface is dead; **`inline`** (`role="status"`, `rounded-card border-neutral-border bg-neutral-surface-raised`, `min-h-24` to match the skeleton footprint it replaces) for a single widget on a still-working page (each Overview widget) — polite, so a total outage does not fire N assertive announcements that interrupt each other. Retry defaults to `window.location.reload()`; pass a query `refetch` (`onRetry={() => void refetch()}`) when the hook exposes one so retry re-runs just the failed request. Copy is one terse `Couldn't load <X>.` per surface. This completes the surface-state trio with `EmptyState` (rule 177, role-less, calm zero-data) and the route `errorElement` (rule 224, `role="alert"`, self-focuses on a render-throw): widget fetch error → polite in-place; empty data → calm; route throw → assertive-and-self-focusing. **`QueryErrorState` keeps `role="status"` on its `inline` variant and that is not an inconsistency with ADR-0989.** Both rules face the same N-announcement problem and solve it differently on purpose: `inline` solves it with **politeness** — N failed widgets announce, but politely and without interrupting each other, and each names a different thing that broke, so N announcements is the honest count. An empty surface solves it with **coalescing** — four empty Board columns are one piece of news, and the fourth adds nothing to the first. Reach for relocation-plus-registry only when the repeats are genuinely redundant; reach for politeness when they are distinct but non-urgent. **A section on a consolidated settings page takes `inline`, not `fill` (#3298).** `WorkspaceSettingsPage` and `ProjectTeamWorkflowPage` mount every section at once on one scroll surface, and a single endpoint backs several of them — `GET /workspace/` feeds General, Methodology, Schedule, Calendar, Attachments and Feedback. So one failed request is N failed sections, which is the exact N-assertive-interrupt case `inline` exists for; and the surrounding page is emphatically *not* dead, since every section on a different endpoint still works. Two consequences that are easy to get backwards: the section's `SettingsPageTitle` must still render inside the error branch, because `<SettingsSection aria-labelledby>` targets the heading id it mints and dropping it dangles that reference; and when a page gates its skeleton on **two** queries (`ProjectMethodologyPage` waits on both the project and the workspace settings) both must be error-checked, or the unchecked one stalls the page exactly as before while the checked one looks handled. **`WorkspaceGeneralPage` uses `fill` here and is the counter-example, not the model** — it predates this clause and fires an assertive alert for a section-scoped failure; do not copy it. **Two gates enforce this rule and they cover different halves — do not read either one's green as covering the other (#3351).** `check-design-system-v2.sh` check **4e** is a RATCHET over destructures taking `isLoading` and never `error`; it keys on `isLoading`, so `const { data: ws } = useWorkspaceSettings()` is invisible to it — which is how `ProgramCalendarPage` shipped the identical stall #3298 had just fixed one scope down, with the gate reporting the file as one offender while it held two. Check **4f** closes that half at **ZERO TOLERANCE**: a `data`-only query binding whose identifier appears in the condition of an early return rendering `animate-pulse` fails the gate outright. The asymmetry is deliberate — 4e counts a population whose members mostly have a legitimate "my parent owns the error" defence, whereas a skeleton gated on a value a failed fetch pins at `undefined` has none, and unlike `isLoading` that term never clears. 4f sees `if (…)` early returns only; a skeleton chosen by a ternary or by a child's own guard is still on you. **It is POSIX awk, not python3** — the `lint:design-system-v2` job runs `alpine:3.20` with `apk add bash grep` and nothing else, so the first cut of this check exited 127 there while passing on macOS; and because the self-test read *any* non-zero exit as "correctly rejected", the crash printed three `SELF-TEST OK` lines for a gate that had not run at all. `st_probe` now requires the gate's own count line in both directions and exit 1 rather than merely non-zero, so a crash can never again be read as a rejection — the tell is that the failures are exactly the expect-PASS cases. Reference: `components/QueryErrorState.tsx`, `features/board/BoardView.tsx`, `features/project/ProjectOverviewPage.tsx`, `features/settings/workspace/WorkspaceMethodologyPage.tsx`, `features/settings/program/ProgramCalendarPage.tsx`.
