# Rule 416 — A real, nonzero-denominator computed zero is a value, not a health signal — it must never wear the on-track/success color

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Signal encoding*. The index carries the rule's headline; this file carries its full text. Binding everywhere, not only on the surface that produced it.

**A real, nonzero-denominator computed zero is a value, not a health signal — it must never wear the on-track/success color.** This is the color corollary to rule 119 and to #2428's "a real zero is a value, not an unavailable card": the two rules together cover the full space a zero can occupy. Rule 119 governs a **zero (or missing) denominator** — 0/0 is mathematically undefined, so it renders muted with a plain-language reason, never a number. This rule governs the other case: a **nonzero denominator with a real, server- or client-computed zero numerator** — 0 of 34 story points committed, 0% team utilization against a roster that genuinely has capacity this week. That value is meaningful and must stay visible as a number (hiding it is the #2428 bug in the other direction) — but "zero committed/assigned" is not "on track," and every threshold-based variant map in the codebase (`value > 90 ? 'at-risk' : value >= 70 ? 'on-track' : 'neutral'`, `over > 0 ? 'critical' : 'on-track'`) falls through to its "healthy" branch at zero by construction, because zero is the smallest number a threshold ladder can see. Coloring that fall-through as success is what let five separate cards read an unstaffed project, an empty sprint, or an un-started backlog as good news (#3477). **The fix is always the same shape: special-case the exact zero to `neutral` before the threshold chain runs**, e.g. `value === 0 ? 'neutral' : value > 90 ? 'at-risk' : …` — never invert or remove the threshold chain itself, which still correctly colors every nonzero value. Do not conflate this with rule 119's muted treatment: a real zero keeps its normal (non-dashed, non-disabled-tone) card chrome and its real numeric value — only the color variant changes. Reference: `lib/notComputableMetric.ts` (`isZeroValue`), `features/sprints/CapacityPreflight.tsx` (points-chip footer), `features/project/ProjectOverviewPage.tsx` (`buildUtilizationMetric`) — #3477.
