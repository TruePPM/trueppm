# Rule 327 — A row's own state must render AT REST, and the cell that states it is where the cell edits it — adding that …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A row's own state must render AT REST, and the cell that states it is where the cell edits it — adding that control changes what a geometric row click hits.** The Schedule row carried `←2` / `→1` dependency chips that appeared **only while the row was selected in focus mode**, so learning whether a row had links required selecting it, which is the opposite of scanning a plan; and the only way to change a link was a right-click menu, so the row could show what it was linked to or offer to change it, never both in one place (#3023, `design_handoff_trueppm_v4/`). Four obligations, and the fourth is the one that bites. **(a) A fact about the row renders unconditionally.** Selection, hover and focus mode are *emphasis*, never the precondition for a fact existing — a signal you have to go looking for answers a question you no longer have. **(b) State the SHAPE, not the tally — and state it in WORDS where a tint is doing the work.** `←2` cannot separate two finish-to-start links from an FS and an SS, and that is the difference between a chain and an overlap — the question the glance was actually asking. Name the types (`FS×2` / `FS·SS`), pick one honest reading for the case the design left open (here: three or more distinct types collapse to `Mixed×N`, counting links so the count means one thing in every arm; a type the client does not recognize echoes its own code rather than falsely reading `Mixed×1`), and put the full breakdown in the tooltip and the cell's `aria-label` rather than widening the token — capped, because a hub row otherwise produces a multi-kilobyte label nobody can read. Criticality belongs in that sentence too: red-on-chip was survivable while the chips appeared only on a selected row, but a column at rest makes hue the sole carrier of the one fact that changes what the reader does next, which is a WCAG 1.4.1 failure. **(c) The control is a control only for someone who may author** — a viewer gets the identical statement as text, absent rather than disabled (rule 302). Gate on the authoring API, not on the mode flag, which is also non-null for a reader because it carries navigation. **Two facts side by side are two targets**: a cell drawing `←FS×2` and `→FS` and routing both to the predecessor picker sends half the clicks to the wrong direction, so give each its own control; and let the control **fill the cell** rather than float in it, or the row's 44px coarse-pointer height wraps an 18px target. **(d) A cell that is also a control makes the row's CENTER a live target, and every pointer action aims at the center.** Seven E2E specs across two files were selecting or renaming a row by aiming at whichever column happened to sit at the midpoint — Duration at seven columns, the new Links control at eight — and the control `stopPropagation()`s, so each failed two lines later on an `aria-selected` assertion or a missing rename `input`, with nothing pointing at the column that had been added. The blast radius is **every row, not only linked ones**: the empty-state affordance means an unlinked row's cell is a control too. The fix is not an offset: **locate the cell by name** (`getByRole('gridcell', { name: /^(Duration|Estimate):/ })`), which survives the next column too, and remember one column can carry two labels across row kinds. Before adding any column, sweep `e2e/` for a pointer action on an **un-narrowed row locator** — and sweep it structurally, because the obvious grep does not find this: the two worst instances were a `dblclick()` (not `click`) on a `page.locator('[data-row-id="…"]')` (not `getByRole('row')`) **held in a variable** (not an inline chain). Cover `click` / `dblclick` / `tap`, both locator forms, and variable-held locators; a chain that narrows to a `gridcell` / `button` / testid first is safe, and `hover()` is safe because it bubbles. Nothing mechanizes this yet — a `scripts/` check that flags a pointer action on an un-narrowed row locator is what would catch the eighth instance. Reference: `features/schedule/deps/depFlag.ts`, `features/schedule/TaskListRow.tsx` (`TaskLinksCell`), `e2e/schedule-links-cell.spec.ts`, `e2e/schedule-group-ungroup.spec.ts` (`durationCell`).
