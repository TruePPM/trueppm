# Rule 177 — A primary surface's zero-data state is a warm `EmptyState`, not a bare "No data" line; its single entrance …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A primary surface's zero-data state is a warm `EmptyState`, not a bare "No data" line; its single entrance animation is `motion-safe:` only.** The shared `EmptyState` (`components/EmptyState.tsx`) is the v2 anatomy — a **role-less** block (see the announcement paragraph below) with a decorative (`aria-hidden`) icon in a `72px` `rounded-full border bg-neutral-surface-raised` circle, a `text-[17px] font-semibold` `<h2>` title, optional `max-w-[380px] text-[13px]` orientation copy, and an optional CTA (the shared `<Button>`). Use it for the genuinely cold cases (Schedule read-mode `ScheduleEmptyState`, Risk register, Grid); surfaces with bespoke needs — role-flavored copy or multiple CTAs (`MyWorkEmptyState`, `BuildModeEmptyState`, `EmptyBacklog`) — keep their own component but follow the same anatomy. Pass `className="h-full …"` when the host must fill its area; the icon is always decorative — the `<h2>` title is the accessible content, and it is also the sentence the announcement speaks. **Announcement (ADR-0989, #3198): the block carries no role and no live region of its own.** It registers its title with the app-wide registry (`useEmptyStateAnnouncement`, `components/emptyStateAnnouncements.ts`), and the shell's one permanently-mounted polite region (`EmptyStateAnnouncer` in `AppShell`) speaks it **on the transition into empty** — so a remount at unchanged emptiness (route change, project switch, a filter edit that leaves the surface equally empty) says nothing, and a Board with four empty columns announces once rather than four times. Two things this fixes that are easy to conflate: a region mounted together with its own text is announced inconsistently across AT (rule 335), *and* mount is a strictly larger event than "became empty" — the second is why the fix could not live inside the component, which can only ever observe its own mount. The bespoke empty states this rule licenses (`GridFilteredEmptyState`, all three `MyWorkEmptyState` flavors) call the same hook; **do not add `role="status"` back to any of them.** Specs that need the container scope on `data-testid="empty-state"` (rule 242). Announcement specs must count **emissions** via `subscribeEmptyStateAnnouncement`, never the region's text — a redundant announcement leaves exactly the text a correct one leaves, so a text assertion is green against the defect (verified by mutation; see `emptyStateAnnouncements.test.tsx`). **Motion:** the block fades+lifts once via `motion-safe:animate-empty-state-in` (160ms brand ease; keyframe in `globals.css` beside `cmdk-in`) — gated at the class layer so `prefers-reduced-motion` users get the content with no animation (the v2 motion contract: motion only, never content — rule 70). Do not add a second always-on empty-state animation, and never animate content in/out without the `motion-safe:` gate.
