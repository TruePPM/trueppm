# Rule 371 — A card that names where it will take you and the function that chooses the destination are two sources for …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A card that names where it will take you and the function that chooses the destination are two sources for one fact — derive them from the same input, in the same module, or they will disagree and nothing will notice.** The Start sheet's Blank card promised "Opens straight into the outline with the cursor already in the first row" while `createdProjectDestination` returned `/overview` for exactly that way in. Both shipped correctly on their own terms and neither was ever wrong in isolation: the copy landed with the sheet (`b0998fbde`), the destination landed a day later (`96a195682`) already returning `/overview`, and they never agreed for a single commit (#3311). This is not a stale-copy bug — the promised screen genuinely exists (`BlankProjectCanvas`, `BlankOutlineDraftRow`, #2733), which is what makes it worse: the card names a real capability at the wrong address, so a user who reads it and lands elsewhere has no reason to suspect the screen is one navigation away. Three obligations. **(a) The copy takes the same input as the route.** Make the card body a function of whatever the destination branches on — here `WAY_DETAIL.blank.body(methodology)` beside a `createdProjectDestination` that branches on the same `methodology` — so a change to one is a type error or a visibly stale branch in the other, not a silent divergence. **(b) Check the destination is reachable FOR THIS CONFIGURATION, not just that the route resolves.** `methodologyTabs.ts` hides `schedule` on AGILE and `product-backlog` on WATERFALL, so a single hardcoded landing is guaranteed wrong for one methodology — routing every blank create to the Schedule would have traded a wrong landing for the #2619 dead end ("Schedule isn't part of this project's workflow"). A route registered in `router.tsx` is not evidence the user can get there. **(c) Pin the pair in one test.** Assert the destination for every branch AND assert the copy names that surface; a test that pins only the router lets the sentence rot, and the sentence is what the user reads. Reference: `features/shell/createdProjectDestination.ts`, `features/shell/NewProjectModal.tsx` (`WAY_DETAIL`), `features/shell/methodologyTabs.ts` — #3311.
