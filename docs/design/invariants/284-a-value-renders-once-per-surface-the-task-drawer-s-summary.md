# Rule 284 — A value renders once per surface: the task drawer's summary strip is the READ surface, the sections below it …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Redundancy*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A value renders once per surface: the task drawer's summary strip is the READ surface, the sections below it are the EDIT surface, and a value belongs to exactly one of them (#2424).** The #2315 at-a-glance strip landed *on top of* the existing sections rather than replacing their content, so Status, Finish and Float each rendered **twice inside one 270px band** — the strip, then again as a control roughly 150px below. Nothing in the layout said which copy was authoritative, so both read as inputs and whichever one the user did not touch looked stale for a frame; the redesign meant to reduce density doubled it. Four invariants: (a) **anything editable is not in the strip, anything in the strip is not editable there** — Status is a `<select>` below, Finish and Float are in the Schedule grid, so all three left; the strip header carries a `read only` pill so the contract is visible, not just documented. (b) **A read-only value still does not belong in the strip if another surface already carries it** — the drawer header renders the WBS code and `DrawerRecentActivity` sits directly above the strip, so re-rendering either there would trade one duplicate for another; the strip keeps only the owner and the baseline comparison, which are carried nowhere else. This is the rule the design handoff's cell list did not know about, and the general form is worth stating: *before adding a cell to a summary surface, grep the surface for the value.* (c) **`FLAGS` renders only non-empty flag content and returns `null` otherwise** — no header, no "No flags" placeholder, no reserved height. A flag is a condition that is **false for a healthy task** *and* **actionable** (blocked, negative float); float, baseline variance, % complete and SPI are metrics every task has, and a band headed FLAGS that delivers a routine number teaches the reader to skip it, so a genuine exception later will not read as one. Critical-path membership and a missing committed start are deliberately **not** flags here — the Schedule strip carries its own critical banner and the row chip is the primary point-of-fix for an uncommitted start (rule 276), so either would be a third copy. (d) **Float keeps the `computed` qualifier treatment** (rule 276) in the Schedule grid so it never reads as editable, and **negative float turns the cell critical** as well as raising the flag. Reference: `features/schedule/{TaskSummaryStrip,TaskFlagsSection,TaskScheduleStrip}.tsx`.
