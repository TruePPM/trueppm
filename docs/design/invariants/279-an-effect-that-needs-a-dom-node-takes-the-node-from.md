# Rule 279 — An effect that needs a DOM node takes the node from `useElementRef` and lists it as a dependency — never …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**An effect that needs a DOM node takes the node from `useElementRef` and lists it as a dependency — never `someRef.current` read inside an effect that cannot re-run when the node mounts (#2365).** A `RefObject`'s identity never changes and mutating `.current` does not re-render, so the ubiquitous shape `useEffect(() => { const el = ref.current; if (!el) return; el.addEventListener(…) }, [])` is **silently dead** whenever the node mounts after the first commit — which is the normal case on any surface that returns a loading skeleton or an error state before its real container (rules 246/248): the first commit renders the skeleton, the effect runs against `null`, bails, and never runs again. Use `const { el, setEl } = useElementRef<HTMLDivElement>()` (`hooks/useElementRef.ts`), attach `ref={setEl}`, and key the effect on `[el]`; a hook that owns such an effect exposes a **callback ref** (`setScrollEl`) plus the node (`scrollEl`) in its public API rather than a `RefObject`, so a consumer cannot reintroduce the bug, and any sibling hook that measures the same container takes `HTMLElement | null` rather than a ref. Three consequences: (a) `setEl` sets state, so it must only be called the way React calls a callback ref — after commit, never during render; (b) the effect's cleanup now genuinely runs when the node is swapped, so listeners/observers rebind correctly instead of leaking onto a detached node; (c) **a unit test must mount the container after the first commit** — the pre-#2365 tests passed a hand-built `{ current: el }` or assigned `ref.current` in the render body, which pre-seeds the very state the bug depends on and is why three broken hooks tested green. This bug class presents as e2e flake (it races query-cache warmth), so a spec covering such a surface should force the cold path with the `delayRoute` fixture (`e2e/fixtures/cold-load.ts`) rather than leave the ordering to chance. Reference: `hooks/{useElementRef.ts,useSpaceDragPan.ts,useHasScrollBelow.ts,useHasScrollRight.ts}`, `e2e/fixtures/cold-load.ts`, `e2e/board-space-pan.spec.ts`.
