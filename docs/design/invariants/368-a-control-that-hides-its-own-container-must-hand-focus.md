# Rule 368 — A control that hides its own container must hand focus somewhere BEFORE the unmount, and the right somewhere …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A control that hides its own container must hand focus somewhere BEFORE the unmount, and the right somewhere is the control that undoes the act.** The Schedule's how-to bar dismiss button called `toggleDisplayOption('coach')`, which unmounted the container the focused button lived in — so focus fell to `<body>` and a keyboard user lost their place entirely (WCAG 2.4.3 Focus Order, 2.4.7 Focus Visible; T10/T11 of #3134). Four parts. **(a) The destination is not a generic fallback.** This button's label already read *"Hide the how-to bar — bring it back from Display options"*, so focus belongs on the **Display** trigger: moving it there makes the sentence the control already makes true for a keyboard user instead of only for someone who can see the toolbar. When a dismiss names its undo, that name is the spec for where focus goes. **(b) Move focus SYNCHRONOUSLY in the handler, before React commits.** Calling `.focus()` right after the state setter moves focus out while the bar is still mounted, so the unmount has no focused descendant to orphan. Deferring to an effect or `requestAnimationFrame` blurs first and lands second — a visible flicker and a real gap for anything listening on `focusout`. **(c) Reaching a sibling's control means owning the ref at the common parent.** `ScheduleDisplayMenu` kept `triggerRef` internal and still needs it (it restores focus there on close), so the fix is an optional `triggerRef` prop merged via a **callback ref** — an element takes one `ref`, so two owners means one callback assigning both — threaded `ScheduleView` → `ScheduleToolbar` → menu. Optional because every other caller (the print layout) needs nothing. **(d) A dismiss/restore test that calls `.focus()` on the restoring control proves nothing about this.** The sibling round-trip test did exactly that, so it passed throughout the defect: it asserts the door opens, never where the user was standing when it did. Assert `toBeFocused()` on the destination immediately after the dismiss, with no intervening `Tab` or `.focus()`, and scope the locator through the toolbar — `name` is a substring match and the dismiss control itself says "Display options" while the bar is up. Reference: `features/schedule/ScheduleView.tsx` (`onDismiss`), `features/schedule/ScheduleDisplayMenu.tsx`, `e2e/schedule-teaching-surfaces.spec.ts` — #3134. **(e) When the destination does not exist yet, the move is an EFFECT on the following commit — and it needs a guard (b) never did.** The Grid's `ConfirmDeleteStrip` is the shape (a) and (b) do not cover: the control that undoes the act is the bulk **Delete** button, and that button is only rendered once `deletePhase` is back to `'idle'`, i.e. on the very commit that unmounts the strip. There is nothing to `.focus()` synchronously, so the handler sets a ref and a `useEffect` keyed on the phase performs the move once the destination's ref is populated. Two things follow. **The ref lives at the common parent even though the two elements are in the same component** — `Toolbar` returns either the confirm row or the idle row, never both, so `GridView` owns both refs and threads them down (still (c), just with the sibling relationship hidden inside one function). And **an effect-time move can arrive after the user has gone somewhere else, which (b) makes impossible by construction** — a dwell that expires while focus is parked outside the strip must not yank it back, that is an unrequested context change (WCAG 3.2). So the move is armed only when the focus being orphaned is the surface's own or already lost to `<body>`, checked at handler time against the container's ref, and the guard needs its own test or the fix trades 2.4.3 for 3.2. Route **every** exit through the one handler — the Grid had three (dwell, Cancel, Escape) and wiring two of them is the likely outcome of fixing only the one in the bug report. Reference: `features/grid/GridView.tsx` (`handleCancelDelete`), `features/grid/ConfirmDeleteStrip.tsx` — #3445.
