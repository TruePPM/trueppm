# Rule 225 — An `aria-invalid` field must gate its form's primary action — the submit/primary button's enabled state …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**An `aria-invalid` field must gate its form's primary action — the submit/primary button's enabled state derives from that validity AND the submit handler re-guards it; never leave the primary action live while showing an error, and never let it commit a stale/previous value the user did not type.** The trap is an input whose parse only *updates* the committed value on success (`if (parsed !== null) setValue(parsed)`): on invalid text the field shows red + `role="alert"`, but the underlying value silently keeps its last valid figure, so a primary button whose `disabled`/`canX` predicate omits the invalid flag stays enabled — and Enter or a click logs the previous value the error is actively warning against. Compute the invalid flag before the enabled predicate, fold it into both the predicate and the submit-handler early-return, so an `aria-invalid={x}` field always has its `x` term reflected in what commits. Reference: the quick-log manual-duration input in `features/timeentry/QuickLogTime.tsx` (#1416, ADR-0185 §C) — `manualInvalid` gates both `canLog` and `handleSubmit`, so a half-typed "abc" disables Log rather than logging the prior 1h.
