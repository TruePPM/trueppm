# Rule 392 — A consent, warning, or write-lock predicate computed from a secondary TanStack Query list must not read that …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Placeholders and operator surfaces*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A consent, warning, or write-lock predicate computed from a secondary TanStack Query list must not read that list's loading/failed default as a verdict — `[]`/`0`/`undefined` while unresolved is "unknown", never "nothing to guard against".** The class (#3313, then four more members in #3424): a guard such as `willOrphanSprints = sprints.length > 0`, `sprintClosed = sprints.find(id)?.state === 'COMPLETED'`, `pointsReadOnly = selectedSprint?.state === 'ACTIVE'`, or `if (items.length === 0) return null` is fed by a hook that returns `query.data ?? []`, so for as long as the query is in flight — and forever after it fails — the guard evaluates exactly as it would on a project with genuinely nothing to protect, and is skipped on timing alone. The tell is a consumer that destructures only the data (`const { sprints } = useSprints(id)`) and drops `isLoading` / `error`: it structurally cannot tell empty from unknown. It was the board's closed-sprint write-lock, the committed-points freeze, the cross-project consent banner, the delete confirm's blast radius, and the sprint scope-review panel's \"nothing pending\" all-clear, all at once, and two of them sat in the same file (`TaskFormModal`) as a hydration guard (#354) that already knew the fix. **The fix shape, and it follows rule 379:** derive an explicit `…Unknown` boolean from `isLoading || error != null` *scoped to the case where the guard actually has something to look up* (a `?sprint=` param, a task with a `sprintId` — Project view and a sprint-less task are never unknown), then apply the two polarities separately. A **withheld affordance** (the board lock, the points freeze) engages on unknown exactly as on the positive verdict — `boardReadOnly(role, sprintClosed, sprintStateUnknown)` takes both inputs rather than folding them, so the third argument cannot be dropped silently. A **disclosure** (the closed-sprint banner, the review banner's count) stays silent on unknown and renders only the positive verdict — but a *terminal failure* on the only entry point to a decision is not silence, it is a false all-clear: render the failure (`Couldn't check for …` + Retry, same footprint as the banner it replaces, rule 246) and never auto-close a review on an empty list unless `!isLoading && error == null`. A **count** the copy quantifies goes `number | null`, and the copy says `(count unavailable)` rather than dropping the clause (`describeBlastRadius`). Two things that are **not** unknown and must not be folded in: a list that resolved and simply lacks the id (the sprint is off the first page — a different gap, not a race), and a refetch that failed while TanStack kept the last good data (`items` still answers; only failure-with-nothing-cached is the error state). **Decision recorded (#3424): this class gets a rule, not a mechanical guard.** A lint on "destructures a list from a query hook without `isLoading`/`error`" over-fires on the many display-only consumers where empty-during-load is the correct render (`ReportsView`, `GroupedMode`, `CalendarView`, `BoardCardPopover`, every drawer section) — which predicates *gate a write or a consent* is semantic, not syntactic. A hook-side discriminated `status` instead of `?? []` would force every one of those ~25 display consumers to unwrap it for no behavior change, and the hooks already expose `isLoading` / `error` — the defect is a consumer dropping them, which a richer return type does not prevent. So: when you write a predicate that *withholds, warns, or asks consent* from a secondary list, read its status; pin the unknown case in the test beside the positive one (loading → locked; failed → locked; resolved-open → editable; resolved-missing → editable), and cover the polarity pair in one test so a "make these consistent" refactor has to confront it. Reference: `features/board/boardView/useBoardSprintScope.ts` + `useBoardIdentity.ts` (`boardReadOnly`), `features/board/TaskFormModal/index.tsx` (`pointsReadOnly`, `deleteBlastRadius`), `features/board/TaskFormModal/DeleteConfirmDialog.tsx` (`describeBlastRadius`), `features/schedule/PendingCrossProjectReview.tsx`, `features/sprints/ScopePendingReviewPanel.tsx` (found by the #3424 sweep, not by the issue — the fifth member), `features/settings/project/ProjectMethodologyPage.tsx` (#3313) — #3424.
