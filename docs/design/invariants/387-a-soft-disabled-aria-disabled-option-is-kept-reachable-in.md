# Rule 387 — A soft-disabled (`aria-disabled`) option is kept reachable in order to be *read* — so style it readable

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Placeholders and operator surfaces*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A soft-disabled (`aria-disabled`) option is kept reachable in order to be *read* — so style it readable.** Rule 122 governs a genuinely `disabled` control and rule 169 reserves `neutral-text-disabled` for affordances whose low contrast *is* the "you can't use this" signal. Neither reaches the third state: an option left in the roving order, stating its own zero, because **"I checked, and none" is a different sentence from "this control is missing"** — and a `disabled` button says neither, because nothing can reach it to hear it. That option's text is its entire purpose, so it takes **no opacity multiplier** (`opacity-60` on `neutral-text-secondary` composites to under 3:1 and fails WCAG 1.4.3 at 12px) and no `neutral-text-disabled` either, which rule 87 already prohibits on `bg-neutral-surface-sunken` — the surface segmented controls sit on. Carry the inert state on the **interaction** instead: `cursor-not-allowed`, the `aria-disabled` attribute, the zero folded into the accessible name, and **no hover recolor** — an inert option that lights up under the pointer and then no-ops on click is an affordance lie. Reference: `features/programs/MethodologyFilter.tsx` — #3295.
