# Rule 328 — A control's EXISTENCE must never be a side effect of a neighbour's visibility — and a fact stated only in a …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A control's EXISTENCE must never be a side effect of a neighbour's visibility — and a fact stated only in a `title` or an `aria-label` is not stated.** Two defects in one row of the Schedule outline, both of which defeat the sentence their feature was built from, and both invisible to every test that shipped with them. **(a) Nesting is coupling.** The ⇤/⇥ structural nudges were placed at the WBS number because the design's reason for having on-row structure buttons at all is that *restructuring must not be keyboard-only knowledge* — and they were implemented as children of the WBS `gridcell`, which renders `visible.wbs && …`. So a Display ▸ Columns preference that has nothing to do with restructuring deleted both controls from every row and left right-click as the only pointer route (#3026). Nothing 403'd, nothing threw, and no test failed, because every one of them rendered the row with the default column set. The fix is structural, not a guard: a control whose reason to exist is independent of a column gets its **own lane**, reserved panel-level like the ⋮⋮ grip's (`resolveOutlineNudgeReserve`), so the header, every row, the pending rows and the draft row hold the same width and no column choice can reach it. Two constraints ride along — the lane goes where the design put the control (immediately left of the WBS number, so the depth is still stated beside the thing that changes it) and **never rightward toward delete**, because a structural nudge and a destructive act must not be neighbours (rule 309 / #2956). The general form: *before nesting a control inside a cell, ask what happens when that cell is not rendered* — and if the answer is "the control is gone", it does not live there. **(b) An attribute is not a statement.** The same row's fold caret carried `4 inside` / `4 hidden` in a `title` and an `aria-label`, and drew neither, so a sighted user had to hover and wait out the tooltip delay to learn whether a collapsed phase contained anything — an interaction unavailable on touch, on the surface #2997 had just made a first-class touch target, and the exact opposite of the "containment survives a fast visual scan" premise the feature exists to serve (#3025). Every unit assertion passed, because they all read the attribute. **Assert rendered text and `toBeVisible()`**, never `toHaveAttribute` alone, for anything the design says the row *states*. Two corollaries. **A fact with three phrasings has no owner**: the caret said "inside/hidden", the live region said "N children visible", and the row said nothing — so derive the phrase once (`containmentCount.ts`) and import it into the visible chip, the accessible name and the announcement, which is rule 316 applied to a noun instead of a sentence. And **the visible copy is `aria-hidden`**: the control's accessible name already carries it, and announcing it twice makes a 40-row plan read as 80 facts (rule 309(b)). Corollary for the coarse-pointer half: a target that does not grow is a target that was never sized — the nudges were hard-coded `w-4 h-4` and stayed 16px inside a 44px row; resolve the size from the row-height owner (`NUDGE_SIZE_COARSE = ROW_HEIGHT_COARSE`, rule 315) so the control is as tall as its row by construction rather than by coincidence, and pay the honest width for a *pair* of 44px targets rather than letting one cover the other. **A 328(b) fix is not done until its siblings are swept.** The caret's containment count and the Owner column's allocation percentage were the *same* `title`-only defect one column apart, and fixing the caret did not surface the Owner cell — it took a separate issue five weeks later (#3154), where the units sat in a `title` while the gridcell's name listed bare assignee names. When you take an attribute-only fact and make it a stated one, grep the surrounding surface for the rest of them (`title=`, and any `aria-label` that lists entities without their values) and fix the class, not the instance. Two things the Owner column added to the pattern. **The column will not fit the fact, and that does not license shrinking the type**: the run of percentages exceeds a 72px cell at two assignees, and the fix is `truncate` — a clipped run with an ellipsis reads as *incomplete*, where a silently shortened one reads as a different, wrong number (the Links cell settled this in #3023) — never `text-[10px]`, which is a `features/settings` dispensation (rule 118) and which the `lint:design-system-v2` gate rejects against the rule 50 type floor. **And the derivation has to bottom out on the value, not on a string**: `chipTitle` (`Alice Chen (50%)`) and the visible run (`100/50%`) are different *spellings*, so making one call the other forces a `.replace('%','')`; the owner is `unitsPercent(units) → number`, and both spellings derive from it. **`SkillChip` is what the sweep clause is for, and it shows the sweep has to follow the COMPONENT, not the file.** #3154 fixed two cells of one Schedule row and the class's next instance was a shared chip in `features/roster/` rendered by four surfaces, so a sweep scoped to the surrounding file was structurally incapable of reaching it — it took #3200. When the attribute-only fact lives in a component, grep its importers, not its neighbours. Three more things this instance added. **(c) When the hidden fact is a MODIFIER of the visible one, `aria-label` is the wrong tool.** The caret and the Owner cell synthesized a whole name, so a label was right there; here the chip already states its subject as text (`HVAC`) and the missing fact qualifies it, so a label would REPLACE the subject and announce "Expert" with no skill — the fix is an `sr-only` **completion** in the same element, and the unit test pins the mechanism (`not.toHaveAttribute('aria-label')`) and not just the resulting string. **(d) The completion's separator is load-bearing, and the two accessible-name engines disagree about it — so never assert the same spelling in both test layers.** Name-from-content concatenates each child's contribution, and jsdom's `dom-accessibility-api` (vitest) **trims each contribution's leading whitespace** while Playwright's inserts a **space between** them. So an ` — Expert` completion arrives as `HVAC— Expert` under vitest, which is a second, wrong spelling of the fact the `title` already owns — use a separator that needs no leading space (`, Expert`). Even then the two engines land on `HVAC, Expert` and `HVAC , Expert` respectively; both are inaudible and neither is a defect, so **assert the exact string in vitest and a `\s*`-tolerant regex in Playwright**. Pinning one spelling in both reds on the other engine, and it reds at *runtime*, where `tsc` cannot see it. **(e) Most `title=` a sweep turns up are NOT defects — say so out loud rather than churning them.** Three shapes are legitimate and recur across `features/roster/`, `features/resources/` and the picker: a **truncation-recovery** title whose text is the clipped visible text (`ResourceAssignmentsSection`'s project and task names), a **pointer expansion of a value that is already visible and already in the accessible name** (`{a.units}×` + `title="2 allocation units"`, with the row `Link`'s own label carrying it), and the derived-phrase title kept as convenience once the fact is stated elsewhere — which is what `SkillChip`'s became. The class is *only* a fact drawn nowhere at rest. **And the fix is not always "draw the word".** `RosterDetailPanel` already renders `PROFICIENCY_LABEL` as visible text at one-skill-per-row density; the chip is precisely where it does not fit (four chips plus two `Missing:` chips share one option row in a drawer-width dropdown, and `Intermediate` is longer than most skill names), so the dots stay the visual channel and the word goes to the name.
