# Rule 391 — A flag fixed at navigation time cannot carry a status the server writes LATER — route the job's id, not a …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A flag fixed at navigation time cannot carry a status the server writes LATER — route the job's id, not a boolean about it, or the destination can never learn how the job ended.** `createdProjectDestination` sent an AGILE template apply to `/product-backlog?seeding=1` while sending the same apply, for any other methodology, to `/schedule?templateApplication=<id>`. The two looked like the same contract in two spellings; they were not. The Schedule polled the application and could therefore show `pending` as a skeleton, `success` as a banner, and (after #3348) `failed` as a stated failure. The backlog held a boolean that was true the instant the 202 came back and had no way to change — so it rendered the identical skeleton for "still writing" and "failed in the worker" and told them apart with a 10s clock, then fell through to the ordinary empty CTA saying nothing either way. **No component change could fix this** — `ProductBacklogPage` had no id to poll — which is why #3348's banner could not simply be ported and the repair had to start in the route (#3422). Three tells that a boolean is standing in for a status: **(a)** the destination has a timer as its *primary* exit rather than its last-resort one (rule 374(a)); **(b)** the sibling surface for the same job carries an id where this one carries a flag; **(c)** a terminal state of the job has no component reading it, and the only place that could have said so is the toast that fired on a *different* page before navigation. When the flag's job is a server-side row with a status, the flag is retired, not kept "for the no-id case" — a skeleton with no job behind it can only ever time out, and a state whose only exit is a timer is the thing rule 374 exists to prevent. The no-id case (dispatch refused) lands on the surface's genuine empty state, which is the honest one. Reference: `features/shell/createdProjectDestination.ts`, `features/project/backlog/hooks/useBacklogSeed.ts` — #3422, sibling of #3348 and the fulfilment of ADR-0800's deferred Alternative D.
