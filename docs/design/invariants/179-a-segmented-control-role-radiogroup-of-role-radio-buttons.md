# Rule 179 — A segmented control (`role="radiogroup"` of `role="radio"` buttons) must fill the active segment with a token …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Controls and composition*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A segmented control (`role="radiogroup"` of `role="radio"` buttons) must fill the active segment with a token that contrasts against its container surface — never the same surface token the control sits on — and selection is conveyed by fill, not text color alone.** Active = `bg-brand-primary text-neutral-text-inverse`; inactive = `bg-neutral-surface text-neutral-text-secondary hover:bg-neutral-surface-raised` (visually distinct from the active fill). The failure this prevents: a toolbar segmented control filling the active segment with `bg-neutral-surface-raised` while sitting *on* a `surface-raised` toolbar renders zero fill contrast, leaving text shade as the only selection signal (WCAG 1.4.1). Roving tabindex (`tabIndex={selected ? 0 : -1}`), Arrow (wrapping) + Home/End key handling **bound to the focusable radios** (not the non-focusable group, per `jsx-a11y/interactive-supports-focus`), and the rule-4 focus ring (no dark-mode override — `brand-primary` is mode-aware sage, rules 4/137; the old `dark:focus-visible:ring-semantic-on-track` override is **retired**, do not reintroduce it) are mandatory; the selection commits immediately on move. Reference implementations: `features/schedule/ScheduleToolbarToggle.tsx` (single pressed/unpressed) and `features/schedule/ScheduleViewModeToggle.tsx` (multi-option Grid↔Timeline). Pattern also in use: `RetentionPurgePage`, `CalmToolbar`.
