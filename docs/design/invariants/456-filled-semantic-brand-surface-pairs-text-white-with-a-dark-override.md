# Rule 456 — A filled semantic/brand surface that sets `text-white` carries a `dark:text-*` override

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Color and tokens*. The index carries the rule's headline; this file carries its full text (#4669). Binding everywhere, not only on the surface that produced it.

**A solid `bg-semantic-*` or `bg-brand-*` fill that sets a base-state `text-white` must also set a `dark:text-*` class — `dark:text-navy-900`, as `Button` does — or the surface must be a `<Button>`.** In dark mode the semantic and brand fills flip to LIGHT tones (critical `#F87171`, brand `#66B998`, at-risk `#FB923C`), so white text on them measures 2.3–2.8:1, under WCAG 1.4.3's 4.5:1. `Button` has carried `text-white dark:text-navy-900` since #2196, but ~30 hand-rolled buttons (Delete workspace, Archive, Purge) never did, and the same shape (`bg-brand-primary text-white`) had already been swept once under #2041 and recurred, because nothing enforced it. Prefer `<Button variant="danger">` for a hand-rolled destructive button. A static fill that does not flip (`bg-brand-accent`, `#E8A020`) is wrong in BOTH themes with white text (2.3:1 on light too) — use `text-navy-900` outright, as `RiskMatrixCell` does.

Machine-checked: `scripts/check-dark-text-white.py` (`make dark-text-white-check`, CI `lint:dark-text-white`, part of `make pre-push`). It reads the class list around each `text-white` (the nearest quote on each side, so a class list wrapped across lines is covered and an apostrophe elsewhere in the file cannot desync it). Known blind spot: a fill and its `text-white` in two different literals of one expression. A deliberate exception carries `dark-text-ok: <reason>` within three lines above.
