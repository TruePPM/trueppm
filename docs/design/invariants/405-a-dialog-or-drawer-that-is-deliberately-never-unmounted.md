# Rule 405 — A dialog or drawer that is deliberately never unmounted must leave the accessibility tree AND the tab order …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Signal encoding*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A dialog or drawer that is deliberately never unmounted must leave the accessibility tree AND the tab order when closed — `aria-hidden={!isOpen}` plus `invisible pointer-events-none`, never one without the other.** A shell kept mounted to preserve state across close — the Schedule `TaskDetailDrawer`'s `renderedTask` dirty-swap rescue latch (#1978) — is mounted on the ROUTE, not on the selection, so a `role="dialog"` whose `aria-label` is the empty string sits on every visit to that route (#3545). Two consequences, both load-bearing. **(a) `aria-hidden` alone is worse than the bug it fixes**: it hides the shell from assistive tech while leaving every focusable descendant (Close, the tab strip, the name field) in the tab order — a hidden keyboard trap. `invisible` is what removes them, because `visibility: hidden` is inherited and un-focusable; `translate-*-full` is not enough, an offscreen element is still focusable. **(b) Every `getByRole('dialog')` absence assertion on that route is vacuous until this is fixed** — web-first assertions pass on their FIRST satisfying sample, so `toHaveCount(0)` passes by sampling before the host renders and reports success for the wrong reason, then starts failing the moment the page renders promptly. Two further obligations: restore focus BEFORE flipping `isOpen` (see `closeAndReset`), or `aria-hidden` lands on an ancestor of the focused element; and put `visibility` in the transition property list (`transition-[transform,visibility]`), because it is not covered by `transition-transform` and without it the closing slide is dropped — the drawer vanishes at frame 0 instead of sliding out. Prefer this pair over `inert`, for consistency with `MonteCarloDetailPanel.tsx` and `ResourceOverallocationDrawer.tsx` which already use it. Reference: `features/schedule/TaskDetailDrawer.tsx` — #3545, surfaced by `ux-review`.
