# Rule 291 — A "the baseline is already on screen" predicate must also be checked against whether the *derived value* is …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A "the baseline is already on screen" predicate must also be checked against whether the *derived value* is already on screen — the component that supplies the baseline is usually printing the delta too (#2531).** Rule 284 says a value renders once per surface; this is its inverse, and it is the harder one to see. When a chip or strip decides it may print a bare signed delta *because* some other component supplies the reference point, that reference-supplying component is almost always the same one that already computed and printed the delta — so the predicate that unlocks the terse form is the same fact that makes the whole fragment redundant. The reference failure: added time's `BASELINE_ON_SCREEN_VIEWS = {'schedule'}` qualified Schedule because `ScheduleForecastBar` renders a dashed `CPM: Oct 24` chip, but the chip *beside* it already reads `P80: Nov 4 (+11d)` — from the same `delta_vs_cpm` the premium is derived from — so the one place a bare number was legible was the one place it was already printed, twice on screen at once with nothing marking either as authoritative. Three obligations: (a) **grep the baseline-supplying component for the derived value, not just for the baseline date**, before adding a route to a baseline-on-screen set; (b) when the grep finds it, the correct outcome is to **suppress the new fragment on that route** — not to add a qualifier, and not to suppress the older, page-level rendering, which is the one the user came to that page for; (c) a *popover or drawer* row is not a second render in this sense and may stay, because it is behind a deliberate click and is usually the only carrier of the operational states (`needs estimates`, a stamped stale read) that the page-level rendering structurally cannot express. Corollary: when two surfaces print one server field they must also share **one formatter** — `useForecastPresentation.deltaLabel` emits ASCII `-4d` while `addedTime.deltaLabel` emits U+2212 `−4d`, which is invisible until something puts them in the same row. Reference: `features/shell/addedTimeChip.ts`, `features/schedule/{useForecastPresentation,MobileMonteCarloCard}.tsx`.
