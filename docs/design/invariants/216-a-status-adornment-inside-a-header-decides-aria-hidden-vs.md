# Rule 216 — A status adornment inside a header decides `aria-hidden` vs `role="img"`+`aria-label` by whether its meaning …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Signal encoding*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A status adornment inside a header decides `aria-hidden` vs `role="img"`+`aria-label` by whether its meaning is ALREADY in the header's accessible name — never by "it's a small glyph, hide it".** A header (a board column `<h2>`, a card title, a lane label) that already folds a state into its own `aria-label` — e.g. the column name computed as `` `${label}, ${count} tasks, over limit` `` — must render the *visual* chip for that same state as `aria-hidden` so a screen reader hears it once, not twice (the `WipBreachChip` case, ADR-0130 D2). But an adornment that carries **net-new information not present in the accessible name** must be an announced element (`role="img"` with an `aria-label`, plus a `title` mirroring it), or it silently vanishes for AT users. The `WipTrendArrow` (#1213) is the second case: the recent-trend direction is nowhere in the column's `<h2>` name, so it is `role="img" aria-label="trending up toward WIP limit"` with the visible ▲/▼ glyph `aria-hidden` inside it. Before adding a header glyph, check the header's computed `aria-label`: if the state is in there, `aria-hidden` the glyph; if not, label the glyph. Do NOT make a net-new-info glyph `aria-hidden` (drops it for AT) and do NOT label a redundant glyph (double announce). Direction/trend meaning must also survive color loss (rule: color-not-alone) — the glyph orientation carries it, amber (`text-semantic-at-risk`, AA-as-foreground per the token) marks only the actionable "about to breach" case, everything else is `text-neutral-text-secondary`. Reference: `WipTrendArrow` (labeled, net-new) vs `WipBreachChip` (aria-hidden, redundant) in `features/board/BoardView.tsx`.
