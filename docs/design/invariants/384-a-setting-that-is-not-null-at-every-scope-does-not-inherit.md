# Rule 384 — A setting that is NOT-NULL at every scope does NOT inherit — it SEEDS — and the copy saying so has to be …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A setting that is NOT-NULL at every scope does NOT inherit — it SEEDS — and the copy saying so has to be swept across every scope in the same commit, because the false sentence is written once per surface and each one reads as authoritative alone.** `Project.methodology` and `Program.methodology` are both `CharField(default=…)` with no null sentinel, so under the default `suggest` policy each scope's own value always wins and `resolve_inherited_methodology` can only ever describe what a *new* child would start from. Copy of the shape "Each X inherits the Y unless overridden" is therefore false at **every** level of that chain, and fixing only the instance a bug report names ships a product that contradicts itself one click away — #3293 named two strings, and a sweep found the same claim on the program Projects subtitle (the destination the corrected hint routes to), the workspace Programs subtitle, and its policy-column description. Three obligations. **(a) Grep the claim SHAPE, not the string you were handed** — `grep -rniE "inherits? the (program|workspace)" packages/web/src/features/settings/` — and fix every hit in the same commit, including the surface your new copy points at. **(b) Distinguish the two mechanisms in the words, using the register already shipped rather than a third one.** A nullable override with a server resolver genuinely inherits live and takes `InheritableSelectField`'s "Inherit (X)" / `inheritFromLabel`; a NOT-NULL column is seeded at create and takes `WorkspaceMethodologyPage`'s "new … start with" / "pre-fill". Never explain the difference in implementation terms — "it is a seed, not a live default" is a column nullability and means nothing to a PM. And name the destination precisely: a program has two surfaces called **Projects** and only the settings one can change an existing project. **(c) When a control shows a PARENT's value, the scope noun follows the RELATIONSHIP, not a value comparison.** `inherited_methodology` resolves program → workspace and the program tier is non-null, so membership alone decides the scope — comparing the two values instead misnames it every time a program happens to agree with the workspace. The corollary is `feedback_null_meaning_two_things_needs_a_discriminator`: a banner that renders byte-identically whether the child matches the parent or diverges is not answering the question its placement implies, and the divergent case is exactly the one the user is there about. Reference: `features/settings/project/ProjectMethodologyPage.tsx`, `features/settings/program/ProgramGeneralPage.tsx`, `features/settings/workspace/WorkspaceProgramsPage.tsx`, `apps/projects/methodology.py` — #3293 (the project banner's own divergence wording and `lib/methodologyLabel.ts` are the two survivors, left to #2619 §3).
