# Rule 410 — A value read from an async query that SEEDS a mount-frozen draft must be gated on that query RESOLVING — …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Signal encoding*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A value read from an async query that SEEDS a mount-frozen draft must be gated on that query RESOLVING — every other consumer of the same value self-corrects on re-render, and that is exactly what hides the one that cannot.** `useDirtyDraft` captures its baseline once at mount and deliberately never resyncs (so a server-side update to the same record cannot clobber an in-progress edit), while sibling reads of the same value — a field's label, an option list's order, a picker's scale — recompute on every render. Feed one unresolved value into both and they *diverge* the instant it arrives: `DetailCreate` seeds `itemType` from `defaultItemType(methodology)` and also derives `pointsLabel` and `typeOptions` from it, so a program query landing after mount reorders the Type dropdown to lead with **Task** and relabels the estimate field to **Estimate** while the selected value stays **Story** — and the form then POSTs `item_type: 'story'` into a Waterfall program (#3644). **This is worse than an ordinary stale render, because the visible surface corrects itself and the persisted value does not** — the screen looks right and the database is wrong, so there is no symptom to report. Three obligations. **(a) Identify which consumers of an async value are FROZEN** — anything passed as a hook's `initial`/seed argument, a `useState(() => …)` initializer, a `defaultValue`, or a `key`-less remount seed — and gate the component's **mount** on that query rather than gating each field. A per-field re-seed (`commitField`) is second-best and has its own trap: it must run only while the draft is pristine, or it silently discards a real edit. **(b) The page's own `isLoading` is not automatically the right gate — read what it actually derives from.** `useBacklogController` exposed `isLoading: itemsQuery.isLoading` and `errorKind` from that one query, so the program query had neither a loading gate nor an error surface: a failed `GET /programs/{id}/` left `resolveMethodology(undefined) → 'HYBRID'` standing forever, rendering every Waterfall program as Hybrid with nothing anywhere saying so. A gate named for the page is usually a gate for one of its queries. **(c) A fallback that returns one of the domain's REAL values is a positive claim, not a default.** This is rule 379(e) reaching a case rule 379 itself waves through as "merely selecting a noun": selecting a noun is safe, and selecting a noun *and* a persisted enum from the same helper is not. Split them — the label may fall back, the seed must wait. **Test by RERENDER, not by prop**: a spec that only ever passes a settled value passes on the broken build, so render with the fallback, rerender with the real value, and assert what the seeded field did. Reference: `features/programs/backlog/components/DetailCreate.tsx` (`emptyDraft`), `features/programs/backlog/methodologyVocabulary.ts` (`resolveMethodology`), `components/dialog/useDirtyDraft.ts` (the "captured once at mount" contract), `features/programs/backlog/hooks/useBacklogController.ts` — #3644, surfaced by `ux-review`, extending rule 379(e).
