# Rule 361 — A control that is inert *by design for a named release* is not rule 122's incidental placeholder — it takes …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A control that is inert *by design for a named release* is not rule 122's incidental placeholder — it takes an at-rest sentence, a version badge, `aria-disabled`, and an explicit `aria-label`; never a `title`, and never `disabled`.** Rule 122's `title` clause assumes a control whose unavailability is incidental. When the control is present specifically so the surface's geometry does not move when the capability ships, `title` is the wrong carrier: it is hover-only, so it is unreachable by keyboard and by touch — the same objection rule 121 raises against tooltip-borne upgrade links. Five parts, and each replaces something that looks sufficient on its own. **(a) An at-rest sentence in the group** naming what is inert and when it ships, in **future tense**, with the version checked against `overview/roadmap.md` — a visibly dead control with no explanation is worse than an absent one. **(b) A version badge on the arm itself**, at `text-xs`: rule 50's floor is *not* waived here and rule 118's compact density is `features/settings/`-scoped, so `text-[10px]` reds the DS-v2 gate on any surface outside settings. **(c) `aria-disabled`, never `disabled`** — `disabled` strips the tab stop and the accessible name, which moves the refusal from the moment of the attempt to a silent nothing at commit time. Keep it inert with `onClick={(e) => { e.preventDefault(); … }}`; a prevented click on a radio/checkbox never fires `change`, so wire the refusal to the **click**, not to `onChange`. **(d) An explicit `aria-label` carrying the whole name** (`"Remove — ships in 0.5"`). A bare version number inside the `<label>` lands in the control's accessible name as an uninterpretable value, and an `sr-only` carrier phrase beside it does **not** fix that: the accname computation *trims each text node before joining*, so `Remove` + `ships in 0.5` announces as `"Removeships in 0.5"`. One attribute states the name; sibling nodes cannot. **(e) The refusal's `role="status"` region is mounted unconditionally** with only its text swapped (rule 335) — a live region inserted together with its own content is announced inconsistently across AT, and for a screen-reader user that announcement *is* the refusal. Lock the roster and its order in a unit test, so "landing the capability deletes a badge and a predicate" is checkable rather than asserted.
