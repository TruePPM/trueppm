# Rule 396 — A `<select>` whose `value` can fall outside its rendered `<option>` set does not fail — it silently paints …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Signal encoding*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A `<select>` whose `value` can fall outside its rendered `<option>` set does not fail — it silently paints the FIRST option, so the control states a fact the record does not hold.** A native select has no "no match" state: `<select value={250}>` over options `[1, 100, 200, 300]` renders as "Viewer", so a member holding a role this client cannot name is displayed as holding the *lowest* one, and the manager's next change then commits from a false baseline — a write nobody intended, off a reading nobody questioned. It is invisible to every test that supplies an in-range value, and `tsc` is no help because the value's *type* is right. The shape recurs wherever a picker's option set is a **subset** of a server-owned value space: role ordinals in ADR-0072's Enterprise-reserved bands (2–99 / 101–199 / 201–299 / 301–399), a status vocabulary the server may extend, a methodology token, a currency, a calendar id. Two obligations. **(a) The control renders the read-only representation, or an explicit `disabled` `<option>` carrying the actual value as the selected entry** — never the bare grantable set. Prefer the disabled option where the capability should survive: the value stays legible, cannot be silently re-baselined, and cannot be re-granted, which is the honest answer when the client does not know what that value means. **(b) Assert the SELECTED option, not that the component mounted** — `sel.value`, `sel.selectedOptions[0].textContent` and its `disabled` state, with an in-range case beside it proving the extra option appears only when it should. `getByRole('combobox')` resolves against the defect, and so does every assertion about the option *list*, because the list is correct; only the selection is wrong. **This is rule 301's "the unknown branch degrades, it does not lie" reaching a control's stated CURRENT VALUE rather than a tone map — and the two halves ship apart.** #3476 built `roleLabel(role, scope, serverLabel)` so an unrecognized ordinal falls back to the server's own name for the read-only badge, documented the reasoning at length, and left the picker beside it painting "Viewer" for the same ordinal: a fallback contract implemented on the read half only. So when you add a degrade-honestly fallback for a value, ask in the same change which *controls* also render it. **The sweep and its denominator, because the second instance was on a different enum and would not have been found by grepping the first:** five selects in `packages/web` bind a role value — the three `RolePicker` call sites that render a *membership* (fixed via the component, so all three at once), `WorkspaceMembersPage`'s row select (a **separate** `WorkspaceRole` enum with only Member/Admin/Owner and the same reserved bands — fixed the same way, with the server's own `role` string as the fallback name), and two whose value is client-owned state seeded from the option list itself (`GroupManageDrawer`'s grant select, `WorkspaceMembersPage`'s invite select), which are in-set by construction and carry a comment saying so. Sweep by asking *which selects bind a server value*, not by grepping the vocabulary you just fixed. Reference: `features/settings/members/RolePicker.tsx` (`isUngrantable`), `features/settings/workspace/WorkspaceMembersPage.tsx` (`renderRoleOptions`), `lib/roleLabels.ts` (`roleLabel`), `features/settings/members/RolePicker.test.tsx`, `features/settings/workspace/WorkspaceMembersPage.test.tsx` — #3476, surfaced by `ux-review` and its sweep by `regression-check`, extending rule 301.
