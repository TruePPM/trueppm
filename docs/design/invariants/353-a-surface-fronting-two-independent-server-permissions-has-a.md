# Rule 353 — A surface fronting two independent server permissions has a PARTIAL-rights band, and one "View only" badge is …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A surface fronting two independent server permissions has a PARTIAL-rights band, and one "View only" badge is wrong for it in both directions — re-derive the standing badge from the union, and sweep every piece of standing copy that names the withheld affordance.** Rule 302 splits presence (`hasEditRights`) from behavior (`readOnly`) on the assumption that a reader either has the apparatus or does not. The Schedule fronts two rules that do not nest — `IsProjectPlanAuthor` for task content (`role >= MEMBER` **minus** the 200–299 band) and `IsProjectScheduler` for dependency edges (`role >= SCHEDULER`) — so each admits exactly one band the other refuses, and a Resource Manager fails the first while passing the second. One boolean across both is wrong for one band whichever way it resolves, and #3034 resolved it as task content: a Scheduler lost canvas drag-to-link the server answers 200, and a Member was offered it while the server 403s. Four obligations, and the last two are the ones a split reliably forgets. **(a) Split the flag per permission and mirror the server rule, not a nearby one.** Deriving the second gate from `can_author` — the first gate's server field — reintroduces the same collapse under a new name; the edge rule is a threshold on the role ordinal and has to be written as one (`canAuthorDependencies`). **(b) Withhold the gesture, do not swallow it.** A canvas affordance refused only at the commit handler still paints its grab point and still offers its cursor, so the user aims at a mark and nothing happens — worse than absence, because their next guess is that the surface failed to render. Tell the engine (`setLinkAuthoring`), and do **not** let the refused hit fall through to a neighbouring gesture: the link zone abuts the bar's right edge, so a fall-through turns a refused link into a silent reschedule. **(c) The standing badge must gain a third state.** `ScheduleViewOnlyBadge` says "change anything here", which is placed by the task-content gate and is therefore false for the one reader who holds the other permission; rule 302's silence clause ("nothing is on offer, so there is no gesture to explain") stops holding the moment something *is* on offer. Give the partial band its own copy naming what it CAN do, on the same element — a second badge reads as a second status. **(d) Standing copy is part of the affordance: legend, cheatsheet, empty states.** The legend's "drag the ◌ handle at a bar's right edge" and the cheatsheet's "Right-click → add dependency" are instructions for gestures that are now role-dependent, and leaving them up while withholding the gesture is louder than the no-op it replaced. Gate the legend line on the same flag as the handle; where the sheet is ungated, describe **both** routes to the capability rather than branching per reader, because a cheatsheet that changes shape per reader is harder to trust than one that says where each door is. Reference: `features/schedule/ScheduleView.tsx` (`readOnly` vs `dependenciesReadOnly`), `lib/roles.ts` (`canAuthorDependencies` beside `canAuthorPlan`), `features/schedule/ScheduleViewOnlyBadge.tsx`, `features/schedule/ScheduleLegend.tsx`, `features/schedule/engine/GanttEngineImpl.ts` (`setLinkAuthoring`) — #3053, extending #2949 and #3034.
