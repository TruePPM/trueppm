# Rule 283 — An icon column carries information or it does not exist: no glyph repeats inside a single settings nav group, …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Iconography*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**An icon column carries information or it does not exist: no glyph repeats inside a single settings nav group, `ExternalLinkIcon` means "this leaves the app", and `WarningIcon` means "exception" (#2425).** The defect this replaced: 6 of the 9 project `Configuration` rows rendered the same glyph (`SettingsIcon` ×5, `ExternalLinkIcon` ×2), with two more collisions in Setup and Danger — a column where most entries are identical is **negative information**, because it trains the eye to stop scanning the column and that costs the rows whose icon actually distinguishes them. Four invariants: (a) **uniqueness is per nav *group*, not per rail** — the same concept deliberately keeps the same glyph across the project / program / workspace rails (General = gear, Team/Members = resources, Access/Roles = lock, Working calendar = calendar, Integrations = plug), so a cross-group repeat is intended and a within-group repeat is the bug; (b) `ExternalLinkIcon` is reserved for navigation that genuinely departs the app and therefore appears in **no** settings nav row — an arrow leaving a box is a promise about where the click goes, and Attachments/Sharing stay inside TruePPM (Sharing gets the share-*network* glyph, because it grants access *inside* the product); (c) `WarningIcon` is reserved for the **Danger** group — spending a warning triangle on routine configuration (sprint guardrails, notifications) is exactly how it stopped reading as an exception; (d) new glyphs are hand-authored into `components/Icons.tsx` on the **16-box** house grid at `strokeWidth="1.5"` (rule 242 — no emoji, no icon library). A 24-box glyph dropped in unscaled renders at ~1.0px effective stroke beside the house set's 1.5px and reads visibly thinner, so convert the geometry rather than the `viewBox`. Each rail exposes its nav as a pure builder (`buildProjectSettingsNav`, `buildProgramSettingsNav`, `buildWorkspaceNavGroups`) so the invariant is asserted on the data, not on a rendered page — `src/features/settings/settingsNavIcons.test.tsx` fails on a reintroduced duplicate. Reference: `components/Icons.tsx`, `features/settings/{ProjectSettingsPage,ProgramSettingsPage}.tsx`, `features/settings/workspace/workspaceNav.tsx`.
