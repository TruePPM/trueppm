# Rule 352 — An entry point whose precondition is "a row is selected" is DEAD on a surface where selecting a row opens a …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**An entry point whose precondition is "a row is selected" is DEAD on a surface where selecting a row opens a covering drawer — put it on the row.** The classification popover reached the product backlog in #3035, and ADR-0800 §6 had left its placeholder in the page *toolbar*. Built that way it looked right in vitest and was unreachable in a browser: clicking a backlog card sets `selectedId` **and** opens `StoryDetailDrawer`, a right-anchored `md:w-[480px]` panel, so the toolbar button was disabled in every state except the one where the drawer covered it. Playwright caught it as `<header> … subtree intercepts pointer events` after 57 retries — the diagnostic that means a genuine overlay, not detachment (a `pointer-events:none` ancestor produces the same message and is a different bug). Three obligations. **(a) Ask what else the precondition does.** "Enabled once a row is selected" is only safe where selection is *inert*; on a master-detail surface selection is a navigation, and the enabling act is the occluding act. **(b) A jsdom suite cannot see this at all** — it has no layout, so an intercepted click still dispatches and every assertion passes. This is rule 300's shape again: the unit test pins the wiring, and only a browser can pin reachability, so an e2e test for a *new* entry point is not optional coverage, it is the only instrument. **(c) The row's own affordance must `stopPropagation`**, since the card is itself a button — otherwise reaching the popover opens the drawer over it and reintroduces the defect from the other side. Reference: `features/project/backlog/ProductBacklogPage.tsx` (`StoryRow`'s `onClassify`), `e2e/product-backlog-classification.spec.ts` — #3035.
