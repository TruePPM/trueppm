# Rule 462 — When one bar state changes its line pattern, re-check every other state that shared it: a pattern freed in one place is a collision in another

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Signal encoding*. The index carries the rule's headline; this file carries its full text (ADR-0653). Binding everywhere, not only on the surface that produced it.

**When one bar state changes its line pattern, re-check every other state that shared it: a pattern freed in one place is a collision in another.** The schedule canvas tells bar states apart by stroke pattern as well as hue (WCAG 1.4.1). In v1 the critical frame is dashed and the selection ring is solid (#4397). The shell v2 Schedule (#4796) needed a third state, near-critical, and gave it the dashed pattern, which made the critical frame solid. That collided with the solid selection ring: a selected non-critical bar and a critical bar then differed only by hue, and no single-state test could see it. The fix was to give the ring a dotted pattern of its own whenever the v2 at-rest option is on. Three obligations. **(a)** Treat the set of patterns as one table (solid / dashed / dotted / none against critical / near-critical / selected / plain), and when one row changes, check every other row against it. **(b)** Pin the whole table in one renderer test that records the dash in effect at each `stroke()` (`GanttRenderer.test.ts`, "shell v2 at rest"). A per-state assertion passes on exactly the collision this rule describes. **(c)** The DOM legend's swatches use the same patterns as the canvas, and its glyphs (▲ critical, ◆ near-critical) are reserved for those two states: any pane that later prints them (the design gives them to the Float column) must use them with the same meaning. Reference: `features/schedule/engine/GanttRenderer.ts` (`criticalAtRest`, `SELECTION_RING_AT_REST_DASH`), `features/schedule/v2/ScheduleLegendV2.tsx`.
