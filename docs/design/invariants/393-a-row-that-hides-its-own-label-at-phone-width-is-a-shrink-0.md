# Rule 393 — A row that hides its own label at phone width is a `shrink-0` budget problem, not a `min-w-0` problem — and …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Controls and composition*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A row that hides its own label at phone width is a `shrink-0` budget problem, not a `min-w-0` problem — and the two have different fixes. Measure before you add either.** The reflex when a `flex-1 truncate` label vanishes is to add `min-w-0`, and on a self-truncating element that is a **no-op**: CSS Sizing 3 §5.2 zeroes the automatic minimum size of any box whose computed `overflow` is not `visible`, and Tailwind's `truncate` IS `overflow:hidden`, so `min-width:auto` already resolved to 0. Measured in Chromium at #3474 — `flex-1 truncate` in a 300px row, with and without `min-w-0`: **120px child / 0px overflow, both times, byte for byte.** What actually emptied the row was arithmetic: a methodology label, two rollup chips, a pin and a Remove button, every one of them `shrink-0`, summed past 390px. `flex-1` then resolves to a legitimate zero and the name is simply gone — not clipped, not ellipsized, *gone*, and `toBeVisible()` agrees with the browser that it is hidden. Three obligations.
**(a) `min-w-0` earns its place on a CONTAINER, not on the truncating element.** Same fixture, truncation moved to a child of the `flex-1` box: the container renders **307px inside a 300px row and overflows by 187px**, and `min-w-0` brings it back to 120px / 0px. That is the shape worth hunting; this tree carries 18 unreviewed sites of it. Keep writing `min-w-0` beside `flex-1 truncate` anyway — `NO_FLEX_TRUNCATE_WITHOUT_MIN_W_0` in `eslint.config.js` enforces it — but as a *consistency* rule, so that the day somebody moves the truncation onto a child the box is already shrinkable. Do not record it as the fix for a disappeared label.
**(b) The fix for the budget is to give the row a second line, and to do it without duplicating a control.** Below `md`, force the metadata group onto its own line (`order-last w-full`, returning to `md:order-none md:w-auto` above it) and leave the name the first line with the actions. The tempting alternative — a phone-only branch that re-renders the pin and the destructive action — doubles their accessible names, which collides Playwright's strict mode and reads the row twice to a screen reader. One wrapping row, one set of controls.
**(c) `toBeVisible()` cannot see this class, so assert geometry.** A collapsed label has an empty box and reads as hidden; a nearly-collapsed one ("the fourth row showed `2…`") has a non-empty box and reads as **visible** while being useless. Assert the label's width as a fraction of its row, and assert `scrollWidth - clientWidth <= 1` on the row so a control pushed past the card edge fails too — an overflowing flex row neither clips nor scrolls, so every element in it stays "visible" while one of them is off the card. Reference: `features/programs/ProgramProjectsPage.tsx`, `e2e/programs.spec.ts` ("Projects tab at phone width"), `src/test/flexTruncateMinWidthRule.test.ts` — #3474.
