# Rule 370 — When a `shrink-0` pane and a `flex-1 min-w-0` pane share a row, the flexible one pays for EVERY pixel the row …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**When a `shrink-0` pane and a `flex-1 min-w-0` pane share a row, the flexible one pays for EVERY pixel the row loses — so the floor that matters must be taken out of the container FIRST, not expressed as a `min-` on the pane that never gets asked.** The Schedule's outline paints at its own summed column width with `flex-shrink-0`; the canvas beside it is `flex-1 min-w-0`. `MIN_BAR_TRACK = 320` had been declared for two releases with a comment saying "below this the timeline stops being one", and nothing enforced it in the shrinking direction — the only clamp built on it was a ceiling on *growing* the name column, which by design "never reaches backwards past the width the user already holds". At 768px the canvas was therefore already down to **25px**, and a sidebar change that took 64px where 0px had been drove it to 0 (#3279). Four obligations. **(a) Reserve the floor from the container and give the rest to the rigid pane** — `outlinePaneWidthFor(pane, outline, reserved)` — rather than putting `min-w-[320px]` on the flexible one, which under `overflow-hidden` merely pushes it off the visible box and changes an unreadable pane into an invisible one. **(b) Count every OTHER `shrink-0` thing in the row.** The 4px `PanelSplitter` is one, and forgetting it leaves the track 4px short of the floor it was promised — a miss no screenshot shows and the arithmetic assertion catches immediately. **(c) Clamp what the pane RENDERS, never what the user stored.** The columns keep their widths and the rightmost ones clip; no persisted value moves and no new `aria-valuemax` is announced, so widening the window restores the user's layout exactly. Guard the floor with a `MIN_OUTLINE_WIDTH` so the clamp cannot trade one useless pane for another. **(d) A zero container means "not measured", never "no room"** — return the unclamped width there, or jsdom and first paint park the pane at its floor forever (rule 343's own trap). **And `toBeVisible()` is not the assertion here.** 25px is a non-empty box, so the gate that should have caught this passed on it for two releases and only failed once the width hit exactly 0 — the same lesson rules 343 and 367 record from the other direction. Assert the measured width against the declared floor, importing the constant rather than repeating it. Reference: `features/schedule/ScheduleView.tsx` (`outlinePaneWidthFor`, `MIN_BAR_TRACK`, `SPLITTER_WIDTH`), `features/schedule/TaskListPanel.tsx` (`renderedWidth`), `e2e/schedule-toolbar-responsive.spec.ts` — #3279.
