# Rule 355 — A responsive surface that renders ONE state through TWO breakpoint-selected components must give that state …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A responsive surface that renders ONE state through TWO breakpoint-selected components must give that state ONE live-region contract — decide it at the state, not once per rendition.** Rule 337 settles this for an ordered `if` ladder inside a single component; a `useBreakpoint()` switch is the same hazard with a predicate no ladder-shaped check reaches, because the two rungs are two *files* and neither can see whether the other announced. The Calendar's "this window holds no tasks" state is rendered by `CalendarMobileList`'s `role="status"` block below `md` and by `CalendarGrid`'s centered week hint above it — same sentence, same condition, and only the mobile one was announced. A desktop screen-reader user stepping into an empty week heard the window change and then had to explore seven empty cells to learn what the sighted user read in one glance. Nothing surfaces this: each component is internally correct, both vitest suites pass, and an axe scan sees two well-formed subtrees. Three obligations. **(a) Locate the contract at the condition, not at the renderer** — if the state is "empty window", every rendition of "empty window" is live or none is; enumerate the renditions before writing either one. **(b) Prefer folding it into an already-mounted announcer over adding a second live region** (rule 335): a `role="status"` node that mounts together with its own text is announced inconsistently across AT, so the surface's permanent announcer is the right home for a "…, no tasks" suffix, and a fresh `role="status"` on the hint is the fallback, not the fix. **(c) An absolutely-positioned `pointer-events-none` hint is decoration to every non-visual consumer** — no role, no name, no meaningful place in the reading order — so it must never be the only carrier of a fact. Note the mechanism honestly (rule 300): "are these two components two renditions of one state?" is decidable by neither grep nor AST, so a zero-tolerance gate would misfire and get disabled. The proportionate mechanism is a paired vitest assertion in the same MR — the desktop empty-state spec asserts the announcement alongside the mobile `role="status"` spec — not a new script. Reference: `features/calendar/CalendarView.tsx` (the permanent announcer, which now carries the emptiness), `features/calendar/CalendarGrid.tsx`, `features/calendar/CalendarMobileList.tsx` — #3167.
