# Rule 407 — Promoting a client constant to a server fact does not end the drift — it MOVES it to every prose restatement …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Signal encoding*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**Promoting a client constant to a server fact does not end the drift — it MOVES it to every prose restatement of that constant, and those are louder than the control they contradict.** #3378 replaced the hardcoded `PROJECT_NOTIFICATION_UNDELIVERABLE_CHANNELS` with the server's `channel_delivery` map so a column could un-mark itself without a web release — the right change, for the same reason the server already owned `eventDelivery` (#2904). One card lower on the same page, an `<h2>` reading "Slack & mobile delivery" sat over hardcoded present-tense prose asserting that TruePPM does not deliver to Slack or mobile push and that no setting turns them on. On the day a delivery path lands (#3252) the 10px caption disappears and that card keeps asserting the opposite — and the card wins, because it is a heading and a paragraph against a caption. Three obligations. **(a) Every surface that restates the constant moves in the same MR.** Grep the file, then the feature directory, for the constant's *members spelled as prose* — the literal channel names, event names, role names — not for the identifier, which is exactly what the change deleted. A constant worth centralizing was worth restating, so there is always more than one site. **(b) Prose that enumerates a dynamic set is BUILT from the set, including whether it renders at all.** The card is gated on `deadChannels.length > 0`, names its members from their labels, and drops the Slack-webhook paragraph when Slack is not among them; a paragraph that cannot be derived must not name members. **(c) The explanation must be reachable at rest for every member the set can hold, not just today's.** #3378's banner said "**Rows** marked not delivered yet…" and was gated on the *row* map, so a server that dispatches every event and delivers on no channel rendered two column markers whose consequence was stated only in a `title` and behind a `FieldHelp` click — rule 328(b)'s defect, re-created by the dynamism rather than by the markup. Watch the accessible name too: `aria-label` overrides sibling content, so a marker that is a sibling span or an unrelated header cell reaches no screen-reader user operating the control — synthesize the state into the name. This is the inverse of the `ux-review` capability-claim check: there the copy promises a capability with no code path; here it denies a capability whose code path is now free to appear. Both are invisible to `docs:version-accuracy`, which only sees text naming a version. Reference: `features/settings/project/ProjectNotificationsPage.tsx`, `hooks/useProjectNotificationPreferences.ts` (`isChannelUndeliverable`) — #3378, extending #3249 / #2904, surfaced by `ux-review`.
