# Rule 382 — An exported symbol with no importer fails `web:knip`. The fix is to delete it, or to name the real root in …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Foundations*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**An exported symbol with no importer fails `web:knip`. The fix is to delete it, or to name the real root in `entry` — never to add an `ignore`.** Thirteen modules with zero importers accumulated in `packages/web` before the 2026-09-04 dead-surface audit, and the reason was not carelessness: nothing detected the class, so every one of them was invisible until somebody read the tree by hand. `web:knip` (config: `packages/web/knip.jsonc`) is that detector. It reports a file no chain of imports reaches from an entry point, an export nobody reads, and a dependency imported but not declared. Three obligations. **(a) An `ignore` entry is a hole in the gate, and the reasons that justify one are narrow**: the file is generated or hand-maintained ahead of its consumers (`src/api/types.ts`, #2609), or it is a gitignored build artifact whose presence depends on whether the tree has been built. "This is reached in a way knip cannot see" is an **`entry`**, not an `ignore` — the two are not interchangeable, because an `entry` still has its own imports followed while an `ignore` deletes the file from the analysis along with everything only it reaches. **(b) A vitest or Playwright spec is a real consumer**, which is why `**/*.test.ts` and `e2e/**` are inside `project` rather than excluded from it — so a test-only export needs no carve-out and must not be given one. **(c) The gate's own blind spots are the part to check, and they do not announce themselves.** One is load-bearing today and it is recorded in `knip.jsonc` (a second, an explicit `entry` for `src/workers/cpmWorker.ts`, was retired by #3593 — the split `new Worker(new URL(...))` that made it unresolvable also stopped Vite compiling the worker, and with the call collapsed knip's output is byte-identical without it): knip's Vite plugin is turned **off** (`"vite": false`) because its `import.meta.glob` visitor reads the pattern and ignores the options object, so the nine `query: '?raw'` source-scanning specs in this tree — two of which glob `src/**/*.{ts,tsx}` — registered every file in `src/` as imported and reduced the whole gate to zero findings. This is rule 300 in its own house: a gate reporting clean is indistinguishable from a clean tree, so before trusting a green `web:knip`, add an exported symbol nobody imports and watch it fail. **(d) The job is BLOCKING, and the ratchet lives in knip's per-rule severity, not in `allow_failure`.** Four rules had a backlog predating the gate — `files` (9), `exports` (50), `types` (53), `duplicates` (3) — and they are `warn` in `knip.jsonc`, which still prints every finding in the job log but does not reach the exit code; everything else is `error` and reds the pipeline. The alternative, shipping the whole job `allow_failure: true` against a 124-finding baseline, was rejected because **a failing `allow_failure` job renders as a green pipeline** — the pipeline `status` field says `success` with the job red underneath, so the reviewer who needed the signal is the one who never sees it, and a permanently-yellow job is one everybody learns to scroll past. Staging by rule keeps the verdict honest: yellow never happens, and red means a class we said was clean is not. So when a new backlog has to be admitted, downgrade the specific rule with the issue that closes it — never reach back for `allow_failure`. #3434 promotes each of the four to `error` as it reaches zero; #3369 clears `files`. — #3375.
