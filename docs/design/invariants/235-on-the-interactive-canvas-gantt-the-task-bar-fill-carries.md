# Rule 235 — On the interactive canvas Gantt, the task bar FILL carries task STATE and the critical path is a red BORDER …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Canvas*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**On the interactive canvas Gantt, the task bar FILL carries task STATE and the critical path is a red BORDER frame — never colour the fill by criticality.** Same principle as the PDF export (rule 234 / ADR-0277), applied to `GanttRenderer.ts`. `barFillColor()` resolves fill by state only (external → `textSecondary`, summary → `barSummary`, complete → `barComplete` sage-600 green, else → `barNormal` blue-500); it must **not** return `barCritical`. `drawTaskBar()` draws a **2px red critical frame** (`barCritical` = #B91C1C light / #F87171 dark) as an inset border for non-external, non-summary critical tasks. The reason: `barFillColor` checks `isComplete` *before* `isCritical`, so a red critical fill lost to a completion-wins-precedence race — a done critical bar rendered solid green and the critical path vanished on a mostly-complete schedule. A completed critical task must read as a **green bar in a red frame**; the critical signal can never be masked by state. Constraints:
- **Draw order:** the 30% progress overlay paints BEFORE the borders so they stay crisp rather than dimmed by the tint; the selection ring paints next; the **critical frame paints LAST**.
- **Selection nests inside the critical frame; risk outranks selection.** The navy `selectionRing` (#1B2A4A) is a 2px inset ring; when a critical frame is present and `barWidth >= MIN_NEST_WIDTH` (12px) it nests one step further in (inset 3px, 1.5px wide) so a selected critical bar reads red-frame-outside / navy-ring-inside. Below 12px the two concentric rings collide, so the ring uses the standard inset and — because the frame is drawn last — the red frame paints over it: a narrow selected critical bar keeps its criticality rather than losing it under the navy ring (the dropped-signal bug the #1699 UX review caught). **Gantt bar visual channels are orthogonal — fill = state, border = risk, ring = selection, line = time (ADR-0103/0277/0280); never encode two on the same channel** (the pre-#1699 bug was critical stealing the fill channel from complete). When channels stack on one bar, each must stay independently perceivable: draw inner channels at a smaller inset than outer ones, and below a minimum width abandon nesting in favor of a treatment that preserves the higher-priority signal (**risk > selection**). A channel another can fully occlude is a dropped signal.
- **The `%` chip uses the surface treatment only** (`chipPillOnSurface` dark pill + `chipTextOnSurface` white). The old white-on-red chip existed for the red critical fill; with no bar red-filled, every chip pairs with the blue/green state fill via the surface treatment. Do not reintroduce a criticality branch in `drawTaskBarChip`.
- **Border clears WCAG 1.4.11** (≥3:1 non-text) in both modes as a 2px frame (#B91C1C ≈ 7:1 on white, #F87171 ≈ 4.87:1 on navy); criticality is additionally backed non-color by the task-list red dot + the critical-path-only filter (1.4.1) — do not remove them.
- **`ScheduleLegend.tsx::CriticalSwatch`** must mirror the canvas: a red-framed neutral bar, not a solid red fill.
- **`barCritical` still legitimately strokes late actuals** in `drawActualDateBar` (#80) — that path is unrelated and must stay.
- **Scope:** the canvas `Task` exposes only `isCritical` (binary), so this is a critical-only red frame; graded at-risk/on-track amber bands (present on the PDF) wait until the risk-band data is plumbed to canvas tasks. Reference: `GanttRenderer.ts::{barFillColor,drawTaskBar,drawTaskBarChip}`, `ScheduleLegend.tsx::CriticalSwatch`.
