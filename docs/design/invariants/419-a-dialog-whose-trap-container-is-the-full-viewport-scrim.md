# Rule 419 — A dialog whose trap container is the full-viewport scrim breaks the instant any phase disables every control

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3433). Binding everywhere, not only on the surface that produced it.

**A dialog whose trap container is the full-viewport scrim breaks the instant any phase disables every control — put `ref`/`role`/`aria-modal`/`tabIndex={-1}` and the `focus:` ring on the PANEL, and let the scrim be a plain pointer-dismiss sibling.** `useFocusTrap`'s `FOCUSABLE_SELECTOR` excludes `button:[disabled]` (`hooks/useFocusTrap.ts:3-4`), so a dialog phase that disables its whole footer — a `pending` / `Switching…` state, a progress step, an in-flight destructive confirm — matches no focusable child, and the re-seat effect falls through to `(first ?? container)?.focus()` (`useFocusTrap.ts:96-97`): focus lands on whatever element carries the trap's `ref`. In the common idiom in this tree, that `ref` sits on the outer `<div className="fixed inset-0 … role="alertdialog" aria-modal="true" tabIndex={-1}">` scrim, with an un-refed inner panel div holding the actual card. A scrim spans the whole viewport, so `focus:ring-*` on it draws a ring around the entire screen — unsatisfiable by construction, and rule 288(c)'s "a programmatic focus target carries a `focus:` ring and never bare `focus:outline-none`" cannot be met no matter what class you add (WCAG 2.4.7).

The fix is structural, not a class tweak: move `ref`, `role="dialog"|"alertdialog"`, `aria-modal="true"`, any `aria-labelledby`/`aria-describedby`/`aria-label`, and `tabIndex={-1}` from the scrim onto the **panel** — the bounded card the user actually sees — and give the panel the `focus:` ring (`focus:outline-none focus:ring-2 focus:ring-brand-primary focus:ring-offset-1` — matching the offset every other programmatic `tabIndex={-1}` target in this tree uses, from `RouteErrorBoundary.tsx`'s heading to `BulkEditSheet.tsx`'s result panel; `ring-offset-2` is reserved for a ring drawn in white against the control's own `brand-primary` background, never `focus-visible:`, since a scripted `.focus()` call may not trigger `:focus-visible` — rule 204(b)/214/288(c)). The scrim becomes a plain sibling `<div className="fixed inset-0 …">` whose only job is the pointer-dismiss handler (`onPointerDown` checking `e.target === e.currentTarget`, unchanged) — it carries no ARIA role and is never a focus target. This is not a purely mechanical rename: moving `role` onto the panel changes what `getByRole('dialog'|'alertdialog')` resolves to, so any test that queried the dialog role node to simulate a backdrop press (`fireEvent.pointerDown(dialog, { target: dialog })`) must instead target `dialog.parentElement` — the panel's immediate parent is still the scrim in every fixed instance, since the two elements' relative nesting does not change, only which one carries the role.

`ScopePendingReviewPanel.tsx`'s slide-over already had this right (`panelRef` sits on the `role="dialog"` panel, and the `fixed inset-0` wrapper is an unrefed sibling) — its nested bulk-confirm dialog is the scrim-trap idiom, but is not affected in practice because neither of its two buttons is ever disabled. That is the scoping test for whether a given scrim-trap dialog needs the fix: audit for the idiom, but only ones with a phase that disables every control actually exercise the invisible-seat bug. `TaskTrashDialog.tsx`, `UpdateStatusDialog.tsx`, `BoardSettingsPanel.tsx`, `BaselineManagerModal.tsx`'s own header-close, `DepPopover.tsx`, and `ApiTokensManager.tsx`'s `CreateTokenModal` all keep at least one control (a persistent close button, an always-enabled Cancel, a never-disabled text input) enabled through every phase, so the trap never falls back to the container and the scrim-trap idiom in them is inert today — reviewed and left alone rather than churned, since they are not exercising the defect this rule exists to prevent. If a later edit disables their last remaining control, they become live instances of this rule.

Reference: `MethodologyFlipWarningDialog.tsx` (the #3433 reproducer), `UnsavedChangesDialog.tsx`, `DeleteConfirmDialog.tsx` (board/TaskFormModal), `RemoveFromProgramConfirmDialog.tsx`, `CommitPlanConfirmDialog.tsx`, `CascadeDeleteDialog.tsx`, `CaptureBaselineConfirmDialog.tsx`, `BaselineManagerModal.tsx`'s `BaselineDeleteConfirm`, `LinkInputModal.tsx` (schedule/sections — the panel here is a `<form>`, so the trap ref, role and ring move onto the form element itself), `GitAutomationManager.tsx`'s `RotateSecretModal`, `WebhooksManager.tsx`'s `ConfirmDialog`, `hooks/useFocusTrap.ts`.
