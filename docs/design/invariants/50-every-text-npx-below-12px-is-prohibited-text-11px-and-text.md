# Rule 50 — Every `text-[Npx]` below 12px is prohibited — `text-[11px]` and `text-[10.5px]` included

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**Every `text-[Npx]` below 12px is prohibited — `text-[11px]` and `text-[10.5px]` included.** The design system floor is `text-xs` (12px); arbitrary size values below it bypass the token ladder and introduce WCAG 1.4.3 failures on any surface. **One** exception is left, and it is a named tree rather than a judgement call: `text-[10px]`–`text-[11px]` under `features/settings/` (rule 118's compact-admin density), fractions included, so `text-[10.5px]` is sanctioned there and `text-[9.5px]` is not — the settings floor is a value, not a leading digit. `text-[9px]` and below are prohibited everywhere, settings included. **The StatusBar's `text-[11px]` carve-out is retired (#3475)** — it bought one pixel of chrome quietness on the app's most persistent surface and cost a 1.4.4 risk; the bar is `text-xs` in `h-6`, which fits, and a `text-[11px]` reappearing there is a regression, not a re-grant. **`aria-hidden` does not license sub-floor type on text a sighted user reads** — the two survivors this rule baselined for three releases were exactly that argument (TaskSummaryStrip's 10px owner initials, ProgramIdentitySquare's 7px `xs-label` code), and both are gone: the strip's avatar grew to 24px and took `text-xs`, and the `xs-label` variant was deleted outright once it was checked that **both** of its call sites already render the program name as adjacent text. Two corollaries that cost two extra sweeps to learn. **(a) A size that cannot hold legible type carries none** — the fix for "the glyphs don't fit" is to drop the glyphs and lean on the adjacent label, never to shrink the type; if nothing adjacent carries the meaning, the tile is the wrong container. **(b) The gate sees the inline form only when it is spelled as a literal (#3506).** `tiny_text_offenders()` matches `text-[Npx]` classes, and since #3506 also an inline `fontSize` that is a sub-12 literal (`fontSize: 10`, `'10px'`), a ternary with a literal arm (`size <= 18 ? 9 : 10`), or a derived `fontSize: size * 0.42`; the settings carve-out applies to the inline literals too (10/11 only). It still cannot see a size that arrives through a variable or helper, a CSS variable, or a stylesheet — a computed-`font-size` Playwright sweep is the only thing that could, and is deferred until the class comes back a fourth time. So `BASELINE_TINY_TEXT=0` is a claim about literal and class-shaped sizes, not about every pixel rendered. Prefer the Tailwind class. SVG chart axis ticks (`fontSize: 11` on FlowCharts and BurnChartCanvas) are chart type, not DOM copy, and carry a trailing `tiny-text-ok: <reason>` comment, the gate's only opt-out. The pattern has been widened three times against its own blind spots (`text-[11px]` at #2858, decimals at #3475, inline style at #3506) — see rule 300.
