# Rule 310 — Two URL-param writes in the SAME commit lose the first — `setSearchParam`'s functional updater does not save …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**Two URL-param writes in the SAME commit lose the first — `setSearchParam`'s functional updater does not save you, and the failure is silent.** `setSearchParams` resolves each updater's `prev` from the **live location** at call time, and react-router does not apply an earlier write before a later one reads. So functional updaters compose only **across** commits. Within one commit — two `setSearchParam(…)` calls for two keys, or one racing a sibling effect that also writes on the mount pass — the later write's snapshot is the pre-write URL and it restores everything the earlier one deleted. Nothing throws, no test fails, and the param simply stays in the URL, which is why this reads as "my effect never ran" and sends you debugging the wrong function. `useUrlSelectedId`'s docstring used to claim same-flush composition; it is corrected, and #2031's fix was always about the *cross-commit* case. Two obligations: **(a)** one pass that must change several keys writes them in **one** `setSearchParams` updater, never N helper calls; **(b)** a write that must survive a sibling mount-pass write (in `ScheduleView` that is the focus/cp/crit/ms display-filter mirror, which fires on every mount) is deferred to a **later commit** — latch a state flag in the consuming effect and do the write in a second effect keyed on it. A one-shot `useRef` guard is still needed for the *consume*, and is a different concern from the *strip*: the ref stops the action repeating, the deferral is what makes the URL actually change. Diagnose it by logging the raw param on every render — a value that stays put across many renders after your write means the write landed and was reverted, not that it never happened. Reference: `features/schedule/ScheduleView.tsx` (the `?author=` consume/strip pair), `hooks/useUrlSelectedId.ts` — #2952.
