# Rule 380 — On a surface that commits from a keyboard shortcut, a description bound to the commit BUTTON is unreachable — …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**On a surface that commits from a keyboard shortcut, a description bound to the commit BUTTON is unreachable — bind it to the dialog.** `aria-describedby` is announced when the described element takes FOCUS. `ClassificationPopover` submits on `Enter` from anywhere inside it and `useFocusTrap` seats initial focus on the first focusable (a preset chip), so the fastest keyboard path — open, arrow an axis, `Enter` — never focuses Apply, and a screen-reader user commits the act having never heard the pre-act disclosure the binding was supposed to deliver. `BulkEditSheet` has the same anatomy on `⌘Enter`. **Rule 377(c)'s "DOM containment is the real guarantee" does not rescue this**: containment guarantees a *browse-mode* reader can find the sentence, and a commit shortcut is exactly the path that skips browse mode — 377(c) was written for a state with nothing to attempt, so no gesture could outrun the reading. Put the id on the `role="dialog"` container, which is announced on focus ENTRY regardless of which child receives focus, and keep the control-level binding as the redundant half rather than the mechanism. Append to any existing description id list rather than replacing it, and generate the id with `useId()` — a duplicate id silently breaks the binding and the obvious assertion (`expect(apply).toHaveAttribute('aria-describedby', note.id)`) still passes on it. The test that proves this rule is not that assertion on the button — it passes on the broken build — but one that the **dialog** carries it. Reference: `features/schedule/classification/ClassificationPopover.tsx`, `features/schedule/buildMode/bulkEdit/BulkEditSheet.tsx` — #3357, surfaced by `ux-review`.
