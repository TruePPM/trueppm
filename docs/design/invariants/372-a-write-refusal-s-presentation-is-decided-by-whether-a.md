# Rule 372 — A write refusal's presentation is decided by whether a replay could succeed, and its inline error is a …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A write refusal's presentation is decided by whether a replay could succeed, and its inline error is a SIBLING `role="alert"` — never a child of the surface's preview `role="status"`.** Two halves, both learned from the classification popover, which relabeled all three of its distinct refusals to "Retry" and rendered them inside its own preview region (#3302). **(a) The primary button keeps its verb on a `4xx`.** `lib/apiError.ts`'s `isClientRejection` already states the contract — the server has made a definitive decision, so an identical replay is refused identically, and "a real retry is the user editing the value and re-submitting". Offering "Retry" on a 403, a cap violation, or a validation refusal points at the one action guaranteed not to help, and it *hides* the affordance that would: the verb it overwrote ("Apply to subtree" / "Apply to task") is what tells the user the scope they are about to commit. Relabel only when a replay could succeed — network loss and `5xx`, plus the two `4xx` that refuse *timing* rather than content (**408**, **429**), which the bare `isClientRejection` predicate would otherwise strand. **(b) The error is not a child of the preview region.** `role="status"` carries an implicit `aria-atomic="true"`, so appending an error inside a preview makes AT re-read the whole preview *before* the refusal, and adding `role="alert"` in place nests two live regions and risks a double announcement. Render it as a sibling above the action row, full width, so a two-line message is not squeezed into the flex column beside the buttons — `ScheduleCommitPopover`'s anatomy: `<div role="alert" className="… text-semantic-critical" data-testid="<surface>-error">`. **Corollary — structured error fields carry the REMEDY, not a re-narration of the prose.** A DRF body that ships machine-readable fields beside `detail` (`code`, `matched`, `max`) ships them so a client can *branch*; spending them on numbers the sentence already contains doubles the reading length of the one message the user is stuck on. Echo them only when the sentence does not carry them. **And retire the refusal the moment the spec it described changes** — copy that names a control ("turn off Cascade to descendants") instructs the user to do what they just did, while the button beside it has already silently recomputed. Reference: `features/schedule/classification/ClassificationPopover.tsx`, `features/schedule/classification/useClassificationPopover.ts` (`describeClassificationError`), `features/schedule/ScheduleCommitPopover.tsx`, `lib/apiError.ts`. **The eight surfaces #3332 tracked are fixed, and the shaping now has ONE definition — `describeWriteRefusal(error, fallback)` in `lib/writeRefusal.ts`** (the classification popover's own copy was lifted there, not duplicated). Every surface consumes the `WriteRefusal` record, and `DialogFooter`/`UnsavedChangesDialog` take it as a **prop type**, so the four drawer call sites were fixed at the seam rather than one at a time and a fifth cannot regress by passing a hardcoded string — `tsc` refuses it. The population is larger still: #3302 counted ~35 surfaces hand-rolling `response?.data?.detail`, and nothing gates them, so a new surface reaches for `describeWriteRefusal` and never the nearest neighbor. **Be precise about what the typed seam did and did not close:** it closed `DialogFooter`'s four call sites *by construction*, and nothing else. **17 hand-rolled `data.detail` readers remain** in non-test `src/` (settings, programs, share, risk, `hooks/commitRefusal.ts`, `hooks/restoreRefusal.ts`, …), reachable by no type and by no gate. A typed prop is a mechanism for *its own* call sites; every other instance is still a sweep, and saying otherwise is how a class gets declared closed while most of it ships. See also rule 375 for why the *shape of the prop*, not a sweep, is what closed this.
