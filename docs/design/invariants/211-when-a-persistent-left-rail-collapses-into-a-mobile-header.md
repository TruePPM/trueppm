# Rule 211 — When a persistent left rail collapses into a mobile header that re-hosts the *same* interactive controls …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**When a persistent left rail collapses into a mobile header that re-hosts the *same* interactive controls (scope switcher, context switcher, copy-link — anything queried by role/label), render exactly ONE copy via a `useBreakpoint()` conditional, NEVER two copies gated by `hidden md:flex` / `md:hidden`.** Tailwind's `hidden` is a CSS-only visibility toggle: both the rail and the mobile header stay mounted in the DOM, so every shared control exists twice. That is invisible in the browser but breaks every role/label query — jsdom (`window.matchMedia` absent → `useBreakpoint()` reports `lg`) and Playwright strict mode both resolve `getByRole('button', { name: 'Workspace' })` to two elements and throw. Extract the shared controls into small components (`ScopeSwitcher`, `ContextRow`) and render `{!isMobile && <aside…>}` / `{isMobile && <header…>}` off `const isMobile = useBreakpoint() === 'sm'` so only one instance is ever in the tree. The `SettingsShell` collapse is the reference: the 240px scroll-spy rail (md+) becomes a compact header below `md` whose scroll-spy nav is a native `<select>` "Jump to section" (`value={activeId}`, `optgroup` per nav group — OS-native, 44px, zero popover code), and `FieldRow` swaps its fixed inline `gridTemplateColumns: '240px 1fr'` for `grid-cols-1 md:grid-cols-[240px_1fr]` so label+control stack instead of overflowing a phone. Corollary for a `NavLink` whose active state must persist across sub-routes (a Settings gear that stays active on `…/settings/general`, `…/settings#access`, …): point `to` at the base the URL actually settles on (`…/settings`), because `NavLink` overrides an explicit `aria-current` prop with its own route match — a `to` that never equals the settled path renders `aria-current` unset even when your own `isActive` styling says active. Reference: `SettingsShell.tsx` (`isMobile` split, `ScopeSwitcher`/`ContextRow`, the jump-to-section `<select>`), `BottomNav.tsx` (the Settings entry's base `to`). **Focus-trap corollary (#2148):** the same single-shell discipline is mandatory whenever a `ref` must bind to the *visible* one of two responsive shells — a `useFocusTrap` container ref or a shared `closeButtonRef`. A `hidden md:flex` / `md:hidden` dual-render binds the ref to the DOM-first (desktop) copy while the mobile copy is `display:none`, so a hand-rolled trap covers only the desktop shell and the shared close-button ref focuses an invisible element (both were live bugs in `RiskDrawer`/`ResourceOverallocationDrawer` before #2148). Render one shell off `const isMobile = useBreakpoint() === 'sm'` and attach the trap to it. When the two shells differ in *modality* — a non-modal desktop inspector that sits beside content vs. a modal mobile sheet (rule 264) — gate the trap on the breakpoint as well (`useFocusTrap(isMobile && isOpen, …)`) so the desktop panel stays Tab-transparent and only the mobile sheet traps. Reference: `RiskDrawer.tsx`, `ResourceOverallocationDrawer.tsx`.
