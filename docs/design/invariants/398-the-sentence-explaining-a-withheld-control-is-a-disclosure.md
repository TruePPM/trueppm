# Rule 398 — The sentence explaining a withheld control is a disclosure in its own right, and it carries the false claim …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Placeholders and operator surfaces*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**The sentence explaining a withheld control is a disclosure in its own right, and it carries the false claim that the withhold does not — three states, not two, and a third footprint that is neither `QueryErrorState` variant.** Rule 392 fixes the *predicate*; this is the copy hanging off it, and it is the half that survives a 392 sweep because the sweep's own success criterion — the affordance stayed closed — is already met. `EstimatesTab` disabled the remaining-points input whenever `activeSprint?.id !== task.sprintId`, which is correct on a failed sprints read, and then explained it with *"Remaining effort can be updated while the iteration is active"* — a statement about the iteration, from a read that never established anything about the iteration, standing under a permanently dead control (#3455). The user goes and looks at a sprint that is running fine. **Three obligations.** **(a) Three-valued, never boolean.** `'resolved' | 'unresolved' | 'failed'`: a two-way `error ? failure : hint` flashes *"Couldn't check…"* during every cold load, and a two-way unknown-vs-known keeps the lie on the failure. In flight the copy says **nothing** — neither claim is available yet — and only a terminal failure names itself and offers Retry. Folding in-flight and failed into one `…Unknown` boolean is right for the *gate* (they are both closed) and wrong for the *copy*, which is exactly the two-different-things-in-one-value tell. **(b) Pass the read state beside the verdict, never folded into it, and default it to `'resolved'`** — so a caller that genuinely holds the verdict, or has nothing to look up, is unchanged, and the unknown case cannot be dropped by a later edit to either input (rule 392's obligation restated at the component boundary). Scope it to the lookup: a task with no `sprintId` is never unknown. **(c) A hint under a control that still renders takes a plain one-line `role="status"` sentence in the same slot, not a `QueryErrorState`.** Rule 246's `fill` is a dead pane and `inline` is a bordered `min-h-24` card that replaces a widget's whole body; here the fieldset is alive — committed points, the legend and the input all render — so both variants inflate a replaced sentence into a card. Match the footprint of the copy you are replacing (rule 392), keep `text-xs text-semantic-critical`, and give it the same underlined Retry wired to the query's own `refetch`. **When the section really is dead, `inline` is still correct**, and the two treatments sitting in one drawer are not an inconsistency — they track what actually died: `SprintSection` has no picker to draw once the list fails, so it takes the card. **The read-only branch is the one that gets missed.** A Viewer on that same failure got *"Not assigned"* — a flat claim about a task that may well be committed, and a worse lie than the create-a-sprint nudge an editor saw, because it names the task rather than the project. Put the error branch **above** the permission fork, not inside the editable arm. Pin all four states per surface (failed → locked and says so; in flight → locked and silent; resolved-negative → locked with the plain hint; resolved-positive → open), so a later "these should all say the same thing" refactor has to confront the asymmetry. Reference: `features/schedule/EstimatesTab.tsx` (`SprintEffortFieldset`, `SprintReadState`), `features/schedule/sections/EstimatesSection.tsx`, `features/schedule/sections/SprintSection.tsx`, `hooks/useSprints.ts` (`useActiveSprint` returning `error`) — #3455, the fail-closed cousins of #3424.
