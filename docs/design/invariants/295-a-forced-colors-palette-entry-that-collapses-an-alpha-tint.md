# Rule 295 — A forced-colors palette entry that collapses an alpha tint to a solid system colour (`Canvas`/`CanvasText`) …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Canvas*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A forced-colors palette entry that collapses an alpha tint to a solid system colour (`Canvas`/`CanvasText`) is only safe if that fill paints BEFORE everything it would occlude — check the draw ORDER, not just the palette.** Rule 244 requires semi-transparent tints to collapse to the solid surface/ink under `(forced-colors: active)`, because the theme may not honour alpha. That collapse is a *no-op* for a fill painted first (row banding, weekend shading — both drawn before `drawGridLines`) and **destructive** for a fill painted later: at 5% alpha the grid, separators and neighbouring marks read straight through; at 100% opacity they are erased. The failure is invisible in light and dark, invisible in any unit test that asserts only "forced mode emits system-colour `fillStyle`s", and appears only to a Windows High Contrast user — who loses the row separators they need most. So for a **region** fill (as opposed to a bar or a line) the forced-colors treatment is to **skip the fill entirely** and let the mark survive as its edges, hatch and label; branch on an explicit module-level `_forcedColors` flag set alongside the palette, never on the palette value alone. Two corollaries. (a) **Shape, not just hue, must separate a new full-height rule from the today line** — under the flat system palette `Highlight` is shared, so a solid 2px band edge is pixel-identical to ADR-0103's load-bearing "now" mark; dash it (`ctx.setLineDash`), which also keeps the mark non-colour-carried at zoom levels too narrow for its text label (WCAG 1.4.1). (b) **Anything drawn on the bars layer after `drawTaskBar` must clear the bar box** (`BAR_TOP_OFFSET`…`BAR_TOP_OFFSET + BAR_HEIGHT`, i.e. y 5–23 of a 28px row) — rule 235's critical frame is the first and last 2px of that box, and a label straddling a row boundary paints over the row above *and* the row below. The free strip is the 10px inter-bar gutter (`rowTop − 5 … rowTop + 5`); a mark that will not fit there paints *before* the bars so the bar wins the collision and the risk signal survives. Reference: `COLOR_FORCED.sprintBandFill`, `drawSprintBands` / `drawSprintBandLabels` in `engine/GanttRenderer.ts`, and their call sites in `engine/GanttEngineImpl.ts` (#2738, ADR-0803 — surfaced by `ux-review`).
