# Rule 298 — A route boundary is inherited, never opted into: every child of the `AppShell` route gets its `errorElement` …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A route boundary is inherited, never opted into: every child of the `AppShell` route gets its `errorElement` from `shellRoutes()` in `router.tsx`, and a recovery action that leaves the document asks the write queue itself before discarding it.** Issue 1654 added the shell-preserving `errorElement` by hand to `projects/:projectId` and `programs/:programId`; every route added afterwards (My Work, My Assets, Timesheet, the notification inbox, `me/settings/*`, the org resource catalog, the programs list) silently missed it, because omission was the default and protection the exception (#2834). Without a boundary *below* the shell, a render throw or a failed lazy chunk bubbles to the `RequireAuth` net and unmounts `AppShell` — which takes `PendingWritesGuard` with it, so the `beforeunload` warning that is the only thing protecting TanStack Query's **in-memory** write queue is gone on the very screen whose job is to offer a reload. Two consequences, both load-bearing: **(a)** add new shell routes *inside* the `shellRoutes([...])` call and do not paste an `errorElement` of your own unless you genuinely want a closer boundary (a nested shell like `ProjectShell` is a legitimate one — the helper keeps any `errorElement` a route already declares); **(b)** any recovery affordance that reloads or hard-navigates reads `getPendingWriteCount()` at click time and interrupts with a focus-trapped `role="alertdialog"` naming the count, because the guard it would otherwise rely on may already have been unmounted by the same crash. Read the count imperatively, not with a hook — the boundary can render *outside* the `QueryClientProvider`, which `AppShell` owns. The enumeration test in `src/router.test.tsx` is the regression guard: it fails if any shell child lacks a boundary, which is the only thing that stops this from recurring. Reference: `router.tsx` (`shellRoutes`), `components/RouteErrorBoundary.tsx` (`DiscardPendingWritesDialog`), `hooks/useSyncStatus.ts` (`getPendingWriteCount`), `src/router.test.tsx`.
