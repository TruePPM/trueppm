# Rule 422 — A role that only permits specific children must not gain siblings-turned-descendants from surrounding markup or a wrapped library

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3482). Binding everywhere, not only on the surface that produced it.

**`<dl>`, `role="grid"`/`"treegrid"`, and `role="row"` each accept only a narrow, named set of direct children — WCAG 1.3.1, axe `aria-required-children` / `definition-list` — and the violation is usually markup that grew up *around* a correct inner structure, not inside it.** Three shapes from one sweep (#3482):

- **`<dl>`** permits only `dt`/`dd` (each optionally wrapped in its own `<div>`), `<script>` or `<template>` as **direct** children — and a wrapping `<div>`'s own children must themselves be a dt/dd group. A status chip, badge, or callout that is neither a term nor a description cannot live inside the `<dl>` at all, wrapped in a `<div>` or not (`SprintGoalCard.tsx`'s points-committed chip). Move it **outside** the `<dl>` as a sibling. If the two need to share a flex/gap layout, move the layout classes to a wrapping element and put `className="contents"` on the `<dl>` so its dt/dd-group `<div>`s participate in that flex layout directly — this preserves the visual result with no layout diff while making the DOM legal.
- **`role="grid"`/`"treegrid"`** permits only `row`/`rowgroup` as direct children. Axis labels, legends, and status captions that read naturally as "part of the chart/matrix" are not rows — they must be **siblings** of the grid-rolled element, never descendants, however tempting it is to nest them for CSS convenience (`RiskMatrix.tsx`: the Impact-axis labels and the "N unmitigated" callout used to live inside `role="grid"`).
- **A library that injects its own DOM into wherever it is mounted can smuggle a disallowed child in** — `DndContext` (`@dnd-kit/core`) renders its own `role="status"` live region as a literal child alongside whatever it wraps, not via a portal. Wrapping `<DndContext><div role="treegrid">…</div></DndContext>` puts that live region **inside** the treegrid. Fix by nesting the other way — `<DndContext>` around the role-bearing element, not inside it — so the injected region lands as a sibling (`OutlineMode.tsx`). When adding a third-party wrapper anywhere near a restrictive-children role, check what that wrapper renders as its own child, not just what you pass it as `children`.

**`role="row"`** is the same shape one level down: it permits only `gridcell`/`rowheader`/`columnheader` as **direct** children, so a row label needs `role="rowheader"` (not a bare `<span>`) and each cell's interactive control needs a `role="gridcell"` wrapper of its own if the control's element type does not itself support that role (`<button>` does not — `role="gridcell"` on a `<div>` wrapping the button is the standard ARIA composite-widget grid pattern, and `gridcell` is a structural role, not an interactive one, so it does not trigger `nested-interactive`).
