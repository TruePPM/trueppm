# Rule 4 — Focus rings on all interactive elements

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**Focus rings on all interactive elements**: `focus-visible:ring-2 focus-visible:ring-brand-primary focus-visible:ring-offset-1`
- **Standalone-control carve-out (rules 214/261(e)): standalone triggers, menu items/rows, tabs, chips-as-buttons, and dropdown/popover triggers use `focus:` — never `focus-visible:`.** Firefox and desktop Safari do not match `:focus-visible` on pointer-initiated focus of a button, so `focus-visible:` leaves these controls with no visible focus after a click. Write `focus:outline-none focus:ring-2 focus:ring-brand-primary` plus `focus:ring-offset-1` (freestanding) or `focus:ring-inset` (menu rows, tight popover items). Form fields (`input`, `select`, `textarea`, checkboxes whose wrapping label carries a `focus-within:` ring) keep `focus-visible:` — browsers always match `:focus-visible` on editable fields, and a persistent `focus:` ring on a field the user is typing in is noise. The Schedule tree (`features/schedule/`) stays `focus-visible:` deliberately per rule 137. Enforced by `NO_FOCUS_VISIBLE_ON_TRIGGER` in `packages/web/eslint.config.js` — an AST sweep over every `<button>` carrying `aria-haspopup`/`aria-expanded`, which is what the two-control Playwright spot check (`e2e/focus-ring-pointer.spec.ts`, #2292) could never be; that spec proves the *browser behavior*, not coverage (rule 300). Reference: `features/shell/UserMenu.tsx`, `CreateMenu.tsx`, `NotificationBell.tsx`, `HealthCluster.tsx`, `BottomNav.tsx`; board/sprints/backlog converted in #2042, the tree swept in #2858.
- On a **sage fill** (primary button, `bg-sage-500`): use `focus-visible:ring-navy-700 focus-visible:ring-offset-sage-500` (navy-on-sage 6.8:1) — with `focus:` variants instead when the control falls under the standalone carve-out above.
- **No dark-mode override needed for `brand-primary` (ADR-0103/0125).** `brand-primary` is mode-aware sage — sage-**700** #316F57 (light, 5.93:1) / sage-400 #66B998 (dark, ≥3:1) — so `ring-brand-primary` passes WCAG 1.4.11 in both modes. (sage-600 #3E8C6D is only 4.06:1 on white — a fill/dot shade, never the foreground/ring token; see rule 143 and ADR-0126 §3.) The old `dark:focus-visible:ring-semantic-on-track` escape hatch (for green #1C6B3A's 2.81:1 dark failure) is **retired** — do not reintroduce it.
- Never use `outline-none` without a visible replacement
