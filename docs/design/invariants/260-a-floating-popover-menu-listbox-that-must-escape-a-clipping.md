# Rule 260 — A floating popover / menu / listbox that must escape a clipping ancestor (an `overflow-hidden` card, an …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Controls and composition*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A floating popover / menu / listbox that must escape a clipping ancestor (an `overflow-hidden` card, an `overflow-y-auto` scroll panel) or stay on a narrow viewport uses the shared `useAnchoredPopover` hook (`hooks/useAnchoredPopover.ts`) as its positioning + dismissal engine — do not hand-roll the `getBoundingClientRect` → `position:fixed` → flip-above → clamp → scroll(capture)/resize → outside-`pointerdown` math inline.** This names the *implementation* of web-rule 253, which remains the *specification* of those mechanics; the two are complementary (a new site could "follow 253" and still re-introduce a clip/flip bug by hand-rolling the math). The hook owns exactly four concerns: portal-`fixed` positioning, flip-above, horizontal/width clamp (to the viewport, replacing any `max-w-[calc(100vw-…)]`), and outside-`pointerdown` dismiss spanning the trigger + the portaled panel (once portaled they are no longer DOM-nested, so a single `containerRef.contains` check treats panel clicks as "outside"). The **call site keeps** its own contents, keyboard model (`aria-activedescendant` roving, two-stage Escape), open-state ownership, and focus-return — the hook deliberately does NOT handle Escape (a duplicate document listener double-fires — the rule-204 lesson). Usage: pass `open`, `width` (`number` | `'trigger'` to match the anchor), `estimatedHeight` (flip heuristic only), and optional `align` / `gap` / `margin` / `onDismiss` (omit `onDismiss` to keep a site's own `onBlur` dismissal); attach `triggerRef` to the anchor and `popoverRef` to the panel; render `open && popoverStyle && createPortal(<panel ref={popoverRef} style={popoverStyle} className="z-50 …" />, document.body)`. The hook returns a non-null off-screen `popoverStyle` immediately when `open` (real coords are measured in `useLayoutEffect` before paint), so the portal mounts in the **same** commit — required for a panel that focuses its own input on open (comboboxes). **A `role="menu"` with focusable items MUST move focus into the menu on open** (`popoverRef.current?.querySelector('[role="menuitem"]')?.focus()` in a `[open]` effect) and rove with Arrow/Home/End + close on Tab/Escape returning focus to the trigger — portaling removes the items from natural tab order, so without this a keyboard user cannot reach them. The two original inline implementations — `features/board/PendingAcceptanceChip.tsx` and `features/schedule/UnscheduledTaskRow.tsx` — are **grandfathered reference specs** (do not rewrite them onto the hook); every new call site uses the hook. Reference: `hooks/useAnchoredPopover.ts`, `components/EntitySelectCombobox.tsx`, `features/settings/SettingsContextSwitcher.tsx`, `features/settings/members/InviteForm.tsx`, `features/settings/program/ProgramCadencePage.tsx`.
