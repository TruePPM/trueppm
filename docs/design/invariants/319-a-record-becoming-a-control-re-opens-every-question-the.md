# Rule 319 — A record becoming a control re-opens every question the record never had to answer — and the first is whether …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A record becoming a control re-opens every question the record never had to answer — and the first is whether the thing can be reached at all.** The Schedule's session trail shipped as a popover with nothing to click (#2948), so `absolute bottom-full` was fine: the panel rendered at y≈-126 on a trigger sitting at y≈74 in the toolbar, entirely above the viewport, and nobody noticed because an unread record costs nothing. Adding an Undo button to it (#2974) turned that into a control the user cannot press, and **`toBeVisible()` passes on it** — Playwright visibility is a box-and-opacity question, not a viewport one, so the only signal was `element is outside of the viewport` buried in a click retry log. Four obligations when a read-only surface grows its first action. **(a) Anchor to where the trigger actually is, not to where popovers usually go — on BOTH axes.** `bottom-full` encodes "my trigger is near the bottom of the screen"; assert the panel's `boundingBox().y >= 0` in the spec that adds the control, because that is the assertion `toBeVisible` cannot make. The horizontal twin is the same bug and shipped for another year (#3663): `right-0` encodes "my trigger is near the RIGHT edge of its container", and this one sits in the toolbar's LEFT group, so its 380px panel grew leftward through ScheduleView's `overflow-hidden` wrapper and lost the first ~50px of every line. Three things follow. **A `z-index` cannot rescue either axis** — only leaving the subtree escapes a clipping ancestor, so the fix is rule 260's `useAnchoredPopover` (portal + clamp), not a different Tailwind anchor class: flipping `right-0` to `left-0` just moves the clip to the other edge at a different rung of the fit ladder. **Assert all four bounds** (`x >= 0`, `y >= 0`, `x + width <= viewport.width`, `y + height <= viewport.height`), not just the one that failed. **And pick the viewport that makes the assertion non-vacuous**: what decides the clip is the width of everything left of the trigger, not the viewport, and at 1000px the undo spec's fixture cleared the edge by 0.03px — the four-bound assertion passed on the unfixed component and guarded nothing until the viewport was narrowed to the composition the DEFAULT display options produce (`structureButtons: false`, `pinMilestone: false` — the two controls whose absence puts the trail closest to the edge). Run it against the pre-fix component and watch it fail, or it is decoration. **(b) The control and any keyboard twin must read one derivation.** `newestUndoableEntry` is the only thing that decides which entry ⌘Z and the button both target — a second copy of "which one is undoable" drifts into a confident wrong answer, which is rule 316's failure mode applied to an action instead of a sentence. **(c) An action the surface cannot perform must render as no control, never as a disabled or silently-inert one.** An entry with no server ledger handle (duplicate, convert-to-milestone) gets a record and nothing else, and the keybinding falls through to the browser rather than absorbing the keystroke — an undo that quietly reverses nothing is worse than no undo, because people stop checking. **(d) Say what is outside the boundary, not what is inside it.** The panel's footer names the acts that cannot be undone rather than listing the ones that can; a positive list reads as exhaustive and silently becomes wrong the moment a seventh gesture ships. Corollary for specs: trigger the act through its stable control, not its keybinding, when the keybinding is not what you are testing — ambient DOM focus plus a background `refetchInterval` lets a roving tabindex re-seat focus between `focus()` and `press()`, so the keystroke reaches the wrong row and the act silently does not happen, one run in three, only under worker contention. Reference: `features/schedule/trail/SessionTrail.tsx`, `features/schedule/trail/trailStore.ts` (`newestUndoableEntry`), `hooks/useStructuralUndo.ts`, `e2e/schedule-structural-undo.spec.ts` — #2974, ADR-0880.
