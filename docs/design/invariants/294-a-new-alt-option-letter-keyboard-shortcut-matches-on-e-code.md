# Rule 294 — A new Alt/Option+letter keyboard shortcut matches on `e.code`, never `e.key`

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A new Alt/Option+letter keyboard shortcut matches on `e.code`, never `e.key`.** Holding Option while pressing a letter on macOS composes `KeyboardEvent.key` into an accented/special character in every browser — Option+A delivers `key: 'å'`, not `'a'` — so a binding keyed on `e.key.toLowerCase()` silently never fires there; the binding is dead on the platform most of this team develops on, with nothing in a synthetic-event unit test to catch it unless the test constructs the composed key (a test built with `key: 'a', altKey: true` and no `code` passes even though production is broken). `e.code` is the *physical* key — layout- and OS-independent — so resolve an Alt+letter combo through it instead (`e.code === 'KeyA'` → `'a'`); arrow keys, function keys, and punctuation (`?`, etc.) are unaffected by Option composition and stay on `e.key`. Reference: `features/schedule/useScheduleKeyboard.ts`'s `resolveKeyToken` (Alt+A Author/Read toggle, #2727 — found by `ux-review`, since the existing regression test synthesized the un-composed key and passed against the broken binding).
