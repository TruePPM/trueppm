# Rule 323 — When a count is narrowed to a subset, re-check every predicate that reads it

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**When a count is narrowed to a subset, re-check every predicate that reads it.** Redefining an existing variable from a total to a subset (`tasks_created` → `plan_tasks_created`; "all rows" → "rows excluding the parked ones") silently invalidates every `count > 0` gate written against the total, and the newly-excluded case is exactly the one nobody demos. The failure is a CTA, empty-state branch, or navigation affordance that vanishes for a state that is now real and reachable — and nothing catches it: the types are unchanged, the tests still pass because none of them exercises the excluded case, and a screenshot of the happy path looks identical. This is how the CSV wizard's "View schedule" button disappeared for exactly the import that most needed it (#2732: every row unresolvable → zero plan tasks, but the operator's data IS in the outline, under the Import review branch the result step had just told them about). When you narrow a count, grep every read of the identifier — including gates in sibling components that receive it as a prop — and decide the predicate for the excluded case explicitly, rather than letting it fall out of the arithmetic. Reference: `components/import/CsvImportWizard.tsx` (`tasksCreated` / `parkedCount`, `WizardFooter`).
