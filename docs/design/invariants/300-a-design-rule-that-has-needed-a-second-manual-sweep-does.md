# Rule 300 — A design rule that has needed a second manual sweep does not have a working mechanism — fix the mechanism in …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Foundations*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A design rule that has needed a second manual sweep does not have a working mechanism — fix the mechanism in the same MR, and watch it fail before you fix the violations.** Four rules recurred here 2–6 times each and every sweep fixed only the sites (#2858). The reason each one came back was mechanical, not cultural, and none of the four was visible from the violation list: `tiny_text_offenders()`'s regex read `text-\[([0-9]|10)px\]` and **could not match `text-[11px]` in any file, in any tree** — six dedicated sweeps (#434, #650, #1023, #1229, #1332, #2043) ran against a gate that was structurally blind to the thing they were sweeping for, and reported green each time; the standalone-trigger focus guard was a Playwright spec asserting **two hardcoded controls** (#2292), which cannot sweep because a behavioral spec only reaches the routes it navigates; the `bg-semantic-{state}/N` tint had **no check at all**; and the "page swallows a fetch error as an empty state" class was fixed one page at a time across #1764/#1937/#1942 with nothing counting the population. **And widening a pattern once does not make it complete — check the SHAPE, not the instance you were sent to fix.** #2858 taught `TINY_TEXT_PAT` the two-digit case and left `px\]` bound directly to the digits, so `text-[10.5px]` and `text-[9.5px]` still matched nothing anywhere; two shipped that way and it took #3475, seventeen releases later, to add `(\.[0-9]+)?`. The sweep that closes a hole is the one moment anybody is looking at the regex — enumerate what the value can *look like* (two digits, a fraction, a unit that is not `px`) and add a fixture per shape, rather than adding the one literal that failed. Three consequences, all load-bearing:
- **(a) A gate you have not seen fail is not a gate.** Run the widened/new check against `origin/main` and confirm it reports the offenders *before* you fix them, and record the before/after counts in the MR. A pattern that silently narrows reports 0 and **passes** — indistinguishable from a clean tree, which is precisely how the 11px hole survived six sweeps. Every pattern in `scripts/check-design-system-v2.sh` therefore ships with an inline both-direction self-test (`hex_pat_self_test`, `pipeline_self_test`) that runs before any count is produced and exits non-zero if a fixture stops matching; a lint-rule gate ships the equivalent as fixtures that import the real selector array, never a copy (`src/test/standaloneTriggerFocusRule.test.ts`).
- **(b) Match the mechanism to what the rule can decide.** A textual rule (a class string) is a grep; a structural one ("this element is a disclosure trigger") is an AST selector in `eslint.config.js`, where `// eslint-disable-next-line` with a reason is the escape hatch; a rule whose predicate needs *semantic* judgement — "is this a primary data surface?" — is decidable by neither, so gate the **population size** as a ratchet instead of pretending to zero-tolerance. A zero-tolerance check that misfires gets disabled, taking the real protection with it.
- **(c) Separate "is this the sanctioned exception?" from "is this a violation?" mechanically, or the exception list becomes the hole.** Each carve-out is a named file or tree in the filter (`features/settings/` for rule 118, `features/schedule/` for rule 137; `StatusBar.tsx` was one for rule 45 until #3475 retired it — a carve-out is retired by deleting the filter line, so the gate reds if the exception comes back), never a per-component judgement — and interaction-state variants (`hover:`, `focus:`) are stripped before counting resting fills, which is what separates 7 real `bg-semantic-*/N` offenders from 32 legitimate hover washes.
