# Rule 366 — Raising a control to the 44px touch floor is a LAYOUT change in every container that control renders in — …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**Raising a control to the 44px touch floor is a LAYOUT change in every container that control renders in — enumerate them and measure each, because the one that overflows does it silently.** The Duration cell's `d`/`h` picker was `h-7 w-8` with no coarse branch, so it stayed 28px on a tablet (#3212). Sizing it from the row-height owner is the easy half; the half that bites is that the pair went from 66px to 90px wide, and a control's width is a claim on a box somebody else owns. The issue named one layout — the 540px drawer, where the Duration track is 126.25px and the cell's content box 97px — and there the 90px group fits with **7px** to spare. It also renders in a second layout nobody named: `TaskDetailDrawer` renders its `content` **twice**, once per shell (`hidden md:flex` 540px slide-in, `md:hidden` 85vh bottom sheet), and in the 356px sheet the strip's four tracks left an **89px cell with a 60px content box** — which the *old* 66px picker already overflowed by 6px and the new one would have overflowed by 30. A touch-target fix that lands on the tablet and regresses the phone has not met the floor; it has moved the failure to the device the floor exists for. Four obligations. **(a) Enumerate the containers before you pick the size, and count SHELLS, not components** — one component with a breakpoint-branched shell is two layouts, and grepping the component's importers finds one of them. **(b) The container yields, not the target.** 44px is not negotiable, so the fix is the strip becoming `grid-cols-2 md:grid-cols-4` below the breakpoint where four tracks stopped fitting — never a smaller control, and never a horizontal scroller for a four-value read-only strip. **(c) The overflow is invisible to every gate we run.** The grid item is `min-w-0` and the control `shrink-0`, so the box neither clips nor scrolls — it paints over its neighbour, and the picker, the Float cell and the strip all keep boxes and all pass `toBeVisible()` (rule 354(e)). Assert **non-intersection of `boundingBox()`s**, in Playwright, at each layout's own viewport; jsdom resolves no lengths, so the vitest half pins the custom property and the class shape and nothing else (rule 330(c)). **(d) A pre-existing overflow is a finding, not a baseline.** The 6px was already shipping and nobody had measured — which is the same reason #3211 exists, one release earlier, on this same cell. When a fix's arithmetic says "it still fits", that sentence is the trigger to open a browser, not a substitute for having done so. Reference: `features/schedule/scheduleConstants.ts` (`resolveUnitSegmentSize`), `features/schedule/duration/DurationUnitPicker.tsx`, `features/schedule/TaskScheduleStrip.tsx` (the two-up strip), `e2e/duration-drawer-edit.spec.ts` (540px, 390px and fine-pointer measurements) — #3212, surfaced by `ux-review`.
