# Rule 224 — A route-level error surface (`errorElement`) that offers recovery actions must move focus to its heading on …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A route-level error surface (`errorElement`) that offers recovery actions must move focus to its heading on mount — the erroring subtree unmounted, dropping focus to `document.body`, so keyboard/AT users otherwise cannot reach the recovery CTAs.** When a route subtree throws (or a lazy chunk fails to load) React Router swaps it for the route's `errorElement`; the element that had focus (the `NavLink` the user just clicked, a button) unmounts, so focus falls back to `<body>`. An error surface whose whole point is recovery (Reload / Go to home) must pull focus to itself in a mount `useEffect` — a `tabIndex={-1}` `<h2>` with a `focus:` ring (**not** `focus-visible:`, which a browser may withhold on a *scripted* `.focus()` — the rule-204(b) / rule-214 caveat) — or the keyboard/screen-reader user has to blind-Tab from `body` to reach the only actions on the page. This is the inverse of the calm `EmptyState` (rule 177), which is a zero-data view with no required action and therefore does **not** grab focus; an `errorElement` is `role="alert"` (assertive, an error the user landed in) and self-focuses, whereas an empty state neither takes focus nor carries a region of its own — since ADR-0989 it announces politely, once, through the shell's persistent region on the transition into empty (rule 177). The contrast that justifies the focus move is unchanged and is worth stating in its own terms: an error surface **is the user's destination and holds the only actions**, so focus must be there; an empty surface is a state of the destination they already reached, so moving focus would take it from whatever they were using. Reference: `components/RouteErrorBoundary.tsx` (the `headingRef` mount-focus + `isChunkLoadError` chunk-vs-generic copy split), wired as `errorElement` at the route-tree root, on `ProjectShell`/`ProgramShell`, and — since #2834 — on every shell child via `shellRoutes()` (rule 298).
