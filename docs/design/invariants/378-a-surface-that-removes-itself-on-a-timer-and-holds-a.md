# Rule 378 — A surface that removes itself on a timer and holds a focusable control must take its dwell from …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Controls and composition*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A surface that removes itself on a timer and holds a focusable control must take its dwell from `usePausableAutoDismiss` — a bare `setTimeout` is the defect, and it is invisible in review because the surface it deletes is correct.** `ToastHost`'s pill paused on hover and focus-within from #2203, and rule 356(d) already stated the invariant (*"an element with focus inside it is never auto-removed"*) — but it stated it as a property of `toastStore`, so the Schedule's private `ScheduleActionToastRenderer`, which renders its own toast rather than the global host, kept an unconditional `window.setTimeout(() => setToast(null), duration)` for a whole release (#3356). An Admin tabbing toward the cascade's Undo lost the button out from under the focus ring at the dwell and focus fell to `<body>` — WCAG 2.2.1 *and* rule 368's failure, on the one control that was the only route to that undo. Four parts. **(a) The remedy is the extraction, not a second copy.** `components/Toast/usePausableAutoDismiss.ts` owns the timer, the hover/focus split (releasing one while the other holds must not resume), the full-dwell restart on leave, and the `relatedTarget` containment check; both surfaces call it and neither reimplements it. This is rule 300(b): the class recurred once already, and a shared hook is a structural mechanism where a prose rule naming one file was not. **(b) A host that OUTLIVES its surface needs the pause flags cleared, and a host keyed per item does not.** `ToastPill` remounts per `toast.id`, so its state resets for free; the Schedule renders one renderer for every toast, and a pill dismissed out from under the pointer fires no `mouseleave` and no `focusout` — so `hovered` would stay true forever and the *next* toast would never dismiss at all. That is what the hook's `active` argument is for; a caller that passes a constant `true` is asserting it is the first shape. **(c) A pausable dwell makes focus a MODE, so the focus ring on the control is load-bearing, not decoration** — pausing something the user cannot see they paused is worse than not pausing. **(d) Prove the pause with a negative control in the same commit.** "Still visible after the dwell" passes trivially against a surface whose timer is simply broken, so the spec must also show it dismisses once hover and focus are released; and park the pointer away from the surface before asserting the *focus* pause, or hover is what is holding it. **The class had five members and the sweep is stated with its denominator:** all 96 `setTimeout`/`setInterval` call sites in `src/**/*.tsx` were triaged, five removed a surface holding a focusable control — `ToastHost` (already correct, #2203), the Schedule action toast, the Grid bulk-action toast (`GridView`/`GridToast`), the retro LWW reconcile toast (`RetroBoardSurface`), all four now on the hook — and `features/grid/ConfirmDeleteStrip.tsx`, which took the hook on an **opt-in** in #3394 — see (e). **(e) When the surface focuses ITSELF, discriminate the autofocus by ORIGIN, not by a timing window, and do not let the hook grow an option for it.** `ConfirmDeleteStrip` focuses Confirm on mount, so a verbatim focus-within pause reads its own autofocus as engagement and the strip never expires — and expiry there is the *safe* direction, because the timeout **declines** a delete. The remedy is `runWithoutPausing(fn)`, which brackets a synchronous `focus()` dispatch with a ref the `onFocus` handler reads: React runs its root `focusin` listener inside `HTMLElement.focus()`, so the bracket contains exactly that one event and nothing else. Three things about the shape. **It is opt-in by CALL, not by option** — the flag can only be set from inside `runWithoutPausing`, so a caller that never invokes it is byte-for-byte unchanged, which is what let a fifth surface join without re-testing the four already on the hook; prefer this to an `ignoreProgrammaticFocus` boolean that every call site has to be reasoned about. **A pausable dwell makes the countdown ANIMATION a claim** — the bar must both stop draining while paused (`animationPlayState`) *and* restart from 100% on resume (remount via `key`), because the hook restarts the full dwell rather than a remainder, and a bar resuming from 40% promises a deadline the timer will miss by 3s. **The honest residual was written down, and then it was closed**: a strip left with the mount focus untouched still expired under the focused button, so a screen-reader user who only *listened* still dropped to `<body>` — 2.2.1 closed, 2.4.3 open. #3445 closed 2.4.3 the way rule 368(e) describes, by handing focus to the bulk **Delete** button on the commit after the strip unmounts, from a single `handleCancelDelete` that all three exits (dwell, Cancel, Escape) now route through. Note what that means for this rule: **discriminating the autofocus was the right call and it was not the whole fix** — a pause that cannot distinguish engagement from its own `focus()` and a handoff that cannot fire until the destination mounts are two different mechanisms, and a surface that focuses itself needs both. When you convert the next one, ask where focus goes when the dwell wins, not only whether the dwell should have won. Note also that this was the one `autoDismiss.conformance.test.ts` ALLOWLIST entry naming a **pending decision** rather than a permanent exemption; landing the decision had to move it to the positive `IMPORTS_HOOK` list, because an allowlist nobody ever empties is a backlog with a guard's name on it. **(f) Converting a hand-rolled timer onto the hook silently fixes a SECOND defect you should look for and pin: the bare `setTimeout` effect almost certainly listed its `onDismiss` in the dependency array.** `ConfirmDeleteStrip`'s did, and `GridView` passes `onCancelDelete={() => setDeletePhase('idle')}` — a fresh arrow every render — so *any* re-render of the Grid tore the timer down and re-armed it, and on a polling project the strip could stay open forever. The hook's `dismissRef` removes that, which means the deadline the shrink-bar draws is only now a deadline the code can keep. Assert it in the same commit, advancing **only in slices shorter than the dwell with a re-render between each and no full dwell after the last** — a trailing full-dwell advance lets the buggy version pass. **The reason to hunt for it deliberately is that it makes an e2e written the obvious way VACUOUS**: a Playwright test that hovers the surface and asserts it is "still visible after the dwell" passes against the pre-fix build, because the re-arm kept it visible for an unrelated reason — it was watched doing exactly that here. The assertion that discriminates is the countdown animation's computed **`animation-play-state`**, which is `paused` only when the pause is real and reads from an element the pre-fix build does not render at all. Which is the general form of 378(d): in a browser, assert the MECHANISM's own state, not the surface's survival. **The class has its own guard now** — `a dwell is not re-armable by an unrelated re-render` in `autoDismiss.conformance.test.ts` matches a `useEffect` that arms a `setTimeout` *and* names an `on*`/`handle*`/`*Callback` identifier in its dep array. Two things it teaches. `react-hooks/exhaustive-deps` **requires** the dependency that causes this, so the lint that normally catches a stale closure is what produces the defect — the remedy is a ref, never a suppression. And its first draft let the match run past the closing `}, [` into the *next* effect's dep array and reported five files, every one a focus-timer effect keyed on plain state sitting above an unrelated `onClose` effect; both `(?!\}, \[)` bounds are load-bearing and pinned by a must-not-match self-test. Swept 1228 non-test files under `src/`: **two members — `ConfirmDeleteStrip` (fixed) and `features/schedule/RecalcPercentChip.tsx` (allowlisted, #3447).** **The sweep is a mechanism, not a one-off** — `components/Toast/autoDismiss.conformance.test.ts` source-scans the tree for a timer that clears a surface (`setTimeout(() => setToast(null), n)`) or calls its own dismiss, and fails on any file that is neither on the hook nor on a four-entry `ALLOWLIST` whose entries each state a reason. Two things about it are the actual lesson. **A first draft matched 30 files** — every `setTimeout(() => setCopied(false))` label swap in the tree — which is the over-broad check rule 300(b) says gets disabled, taking the real protection with it; the pattern was narrowed to names the author chose for a *surface*, because "does this hold a focusable control" is not decidable by regex, and the allowlist carries what the regex cannot. And **the positive half must match the `import`, not the identifier**: every converted file also names the hook in a comment explaining why it uses it, so a `toContain('usePausableAutoDismiss')` passes on a file that deleted the call and kept the paragraph — caught only by watching the guard fail against the pre-fix source, which is the whole of rule 300(a). Reference: `components/Toast/usePausableAutoDismiss.ts`, `components/Toast/ToastHost.tsx`, `features/schedule/ScheduleView.tsx` (`ScheduleActionToastRenderer`), `features/grid/GridView.tsx`, `features/sprints/RetroBoardSurface.tsx`, `features/grid/ConfirmDeleteStrip.tsx` — #3356 and #3394, surfaced by `ux-review`.
