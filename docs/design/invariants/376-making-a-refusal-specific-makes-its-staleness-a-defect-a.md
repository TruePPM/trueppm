# Rule 376 — Making a refusal SPECIFIC makes its staleness a defect — a surface showing the server's own sentence must …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**Making a refusal SPECIFIC makes its staleness a defect — a surface showing the server's own sentence must RETIRE it when the thing it describes changes, and the mutation hook will not do that for you.** Rule 375 is right that a hardcoded sentence throws away the server's reason and right that the fix is the prop type. What it does not carry is the consequence, and the two live at opposite ends of one change: `"Save failed"` going stale is harmless noise, while `"Enter a valid date."` still on screen after the user entered a valid date is the product **stating something false**, and `"You do not have permission to edit this task."` on a row the user never submitted is worse. TanStack's mutation `error` persists until the next `mutate()` or an explicit `reset()` — nothing clears it on an edit, and nothing clears it when the surface changes which entity it is editing. So a review that confirms the server's sentence now reaches the user has confirmed nothing about whether it is still **true**. Three obligations. **(a) Clear the refusal on the edit that could have fixed it, at the ONE setter every field goes through.** Wrap `useDirtyDraft`'s `setField` rather than each control's `onChange`, so the next field added inherits it; a refusal describes a submitted payload, and the moment that payload changes the statement is unowned. **(b) A surface that swaps its subject WITHOUT remounting carries the previous subject's refusal across, and the tell is the absence of a `key`.** `TaskDetailDrawer` holds its task in state precisely so a swap-while-dirty can lag the prop, and `ScheduleView` renders it with no `key` — so one `useUpdateTask()` instance spans every task the user visits. The backlog drawers escape this only because their callers pass `key={selectedStory.id}`; that is the difference, not anything in the drawers. Key the reset on the rendered id, not on each swap path (clean adopt, dirty-guard discard, Save & open), so a fourth path inherits it — and **skip the first run**, or a spec that preloads a refusal has it wiped before its first assertion and reads as the feature working. **(c) Two mounted surfaces must not both hold the same refusal.** The swap guard fires only while dirty, which is exactly when `DialogFooter` is mounted, so a refused *Save & open* inserts two `role="alert"` nodes with identical text in one commit — announced twice, one of them behind a scrim. When a modal takes over a commit it takes over the refusal: pass `null` to the surface underneath. **Corollary — a mock that models `reset()` as a bare spy cannot see any of this.** The mutation mock must actually clear the error the way TanStack does, or a call-count assertion passes while the sentence is still on screen; and put the `mockClear()` in `beforeEach`, never inside the spy's own implementation, where it erases the record it is being asserted on. Order matters in the spec too: set the refusal **after** the edit that mounted the bar, because obligation (a) means an edit-then-assert spec now retires its own fixture. **(d) Mount the live region before it has anything to say — where the host outlives the refusal.** Rule 335's hazard applies to a `role="alert"` too: a region inserted together with its content is announced inconsistently, and for an AT user that announcement *is* the refusal. `BulkEditSheet` already did this correctly for its `bulk-owner-refusal` region and then got it wrong for `bulk-edit-error` 400 lines away in the same file — the tell that this is a per-surface habit rather than a component property. `RefusalAlert`'s `persistent` flag is therefore **opt-in, not the default**: pass it where the host is already open when the write is refused (a sheet, a popover), and leave it off where the host mounts *with* the refusal (`{dirty && <DialogFooter/>}`, a swap guard that fires on the swap), because there the flag would promise a guarantee it cannot keep. `empty:hidden` keeps the layout cost at zero either way. Reference: `features/schedule/TaskDetailDrawer.tsx` (`lastSubjectRef`, the wrapped `setField`, `swapGuardOpen ? null : saveRefusal`), `features/project/backlog/ProductBacklogPage.tsx` (`key={selectedStory.id}` — the working counter-example), `features/programs/backlog/components/DetailView.tsx` (`setSaveError(null)` at the top of `save()`) — #3332, surfaced by `ux-review`.
**(a) Move the DECISION into the record, not just the words.** A refusal is `{ message, detail, retryable }` because the button label is part of the answer: collapsing it to a string discards the only bit that separates "Retry" from a dead end, and a surface handed a string has no way to recover it. `retryable` is `!isClientRejection(error)` plus the 408/429 timing carve-out (rule 372a) — computed once, in `lib/writeRefusal.ts`, never re-derived at a call site.
**(b) The FALLBACK is the caller's, and it is the only thing that should be.** `describeWriteRefusal(error, fallback)` takes the sentence for "the server sent nothing readable" as an argument because that is genuinely per-surface ("Couldn't save the epic." / "Couldn't run the simulation."), and the optional `structuredDetail` reader is the same shape for a surface with machine-readable fields to spend. Everything else — the DRF body walk, the HTML-page guard, the length ceiling, the retryable predicate — is not per-surface and must not be a parameter, or the copy comes back one branch at a time.
**(c) A boolean `isError` mock cannot see this class, and it is what let three suites stay green through it.** `useUpdateTask()` was destructured as `isError: saveFailed` and the tests mocked `{ isPending, isError }` — so every spec exercised the *slot* and none of them the wiring, exactly rule 372's "passing a finished string in as a prop tests the slot". Mock the **real `error` object** (`src/test/axiosError.ts`'s `axiosRefusal(status, body)` builds a genuine `AxiosError`; a hand-rolled `{ isAxiosError: true, … }` passes some branches and skips the `response.status` ones), and assert both directions per surface: the server's own sentence is present, AND the retry advice is **absent** on a 4xx. The negative half is the one that regresses.
**(d) Widening a fixed-height bar is part of the change, not a follow-up.** A footer that was `h-14` because its error slot held four hardcoded words will **paint a two-line refusal over its own buttons** — no clip, no scroll, both boxes still passing `toBeVisible()` (rule 354c/e). `min-h-14` + `py-2` + a `min-h-10` button row is the same 56px whenever there is no refusal, and grows only when there is.
**(e) A refusal rendered inside a `<button>` is announced by nothing.** `MobileMonteCarloCard` puts its whole card in a button carrying an `aria-label`, which **replaces** the subtree for name computation — so the failure text inside it was invisible to AT no matter how it was worded. The `role="alert"` goes outside the button (rule 372b's sibling rule, arriving through a different door). Reference: `lib/writeRefusal.ts` (`describeWriteRefusal`, `isRetryableFailure`), `components/dialog/RefusalAlert.tsx`, `components/dialog/DialogFooter.tsx` + `UnsavedChangesDialog.tsx` (the retyped props), `src/test/axiosError.ts`, `e2e/schedule-bulk-edit.spec.ts` ("a refused batch") — #3332, after #3302.
