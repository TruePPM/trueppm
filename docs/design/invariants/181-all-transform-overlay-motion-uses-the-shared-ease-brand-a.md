# Rule 181 — All transform/overlay motion uses the shared `ease-brand` + a named `duration-*` token, and the four entrance …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Motion*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**All transform/overlay motion uses the shared `ease-brand` + a named `duration-*` token, and the four entrance keyframes live in `globals.css` and are applied under `motion-safe:` — never hand-rolled per call site, never ungated.** The v2 motion layer is centralized so it stays consistent and honors the motion contract (rule 70: motion only, never content).
- **Tokens (`tailwind.config.ts`):** `ease-brand` = `cubic-bezier(.2,.7,.2,1)` is the standard easing for every transform/overlay transition; durations are the named `duration-fast` / `duration-base` / `duration-slow` (120 / 200 / 320ms, aliasing `--dur-1/2/3`). Do not hard-code `duration-150`/`duration-200` or rely on Tailwind's default ease for v2 surfaces. The `checkpop` spring is the one exception — it uses the overshoot ease `cubic-bezier(.34,1.56,.64,1)` for its 1.22 bounce, baked into the keyframe.
- **Keyframes (`globals.css` `@layer utilities`, beside `cmdk-in`/`empty-state-in`):** `checkpop` (220ms, task-complete spring), `toast-rise` (240ms, global toast entrance), `modal-scale-in` (180ms, dialog/modal panel), `save-bar-slide` (220ms, docked save bar). Each has a paired `.animate-*` class applied at the call site under `motion-safe:` — the keyframe itself carries no `@media` guard (the gate is at the class layer, matching the established pattern). Do not add the dead `tailwindcss-animate` utilities (`animate-in`/`fade-in`); they emit no CSS.
- **Micro-interactions:** the shared `<Button>` presses via `motion-safe:active:translate-y-px`; interactive cards (`ProgramCard`, `BoardCard`) lift via `motion-safe:hover:-translate-y-px`. **No shadow on the lift** (rule 1) — the card's own border (or a `hover:border-*` emphasis on a single-state border) supplies the depth cue the prototype's hover shadow would have; on a card whose border is state-driven (e.g. `BoardCard`'s critical/dashed border) use translate-only so the lift never overrides the state border. `shadow-pop` remains allowed only on true pop surfaces (toast/popover/drawer/modal/command palette — rule 1's standing exception).
- **Coexisting transitions:** when a transform animation must share an element with an existing color/opacity transition, use ONE multi-property declaration (`transition`, or `transition-[opacity,transform]`) — never stack `transition-transform` on top of `transition-colors`/`transition-opacity`, which collide on `transition-property` (the later one in the cascade silently wins and drops the other).
