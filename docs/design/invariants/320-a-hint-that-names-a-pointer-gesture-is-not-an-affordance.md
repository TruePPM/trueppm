# Rule 320 — A hint that names a pointer gesture is not an affordance — every gesture-only path needs a NAMED action …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A hint that names a pointer gesture is not an affordance — every gesture-only path needs a NAMED action beside it, and the hint must name the action first.** The board's backlog rail is the case that makes this an invariant rather than a courtesy: an inbox exists to catch an item that has no place yet, so *getting it out again* is the surface's entire job, and its only promotion path was "Drag right onto a phase to promote to To do" — a sentence describing the one route a keyboard user cannot take and a phone user finds fiddly (#2952). The mutation was reachable; nothing 403'd; every test passed. What was missing was a control, and a paragraph is not one. Four obligations. **(a) The non-drag route performs the SAME move, through the same mutation.** `File under…` re-parents and lands in To Do by calling the board's own `updateStatus`, including the sprint assignment that rides along on a drag (#429) — a keyboard path that promoted *differently* would be a second implementation of the surface's central gesture, which is the drift rule 316 exists to stop, arriving through the accessibility door instead. **(b) Name the action first and the gesture second.** The hint is not deleted — a pointer user's fastest route is still the drag — but a sentence that opens with the gesture teaches the gesture as *the* way, and whoever cannot perform it reads it as "not for you". **(c) The action lives where the object is.** Per-card, in the `···` menu, on the row it acts on: a rail-level button would need a selection model to say *which* idea, and a surface that already has a focused card does not need a second concept. **(d) Gate it by ABSENCE, not by a disabled item (rule 302), and render no menu at all when it would be empty** — a `···` that opens onto nothing is worse than no `···`, and a viewer must not be shown the shape of an action they cannot take. Corollary for the trigger: a single button that says `aria-haspopup="dialog"` while announcing itself as "Actions for X" is already lying about being a menu — the moment a second action exists, make it a real `role="menu"` with roving focus and Escape-to-trigger rather than stacking a second corner button. Reference: `features/board/BacklogBand.tsx` (`BacklogCardMenu`, `FileUnderTarget`), `features/board/BoardView.tsx` (`handleFileUnder`, next to `dropOnCell`), `e2e/board-backlog-band.spec.ts` — #2952, design `v6-cases.js` case 18.
