# Rule 330 — A touch target built as a `before:` pseudo-element must be SIZED, never `inset`-ed — an inset box is `size − …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Accessibility floors*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A touch target built as a `before:` pseudo-element must be SIZED, never `inset`-ed — an inset box is `size − 2×border` wide, and no vitest assertion in this repo can see the difference.** The row-edge insert `+` on the Schedule outline is a 16px disc that cannot grow (it straddles the row boundary, so a 44px circle would cover the name cell of the rows on *both* sides of it), so its target is a `before:` box drawn around the mark. It shipped as `before:-inset-3.5`, and `16 + 2 × 14 = 44` is the arithmetic that made that look correct. In a browser it measured **42**: an absolutely positioned pseudo-element resolves `inset` against its **padding** box, and Preflight's `border-box` sizing puts the control's 1px `border` *inside* its 16px border box — so the containing block is 14px, not 16, and the box came out two pixels under the floor for the control's entire life. Three obligations. **(a) Size the box, do not inset it.** `before:w-[var(--x)] before:h-[var(--x)]` with `before:left-1/2 before:top-1/2 before:-translate-x-1/2 before:-translate-y-1/2` is immune to the border, to any padding added later, and to the disc's own size; the inset form silently subtracts whichever of those changes. This is rule 315's `inset-y-0` corollary — *size a target from an explicit length, not from insets* — reaching a second geometry. **(b) The size comes from the row-height owner through a CSS custom property, not a Tailwind literal.** A Tailwind class is a static string, so writing the 44 in it is a module-scope capture of a runtime value (rule 315(b)); emit `--insert-tap-size` from `scheduleConstants` in the inline `style` and let the arbitrary-value class read it. **(c) A browser is the only instrument that can check this — jsdom renders no pseudo-element geometry at all**, so a vitest suite can pin the *mechanism* (the custom property, the class shape, the absence of any `before:*inset*`) and nothing more; the measurement belongs in Playwright via `getComputedStyle(el, '::before')`, paired with an `elementFromPoint` hit test in the overhang so a box that exists but sits behind something still fails. The general form: **when a gate is structurally blind to a property, the unit test asserts the mechanism and a browser asserts the value — do not let the mechanism assertion read as coverage of the value** (rule 300). **(d) The same blindness covers HIDING mechanisms, and there it is an accessibility contract rather than a measurement.** jsdom applies no stylesheet at all, so `sr-only` and `hidden` are indistinguishable in vitest: both leave the text in the DOM and in the computed accessible name, and swapping one for the other leaves the suite green. That is not a missing assertion anyone can add — the information is not present. When a surface hides text *visually while keeping it for assistive tech* (an icon-only rail, a visually-hidden heading, a label that survives a collapse), the vitest half asserts the **class** (`toHaveClass('sr-only')`, `not.toHaveClass('hidden')`) and a browser asserts `getComputedStyle(el).display !== 'none'`. **Two traps specific to this case.** First, `.not.toBeVisible()` is the wrong Playwright assertion for `sr-only`: it clips to a 1px box rather than hiding, and Playwright counts a 1px box as visible — measure `getBoundingClientRect().width <= 1` instead. Second, and the one that quietly voids the whole test: if the element also carries a `title` (the tooltip an icon-only control wants anyway), `title` is an **accname fallback**, so `getByRole(…, { name })` resolves whether the label is `sr-only` or `display:none` — the accessible-name assertion passes against the defect and only the computed-display assertion fails. Verified by mutation on #3279; leaning on `title` alone is the weak contract, since it is last in the accname order and screen readers honor it inconsistently.
