# Rule 377 — A control whose field has NO reader is a third inert state — render no control at all, for every role, with a …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Surface states*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A control whose field has NO reader is a third inert state — render no control at all, for every role, with a plain sentence inside the row saying nothing reads it. It is neither rule 122's disabled stub nor rule 361's version-badged inert arm.** Both of those assume the capability is *coming*: 122 dims a stub and links a tracking issue, 361 keeps the arm present so the geometry does not move when the named release lands, and each hands the user a thing to wait for. Neither fits the case where the column persists, the API echoes it, the methodology default resolves it — and **nothing in the product ever reads it**, with no issue filed to change that. Here a save is *accepted* and changes nothing, which is worse than a refusal, because a refusal is at least information. Rule 302 does not reach it either: 302 splits on *who the user is*, and this splits on *whether the field has a consumer* — a property of the field, identical for Owner and Viewer, so it must take precedence over the rights branch rather than sit inside it. Five obligations. **(a) Render no editable control, for every role including the one that may write it** — not a `disabled` toggle, not `aria-disabled`, not a dimmed switch. 361(c)'s case for keeping a named, focusable control is that the refusal must be reachable at the moment of the attempt; with nothing to attempt there is no refusal, and a control that dims *for an Admin* teaches them their role is the problem when the field is. **(b) The replacement is a NAMED region, never a bare `<div>` with an `aria-label`.** A div is `role="generic"`, where browsers drop the name — so a status row whose children are all `aria-hidden` announces *nothing*. Give it `role="group"` with an `aria-label` carrying value plus provenance. The trap is that **jsdom computes that name anyway**, so a `getByLabelText` unit test passes on the broken form and pins it: assert `getByRole('group', { name })`, which fails on the div. This is how the pre-existing read-only branch of `InheritableToggleField` stayed silent to a Member through its own passing tests. **(c) Keep the explanation as exposed CONTENT inside the region; `aria-describedby` is belt-and-braces, not the mechanism.** Descriptions are surfaced reliably on *focus*, and nothing here takes focus — DOM containment is the guarantee that actually holds, so never `aria-hidden` the sentence and never move it outside the group on the strength of the binding. **(d) The accessible name must not end "View only."** — that sentence promises the value is enforced for someone with more rights, which is exactly the assurance this state withdraws. End it with the withdrawal itself ("Not enforced."). **(e) Say what is true today, and never "yet".** No future tense, no "coming soon": 361(a)'s future tense is licensed by a version checked against `overview/roadmap.md`, and a state with no filed issue has no version to check — "yet" is a version claim with nothing behind it. Name what *would* make it real and cite the issue, or say plainly that none is open. Two corollaries. **The copy must describe the effect of the VALUE, not of the gesture** — a project that stored an override before the control was withdrawn has no path back to inherit, so "turning this off would hide nothing" is the wrong tense for the very state it is most needed in; state it once and make it true in every state. **And a section header is a control too:** a subtitle reading "each of these inherits unless you override it" is a present-tense capability claim that the first inert row three lines below contradicts, so scope it in the same change. Reference: `features/settings/components/InheritableToggleField.tsx` (the `notEnforced` branch, ahead of `!canEdit`), `features/settings/project/ProjectVisibilityPage.tsx` (`SURFACES` — and its module docstring, which lists each surface against its consumer so the next reader can *check* the claim rather than trust it) — #3376, surfaced by `ux-review`, extending rules 122, 302 and 361.
