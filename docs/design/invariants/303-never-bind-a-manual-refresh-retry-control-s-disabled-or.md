# Rule 303 — Never bind a manual refresh/retry control's `disabled` (or spinner) state to a query's raw `isFetching` when …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**Never bind a manual refresh/retry control's `disabled` (or spinner) state to a query's raw `isFetching` when that query also polls (`refetchInterval` set) — track a local "this fetch was user-initiated" flag instead.** TanStack Query's `isFetching` is true for *every* in-flight fetch, a background poll tick as much as the user's own click. Wire it to a native `disabled` and the control disables itself on every interval — and because browsers blur an element the instant it becomes disabled, a keyboard user resting on that button is silently ejected to an arbitrary point in the document, on a timer, for as long as the page stays open. Nothing catches this: the types are fine, a unit test that clicks once and asserts the handler fired passes, and a sighted mouse user never notices because the flicker coincides with data they were not watching. `refetchIntervalInBackground: false` does not help — it means the poll runs *only* while the tab is foregrounded, i.e. exactly while someone is interacting. So: set a local flag before calling `refetch()`, clear it when the returned promise settles, and gate `disabled` + the spin animation on that flag; or drop `disabled` entirely and let the icon-spin alone carry busy state, since a duplicate click during an in-flight fetch is deduped anyway. The same reasoning applies to any ambient hook state that is true for reasons other than the user's action. Reference: `features/settings/workspace/systemHealth/TelemetryCard.tsx`'s `LiveRefreshButton` (the corrected form — local `pending`, and a `role="status"` announcement fired only for a user-initiated refresh, because putting `aria-live` on the polled region itself would re-announce every tick). Known remaining offender: `SystemHealthOverviewPage.tsx`'s "Force refresh" button, which disables off the same polled query's `isFetching` (#2880 ux-review).
