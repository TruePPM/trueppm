# Rule 311 — A direct-manipulation gesture must state its CONSEQUENCE before release, and the same pointer position must …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Dialogs, focus and keyboard*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A direct-manipulation gesture must state its CONSEQUENCE before release, and the same pointer position must never be able to mean two things.** An insertion line is a position, not an outcome. On a tree, one pointer y legitimately means either "beside this row" or "inside this row" — and on the Schedule outline the second one also silently converts a leaf into a phase, which is a structural change the user never asked for and cannot see coming from a line. Four obligations, and the first two are what make this an invariant rather than a Schedule detail. **(a) Draw the destination, not the pointer.** The mark's position is derived from where the thing will *land* — for a tree that is the destination level's own indent origin, so "beside" and "inside" differ by one indent step at the same height and are distinguishable without color (rule 6.1); a preview that tracks the cursor tells the user where their hand is, which they already know. **(b) Name the outcome in words, on the element it happens to** — `↳ becomes a phase`, `into this phase` — and speak the same claim through a polite live region, because a chip pinned to a row a screen-reader user is not on says nothing. **(c) A refusal is stated, never silent, and never drawn as an offer**: mark the row that said no and say why (`a gate cannot hold work`), and suppress the insertion line entirely — a line over a target that will reject the drop is the exact failure the preview exists to prevent. **(d) The gesture is Pointer Events, and it adds no capability the keyboard lacks.** HTML5 `dragstart` never fires from a finger, so it ships a desktop-only gesture by construction; and where the drag reaches further than the existing keys do (⌥→/⌥← step one level against the row above; a drag can reparent anywhere) that extra reach needs its own non-drag route or it is a WCAG 2.1.1 failure — put it in the row menu, not in a fallback nobody finds. Corollary for the plumbing: resolve the drop where the rows are (the list), commit it where the *whole* dataset is (the view) — a virtualized list sees only visible rows, and an endpoint that wants a complete sibling set will 400 on the subset.
