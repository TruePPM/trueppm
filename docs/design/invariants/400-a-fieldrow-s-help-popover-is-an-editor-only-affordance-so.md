# Rule 400 — A `FieldRow`'s `help` popover is an EDITOR-only affordance, so every fact a read-only user needs lives in …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Signal encoding*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A `FieldRow`'s `help` popover is an EDITOR-only affordance, so every fact a read-only user needs lives in `hint` — a `help`-only row explains itself to Admins and to nobody else.** Both General pages define `fieldHelp` as `canEdit ? <FieldHelp …/> : undefined`, and they must: the form is wrapped in a `<StubFieldset disabled>`, and a `<fieldset disabled>` disables every descendant button including the ⓘ trigger, so rendering it below Admin would ship a dead affordance (rule 122). The consequence is easy to miss because it is invisible to the author, who is always testing as an Admin: a row carrying `help` and no `hint` renders to a Viewer as a bare label with **no explanation anywhere on the page**. This is rule 263(d) ("supplements, never replaces, the inline hint") restated as the invariant that makes it checkable — `hint` carries the sentence that changes what the user *believes*, `help` carries the full option set and the docs deep-link. The tell that a row is wrong is that deleting `help` deletes all of its explanation. Two corollaries. **The audience that needs the sentence most is the one that cannot open the popover**: on the row this rule came from, the fact is "Program lead is a display field and grants no access", and the reader most likely to misread it as the *Program Manager role* is precisely the below-Admin member who never sees the ⓘ. **And a `hint` you add is not associated by adding it** — it renders as an adjacent `<div>` with no implicit relationship, so take the `FieldRow` render-prop child and thread its `describedBy` onto the control (rule 269, WCAG 1.3.1 / 4.1.2); a control whose props cannot carry it needs an optional `describedBy` pass-through, not a hint left dangling. Population check at the time of writing: 28 rows across the program and project General pages carry `help`, and all 28 carry `hint`. Reference: `features/settings/SettingsShell.tsx` (`FieldRow`), `features/settings/{program,project}/*GeneralPage.tsx` (`fieldHelp`), `features/settings/components/MemberPicker.tsx` + `components/EntitySelectCombobox.tsx` (`describedBy`) — #3513, surfaced by `ux-review`.
