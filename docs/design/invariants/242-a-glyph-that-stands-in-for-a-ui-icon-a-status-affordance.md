# Rule 242 — A glyph that stands in for a *UI icon* — a status/affordance mark like a warning, lock, target, chart, pin, …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Iconography*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A glyph that stands in for a *UI icon* — a status/affordance mark like a warning, lock, target, chart, pin, or disabled sign — must be a house SVG from `components/Icons.tsx`, never a Unicode emoji.** Emoji render inconsistently across platforms/fonts (flat vs. glossy, differing metrics, some monochrome some multicolor), do not inherit `currentColor`, and never match the design-system stroke weight — so a functional emoji reads as a foreign, off-brand mark and can't be tinted to the surrounding text/semantic color. #1739 converted the affordance families to house icons: `⚠`→`WarningIcon`, `🔒`→`LockIcon`, `🎯`→`TargetIcon`, `📊`→`BarChartIcon`, `📌`→`PinIcon`, `🚫`→`BanIcon`, and the file-type mime map (AttachmentSection, `previewType`) to the `FileIcon`/`FileTextIcon`/`FileSpreadsheetIcon`/`FileImageIcon`/`FilePdfIcon`/`FolderIcon`/`PaperclipIcon` set. The recipe for an inline `<span aria-hidden="true">GLYPH</span>`: replace with `<Icon className="inline-block h-3 w-3 align-[-0.125em]" aria-hidden="true" />` (the `inline-block h-3 w-3 align-[-0.125em]` baseline-aligns the SVG like the emoji it replaces; a trailing space inside the old span becomes `mr-1`; preserve any existing span classes by merging them before the standard ones). Keep the glyph `aria-hidden` — the adjacent text or an `aria-label` on the wrapper carries the accessible name (rule 6). **Three carve-outs stay as emoji** (they are *content*, not icons): user-chosen **reactions** (`CommentSection` 👍), an **emoji-scale input** (`TeamHealthPulse` mood 😞😐🙂😀🤩), and third-party **brand logos** (GitHub/GitLab/Figma/Notion/Slack host marks — a separate brand-asset/licensing decision, tracked in #1748). The remaining long tail of functional glyphs is a phased follow-up (#1749) — convert **one glyph family at a time**, updating its e2e/vitest assertions in the same commit. **The sweep is complete (#1749, #2480).** Every functional-glyph family and every string-stored `icon:`/`glyph:`/`emoji:` field now holds a house SVG, including the mixed maps that stalled the earlier slices (`OBJECT_TYPE_META`, `EVENT_META`, the Gantt and Queue row menus, `CalmToolbar`/`BoardLensBanners`, `notificationFilters`). **The unblocking move on a mixed map is to type it by *meaning*, not by shape** — `OBJECT_TYPE_META`'s `□ ◇ △ ⇢ ◈ ↻` had only two same-shape house icons between them, and inventing six abstract geometric marks would have produced a column that says nothing; reusing the icon each object type already carries elsewhere (`RiskIcon`, `SprintIcon`, `RepeatIcon`, …) made it readable instead. **Convert a map whole or not at all** — a half-converted map puts an SVG next to an emoji inside one control, which is worse than either alone. Four things stay glyphs on purpose, and are *not* regressions: `forecastDelta`'s `▲ ▼ ◆` direction triple (a redundant-encoding channel, not an icon family), **keycap legends** (`⇥ ⌘D ⌫ ⇧+Tab` — those are keys), the decorative `◆` on `OSSChip`/`BuildModeEmptyState`, and `$` on the cost toggle (a currency denomination — baking USD into an SVG path is worse for i18n). Two lessons from the `✓` pass: (a) **take the inventory in a script, not `grep -P` with a multi-codepoint bracket class** — that undercounted by an order of magnitude here (it reported one glyph where 27 were live), so a phase can silently believe a family is finished; count per-codepoint and exclude comment lines. (b) **A glyph span is not always a plain wrapper** — when the span carries sizing/background/border classes (`w-4 h-4 rounded-full bg-…`, a checkbox box, a 44px badge) it is a *container*: keep it and nest the icon inside at an explicit size, rather than merging its classes onto the SVG (which yields conflicting `h-4`+`h-3` and `inline-flex`+`inline-block`). Where the "off" state hid the glyph with `text-transparent`, omit the icon instead — the box already holds the layout. When a family's mark distinguishes *kinds* of selection, give each kind its own shape (`RadioDotIcon` for a `menuitemradio` row vs `CheckIcon` for `menuitemcheckbox`; `HalfCircleIcon` for a partially-met three-state outcome) so shape carries the state, not tint alone (rule 6). When a test asserts on the old glyph text (`getByText('⚠')`), re-anchor it to the rendered SVG (`getByLabelText(/…/).querySelector('svg')` or `.closest('.inline-flex')?.querySelector('svg')`) or a `data-testid` on the container. Reference: `components/Icons.tsx`, `previewType.ts`, `features/schedule/sections/AttachmentSection.tsx`.
