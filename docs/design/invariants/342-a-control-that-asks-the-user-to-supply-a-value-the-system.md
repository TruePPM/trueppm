# Rule 342 — A control that asks the user to supply a value the system has already computed is friction wearing a form's …

> **Invariant.** Indexed from [`packages/web/CLAUDE.md`](../../../packages/web/CLAUDE.md), section *Signal encoding*. The index carries the rule's headline; this file carries its full text (#3744, ADR-0653 amendment). Binding everywhere, not only on the surface that produced it.

**A control that asks the user to supply a value the system has already computed is friction wearing a form's clothes — seed it, and offer the computed answer as a one-click commit.** The Unscheduled tray's `···` menu opened an empty `type="date"` input with its submit `disabled={!dateInput}`, so committing a start cost four interactions and required the planner to invent a date from nothing — while CPM's `early_start` for that exact task sat one panel away, and the write that commits it (`useCommitStartOrTodo.commitStart`) had already shipped for a different surface. Three obligations. **(a) Seed the field, never open it empty.** An input born with a disabled submit reads as "the system has no opinion", which is false here and usually false generally; the seed is the computed answer, and the fallback when none exists is the most common answer (today), not blank. Then the button is live on open and the user is *adjusting* rather than *originating* — and the disabled state means what it should, that they cleared it on purpose. **(b) When two default answers can differ, offer both and put the DATE in each label.** "Earliest" and "today" are the same day only when nothing blocks the task; a predecessor makes earliest later, a slipped plan makes it earlier, and a menu that says only "Start at the earliest" hides which case the user is in until the bar lands somewhere surprising. Collapse to a single item when they resolve to the same day — two entries with identical outcomes is a choice that cannot be made wrong, which is worse than no choice. **(c) Do not suppress the option that expresses a conflict.** "Start today" stays offered when the earliest is later: that commitment is unachievable, and the gap it creates between the committed and computed start is a real scheduling conflict the planner is entitled to state. A menu that silently removes the unachievable option prevents the user from expressing the very thing the schedule exists to surface. Corollary — the quick commit must announce. Its only visible proof of success is the row *leaving* the tray, which tells a screen-reader user nothing, and the sibling path beside it (backlog promote) had announced since #318; two paths writing one field with different feedback is the drift rule 341 is about. Reference: `features/schedule/UnscheduledTaskRow.tsx` (`quickActions`), `features/schedule/UnscheduledGutter.tsx` (`handleSetDate`), `features/schedule/scheduleUtils.ts` (`todayLocalIso`) — #3064, after #3063.
