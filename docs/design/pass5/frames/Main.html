Q5.1Are seeded-hidden views a distinct state from user-hidden views?✓Decided Nov 24 Yes, distinct. Each stores its source (seed:scrum_master vs user). They sit in the same list and use the same control, but carry a different label: “◌ Suggested hidden · Scrum Master” vs “Hidden by you”.Two reasons. A re-seed may touch only seed entries, so the source has to be stored. And a user who can't find Gantt needs to know they didn't hide it. One label difference covers both. It needs no new color or icon family.
Q5.2Is re-seeding on a lens change acceptable?✓Decided Nov 24 Never automatic. Offer it once, and confirm it with a diff. Changing the lens reorders the views immediately, as it does today, and leaves visibility alone. Row 3 then offers “Apply Product Owner suggestions”, and the confirm only changes seed-sourced entries.A lens switch is often a quick look (“what does the PO see?”). Silently re-hiding views on a look would destroy curation the user built over weeks. An opt-in that changes only seed entries keeps the default useful and costs no one their own choices.
Q5.3Are the Amend loop and the Pass 3 Rebaseline dialog one surface?✓Decided Nov 24 One surface. “Review N changes” and Pass 3's “Rebaseline” both open the same sheet. The Pass 3 dialog becomes its zero-changeset variant. When both apply (a changeset is open and someone starts a deliberate rebaseline from Baselines), the changeset sheet wins and lists the open changes.They are the same act, which the prototype says too: agreeing that the plan as it stands is what you are measured against. Two dialogs would allow a v2 that skips the open changeset's reasons. Take v2 still requires its own one-line reason, which keeps #4813's rule.
