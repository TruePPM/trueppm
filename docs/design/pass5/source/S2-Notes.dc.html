Section 2 · Project layout toggles and the More menu · #3887, frames only

Notes

Ground truth and scope

The Pass 1 shell spec consolidates project tabs to Overview · Plan · Deliver · Risks · People · More, with about seven layout toggles inside Plan and Deliver, but no frame drew them. These frames draw the control. Which views survive (#3887's inventory and per-view sunset-check) is a separate analysis and is not decided here. Every list that depends on it carries a pending consolidation tag: the Plan set, the Deliver set beyond Board · Sprints · Backlog, and the More groups.

Pins · 2A Plan

1The layout toggle is a segmented radio group in row 3, at the left of the page toolbar. Each segment is 44px tall, and arrow keys move between them. The toolbar controls to its right (Filter, Group, Zoom) belong to the current layout and change with it.
2Remembered layout: clicking the Plan tab reopens the layout you used last, per user and project. It is stored server-side so it follows you across desktop browsers. A link with a layout in the path (/plan/calendar) always wins over the remembered one. The quiet “Opened in Gantt, your last Plan layout” line is shown only when the remembered layout differs from the default.
3States: a layout hidden (it leaves the toggle), one layout left (the toggle turns into a label), a per-layout skeleton, and a per-layout error with a way out to another layout.

Pins · 2B Deliver and More

1The Deliver toggle is Board · Sprints, with Backlog suggested hidden for this PM. A hidden layout leaves the toggle and is listed in More, whether a seed or the user hid it.
2More is grouped as Track (timesheet, baselines, reports) and Project (activity, files, settings), followed by two fixed groups: Hidden from your tabs and Off in {workspace}. The first two groups are pending consolidation. The two fixed groups are part of the design whatever the inventory decides.
3An area that is off (#4888) is listed and disabled, with a “Why” link to the Pass 4 · 1B page. Hidden items open. Off items don't, and say why.
4The URL carries the layout, so a shared link opens the same layout. Layout changes push history, so Back returns to the previous layout.

Phone · 2C

Rule: with three or fewer visible layouts, use a full-width segmented control under the tab strip. With more, use a “Board ▾” button that opens a picker sheet with the same groups as More. Segmented wins whenever it fits, because it shows the options without an extra tap. A link that opens a hidden layout shows “◌ … hidden from your tabs · Keep it” in place of row 3. A link to an area that is off goes to the AreaOff page, never to a hidden layout.

Open questions

Q2.1Remembered per device or per user? I drew desktop as per user (server-side) and phone as remembered separately, because a phone user usually wants Grid and a desktop user Gantt. Is one per-user value enough?
Q2.2What survives the inventory: the Plan set (Gantt · Grid · Calendar, plus Scope/WBS?) and the Deliver set (Board · Sprints · Backlog, plus Releases or Swimlanes?) depend on #3887's inventory. If either set ends up above three, the desktop toggle still fits at 1280, but the phone switches to the sheet.
Q2.3Backlog's home: BacklogItem is program-scoped. Should a project's Deliver › Backlog be a filtered view of the program backlog, or should it live only at the program level? This affects the Product Owner landing view in 1C.
Q2.4Should toolbar controls be kept per layout (Filter and Group remembered for each layout separately) or shared across layouts? I propose per layout.
Q2.5Does Baselines belong in More › Track or in a Plan layout? Section 3 makes the baseline state part of Plan's context header, so the More entry may only be the history page.
