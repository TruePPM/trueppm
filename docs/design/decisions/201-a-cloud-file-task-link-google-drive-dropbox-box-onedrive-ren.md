# Rule 201 — A cloud-file task link (google_drive/dropbox/box/onedrive) renders a neutral preview_type chip in the link right-slot, NEVER a lifecycle StatusBadge — status pills are reserved for git lifecycle states

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Cloud-file link preview (#571, ADR-0163)*

**A cloud-file task link (`google_drive`/`dropbox`/`box`/`onedrive`) renders a neutral `preview_type` chip in the link right-slot, NEVER a lifecycle `StatusBadge` — status pills are reserved for git lifecycle states.** A file has no open/draft/merged/closed lifecycle, so reusing `StatusBadge` (which would show "UNKNOWN" for a file's always-`unknown` status) is wrong. `LinkRightSlot` (`ExternalLinksSection.tsx`) branches: file provider + `preview_type` set → `<TypeChip>` (a neutral `bg-neutral-surface-sunken` `text-neutral-text-secondary` chip whose visible Title-Cased label IS its content, plus `aria-label="File type: {Label}"`); file provider not yet refreshed (`preview_type === ''`) → **renders nothing** (the "never refreshed" stamp + the ⟳ button are the call to action — do NOT show an em-dash, which reads as "n/a status"); git/generic → the existing `StatusBadge` unchanged. The chip may use `text-[11px]` **specifically to match its sibling `StatusBadge` in the same slot** — the one sanctioned sub-12px exception outside `features/settings/`/`EnterpriseBadge` (rules 118/121), justified because a 12px chip beside an 11px badge breaks slot uniformity and the chip's meaning is independently carried by its `aria-label`. Do not generalize the [11px] exception beyond badge-class chips adjacent to `StatusBadge`. Scope clarification (#2043): the exception travels with the *slot*, not the file — the Assets workspace `AssetRightSlot` (`AssetsPage.tsx`) deliberately mirrors this same right-slot family (`StatusBadge`/`TypeChip`/file-kind chip), so its chips share the sanction; a standalone chip on any other surface (e.g. the sign-in `OSSChip`) does not, and uses `text-xs`.
