# Rule 227 — Any dialog that reveals a value the user cannot retrieve again (API token, board/share link, webhook secret) must disable both Escape and backdrop-click dismissal for as long as that value is on screen — the user leaves only via an explicit "Done" control

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *One-time secret reveal (Issue #283)*

**Any dialog that reveals a value the user cannot retrieve again (API token, board/share link, webhook secret) must disable both Escape and backdrop-click dismissal for as long as that value is on screen — the user leaves only via an explicit "Done" control.** A one-time secret uses the standard `useFocusTrap` + fixed-overlay dialog shape, but the reveal state is different from the form state: an accidental Escape (a near-universal reflex after finishing a dialog action) or an outside click discards the secret permanently, and nothing in the UI stores it afterward (the list rows show only a non-revealing prefix). Gate the dismiss paths on the reveal state: `useFocusTrap(true, revealed ? undefined : onClose)` for Escape, and add `&& !revealed` to the backdrop `onPointerDown` guard. The reveal warning itself carries real visual weight — a bordered `border-semantic-warning/70 bg-semantic-warning-bg` box, not bare warning-colored text — since it is the highest-consequence warning in the flow. References: `features/settings/token/PersonalAccessTokensPage.tsx` (the original), `features/settings/project/ProjectSharingPage.tsx` (#283 board share links).
