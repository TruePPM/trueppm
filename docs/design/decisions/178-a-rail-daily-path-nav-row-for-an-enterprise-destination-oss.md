# Rule 178 — A rail / daily-path nav row for an Enterprise destination OSS cannot reach renders as an *empty extension-point slot* — never a disabled teaser or padlock (rule 231 / ADR-0266)

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Pre-1.0 Enterprise-gated nav rows (Issue #1173, ADR-0029/0030)*

**A rail / daily-path nav row for an Enterprise destination OSS cannot reach renders as an *empty extension-point slot* — never a disabled teaser or padlock (rule 231 / ADR-0266).** The rail is the OSS daily path, so a cross-program / org destination that community edition cannot route to — the cross-program Portfolio rollup — is hosted as the `nav.portfolio_section` slot in `features/shell/Sidebar.tsx` ("Organization" group): `registry.get('nav.portfolio_section').map(({ id, component: Component }) => <Component key={id} />)`. In community edition the slot has no registration, so it renders **nothing** — no disabled row, no padlock, no upsell. The enterprise module injects its portfolio nav into the slot. This is the empty-slot pattern shared with `resources_heatmap.level_loads` (issue 1614), and it **supersedes** the former disabled-grayed-row treatment (the padlock removed in #1677). Discovery of the Enterprise portfolio moves to the `/programs` seam (rule 231(b)), not a rail teaser — hiding the row does *not* read as broken OSS here because the slot, not a gap, is the contract. The slot host stays `showFull`-gated (the collapsed rail is unchanged); the enterprise edition keeps its `/portfolio` `NavLink` until the enterprise module migrates its portfolio nav onto the slot. Contrast **rule 121**: a per-row `EnterpriseBadge` link is correct only on **seam surfaces** (the Settings → Roles capability matrix), never on the daily-path rail (rule 231's daily-path-vs-seam classifier).
