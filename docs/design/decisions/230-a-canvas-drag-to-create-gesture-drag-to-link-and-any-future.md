> Original section: *Canvas drag-to-create gesture previews (Issue #1666)*

**A canvas drag-to-create gesture (drag-to-link and any future create-by-drag on the schedule canvas) paints its preview only to the `canvas-interaction` layer using the `linkPreview` palette token, arms pointer-fine-only, and confirms success via the drawn artifact — never a success toast.** The drag-to-link preview (`drawLinkPreview` — dashed `[4,3]` line while hunting, flipping to solid + a 2px target ring on snap, `not-allowed` cursor on a self-drop) uses `linkPreview` (brand-primary sage-700/400) from the renderer `COLOR`/`COLOR_DARK` palettes — the sanctioned home for canvas hex (rule 40), never an ad-hoc rgba. Three invariants for any new create-by-drag gesture: (a) it arms only when `matchMedia('(pointer: fine)').matches` **and** `e.pointerType !== 'touch'`, so it never fires on touch — a keyboard/touch-complete alternative must remain (the `ScheduleDependencyPicker` drawer is the drag-to-link equivalent, and must not be regressed); (b) the pointer-down branch that arms the gesture **short-circuits before the bar move/resize path** (`_onPointerDown` returns on a `link-dot` hit before `_dragFSM.onPointerDown`), and Escape / `pointercancel` silent-cancel it; (c) success is confirmed by the artifact itself (the drawn dependency arrow, redrawn off the mutation's cache invalidation) with the accessible equivalent announced on the polite `sr-only` region — **no** success toast (a toast per link is noise during rapid linking); only the failure paths speak (cycle → `toast.error`, offline → `toast.info`). Reference: `features/schedule/engine/{GanttLinkFSM,GanttRenderer,GanttEngineImpl}.ts` + the `create-link` → `useAddDependency` wiring in `ScheduleView.tsx` (#1666).
