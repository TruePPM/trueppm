# Rule 189 — The desktop Schedule view has exactly ONE Monte Carlo forecast surface (ScheduleForecastBar), the percentiles render exactly ONCE on it, and every forecast date routes through lib/formatUtcDate (ADR-0144)

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Overlay motion (Issue 1227, ADR-0126)*

**The desktop Schedule view has exactly ONE Monte Carlo forecast surface (`ScheduleForecastBar`), the percentiles render exactly ONCE on it, and every forecast date routes through `lib/formatUtcDate` (ADR-0144).** The former two-surface split — a top `MonteCarloRow` and a bottom `ScheduleInsightsBar` — is deleted; both rendered the P50/P80/P95 percentiles (up to three times total) and *disagreed on the calendar day* because some formatters omitted `timeZone:'UTC'` and drifted a day west of UTC. **Server ISO dates are UTC and authoritative** — never format an MC/forecast date with a bare `toLocaleDateString`/`new Date(iso).getDate()`; always use `fmtUtcShort`/`fmtUtcLong` (or pass `{timeZone:'UTC'}` explicitly). `ScheduleForecastBar` is desktop-only (`hidden md:block`); mobile keeps `MobileMonteCarloCard` + `MonteCarloSheet`. It owns the MC hooks (`useMonteCarloResult`, `useRunMonteCarlo`, history), the stale/recomputing machinery (**since #3140 / ADR-0954**: the server's `forecast_staleness` verdict off the MC payload → stale; `runMc.isPending` → recomputing, `data-testid="mc-recomputing"`. It was a session-local `mutationVersion` counter cleared on a `lastRunAt` change, which missed every write path but the drag commit and reset on reload), and the single no-result "Run a simulation" prompt — there is no second prompt to double-claim it. The collapsed header shows the percentile chips once (P80 is the commit, accented `text-semantic-at-risk`, with the server-owned `+Nd vs CPM` delta — never a client recompute) plus the top sensitivity driver and its distinct affordances: the maximize/minimize **toggle** (`aria-expanded`/`aria-controls`, persisted to `localStorage['schedule.insightsExpanded']` — exact key), **Details** (`data-testid="mc-details-btn"`, opens `MonteCarloDetailPanel`), and — **only on the stale branch** — **Rerun** (`aria-label="Rerun Monte Carlo forecast"`). Rerun is **not** unconditional (#3132, UX-REVIEW §8.1): on a fresh forecast the bar states when the server last confirmed the run and offers no recompute, because a permanently parked one is a debug affordance on a user surface. It is gated on `runMc.isPending || forecastStaleness !== 'current'`, so it survives its own in-flight run and leaves only when the server confirms the fresh result is current. **The notice and the action are separate decisions** (#3140): `unknown` — a run the server cannot place against the plan — offers Rerun and renders NO `mc-recomputing` notice, because an unfounded "Stale" is the same defect inverted. `aged` keeps *Stale — rerun for updated forecast*; `project_changed` says only *Edited since this run*, since the counter behind it advances on any write in the project. The action group carries `shrink-0` so the appearing button cannot steal width from Details; the no-layout-shift guarantee is pinned by a `boundingBox` assertion in `e2e/schedule-monte-carlo.spec.ts`. Expanded body = `MonteCarloHistogram` + `SensitivityList` + `ForecastHistorySection` — **no `ForecastStat` triplet** (that was the duplicate). Entrance motion is the shared `animate-empty-state-in` only (rule 177/181). `MonteCarloHistogram` distinguishes `buckets.length === 0` (cold / not-persisted past cache TTL → "Run a fresh simulation" prompt, `role="img"`) from `buckets.length === 1` / `p50===p80===p95` (genuine zero-spread → "every simulation finished on {date}" prose) — never claim a converged date the run never had. The run-history list is visible to all project members; `triggeredByName` attribution is gated server-side (render only when present), a workspace with history off returns `enabled:false` (quiet "Run history is turned off for this workspace." note, not an empty shell), and a past run's persisted distribution loads on demand via `useMonteCarloRunDistribution` (`?expand=distribution`). A rerun fires NO push notification.
