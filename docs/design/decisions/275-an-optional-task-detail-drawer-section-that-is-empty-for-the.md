# Rule 275 — An optional task-detail-drawer section that is *empty* for the current task folds behind the single shared AddDetailRow "Add detail" affordance — it does NOT render an empty collapsed header; sections with content stay in the flow, and a section whose emptiness can't be derived from the task stays always-shown (ADR-0605, #2315)

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *AppShell owns the only `<main>`; the 404 keeps the shell (Issue #2184)*

**An optional task-detail-drawer section that is *empty* for the current task folds behind the single shared `AddDetailRow` "Add detail" affordance — it does NOT render an empty collapsed header; sections with content stay in the flow, and a section whose emptiness can't be derived from the task stays always-shown (ADR-0605, #2315).** The Details tab drove the drawer's 3.7/10 VoC score by always rendering six empty section headers. Progressive disclosure is driven by an **additive** `isPopulated?(ctx): boolean` predicate on the `task_detail.section` registry descriptor (parallel to `canRender` — capability vs. content), reading only the task object plus the already-warm schedule cache (`ctx.tasks`/`ctx.links`) so **no section query fires** to decide emptiness. Semantics: predicate **absent** → always shown (every Enterprise section — the safe default: an unknown section is never hidden); returns **true** → shown as a normal collapsible; returns **false** → folded out and offered under `AddDetailRow`. Four invariants: (a) **a predicate must be answerable without firing that section's query** — either from the task/warm cache: `sprint` (`sprintId`), `blocker` (`blockedAgeSeconds`, NOT the privacy-gated `blockedReason`), `dependencies` (any `links` edge touches the task, falling back to `predecessorCount`), `estimates` (leaf PERT triple, or any descendant PERT for a summary); **or from a server emptiness annotation** where the content is lazily fetched (#2317): `related-links` (`hasRelatedLinks` — a live relation on either end) and `recurring` (`hasRecurrence` — the task owns the rule; NOT `is_recurring`, which is also true of generated occurrences that own none). Never fire the section's own hook to decide. A cold cache or a missing annotation under-reports → section is *offered*, never wrongly shows stale data or an expanded-and-empty header. All six OSS optional Details sections now carry a predicate, so the Details tab renders **zero** empty headers. (b) **populated sections stay collapsed-by-default** (ADR-0050 lazy-load) — showing them is the win; only a *just-revealed* section auto-opens (so the user lands in it). Do not auto-expand every populated section: it re-introduces the query fan-out and flips the established click-to-expand that e2e specs and muscle memory rely on. (c) **reveal state is per-task, session-scoped** in `drawerSectionStore` (`revealed`, keyed `${taskId}:${id}` via `revealKey`) — revealing Recurrence on task A never reveals it on task B. (d) **`AddDetailRow` is a labeled `<section aria-labelledby>` region** of standalone `<button>`s (not a popover — at most a handful of sections ever collapse) using `focus:` rings (rule 214), `min-h-[44px]` targets (rule 5), the rule-250 eyebrow, neutral DS tokens, and the house `PlusIcon` (rule 242); the Sprint button's label comes from `useIterationLabel().singular`, never a hardcoded "Sprint". **E2E consequence:** a drawer section that is empty for the spec's task is no longer a collapsed header — it is an `AddDetailRow` button of the same accessible name (no `aria-expanded`); assert `getByRole('region', { name: 'Add detail' })` for the offered set, and reveal-then-assert `aria-expanded='true'` for the opened section. Reference: `features/schedule/AddDetailRow.tsx`, the Details-tab partition in `TaskDetailDrawer.tsx`, `sections/index.ts` (`isPopulated` predicates), `stores/drawerSectionStore.ts` (`revealed`/`revealKey`), `lib/widget-registry.ts` (`isPopulated` on the descriptor).
