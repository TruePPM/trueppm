# Rule 185 — Overlay entrances use the shared keyframes, and the dead animate-in/fade-in utilities are never used (no tailwindcss-animate in this repo — they emit no CSS)

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Overlay motion (Issue 1227, ADR-0126)*

**Overlay entrances use the shared keyframes, and the dead `animate-in`/`fade-in` utilities are never used (no `tailwindcss-animate` in this repo — they emit no CSS).** A centered dialog/modal **panel** scales in via `motion-safe:animate-modal-scale-in` (rule 181, 180ms); its **scrim** fades via `motion-safe:animate-scrim-fade` (150ms — replaces the old dead `animate-in motion-safe:fade-in`); the new-task modal's scrim also carries `backdrop-blur-[2px]`. A docked **Save bar** (settings + the task drawer, both gated on `dirty`) slides up via `motion-safe:animate-save-bar-slide` (220ms). The desktop **task drawer** slides on `transition-transform duration-slow ease-brand` (proto .26s), never the default ease; per rule 89/164 it has **no desktop scrim** (non-modal). On create success the new-task modal fires `toast.success("Created {name}")` (rule 183) — `onSuccess`/post-`mutateAsync`, never optimistically. A **bottom sheet** (`BottomSheet`, mobile) keeps its own `translate-y` slide-up — the scale-in is for centered surfaces only. Every entrance is `motion-safe:`-gated at the class layer (rule 70); the keyframes live in `globals.css` beside `cmdk-in`. Reference: `TaskFormModal`, `SettingsShell`, `TaskDetailDrawer`, and the confirm/editor dialogs (`ConfirmDiscardDialog`, `DeleteConfirmDialog`, `SessionExpiredBanner`, `WebhookEditorModal`, `ConnectedAccountsPage`).
