# Rule 263 — A field's contextual-help affordance is the shared FieldHelp component (components/FieldHelp.tsx) — a circled-ⓘ button in the field's label row that opens a non-modal role="dialog" popover, not a hand-rolled tooltip

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *A field's contextual-help affordance is the shared `FieldHelp` component, not a hand-rolled tooltip (Issue #1975)*

**A field's contextual-help affordance is the shared `FieldHelp` component (`components/FieldHelp.tsx`) — a circled-ⓘ button in the field's label row that opens a non-modal `role="dialog"` popover, not a hand-rolled tooltip.** Reach for it when a form field's options are jargon a first-time user cannot decode from the label alone (the task-editor Type / Governance class / Delivery mode selects, #1975) — NOT on every field (a `?` on "Task name" is noise). Eight invariants a new call site or refactor must preserve: (a) **circled-ⓘ, never `?`** — `InfoIcon` (a house SVG, rule 242) reads as "reference information about this thing"; a `?` reads as "I need help doing a task". (b) **click-to-toggle, never hover** — hover fails touch and keyboard, and a hover surface that contains a link is unreachable (rule 121); the trigger is a real `<button aria-haspopup="dialog" aria-expanded aria-controls>`. (c) **`role="dialog"` + `aria-modal="false"`, NOT `tooltip` or `menu`** — the popover contains a "Learn more" link, and an `aria-describedby` tooltip's link is unreachable (rule 121), while a `menu`'s rows would mis-announce descriptive text as invokable commands. (d) **supplements, never replaces, the inline hint** — the always-visible `<p>` under the select answers "what does my *current* pick mean" (zero-click, and the select's `aria-describedby` target); the popover answers "what are *all* my choices" and links deeper. Keep both. (e) **current option carries a non-color signal** — `CheckIcon` + the literal word "Current" + `aria-current="true"`, with any tint (`bg-brand-primary/5`) as reinforcement only (rule 6). (f) **capture-phase Escape peels ONE layer** — a `document` keydown listener in the **capture** phase with `stopPropagation()` closes the popover and beats the parent modal's own bubble-phase Escape, so Escape inside the popover never closes the whole modal; focus returns to the trigger on Escape / "Got it" (outside-click dismiss deliberately does not steal focus, rule 253c). (g) **44px touch targets** — the trigger reaches the floor with `before:-inset-3` on a 20px button, and the popover's own footer controls ("Learn more", "Got it") carry `min-h-11 md:min-h-0` because `FieldHelp` renders inside the mobile `BottomSheet` where they are real touch targets (rule 5). (h) **positioning is delegated to `useAnchoredPopover` (rule 260) and the docs link to `docsUrl()` (rule 212)** — never hand-roll the fixed/flip/clamp math and never point the link at an in-app `/docs/…` path. The component takes `{ label, intro?, options?, body?, docHref, docLabel? }`; pass `options` for an enum field (each `{ label, desc, selected }`) or `body` for free-form help — the heading + "Learn more" chrome and all ARIA wiring are identical either way. Reference: `components/FieldHelp.tsx`, its use in `features/board/TaskFormModal/index.tsx`.
