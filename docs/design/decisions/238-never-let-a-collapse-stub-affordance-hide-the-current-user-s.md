# Rule 238 — Never let a collapse/stub affordance hide the current user's assigned cards without a quiet, always-present signal: an edge accent on the affected stub plus an expand affordance in the collapsed-count banner (#1696)

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Responsive table→card reflow for the task Grid (Issue #1701)*

**Never let a collapse/stub affordance hide the current user's assigned cards without a quiet, always-present signal: an edge accent on the affected stub plus an expand affordance in the collapsed-count banner (#1696).** Once a column folds to a stub a contributor can lose track of their own cards inside it; the signal must be *quiet* (no toast, no push — churns on noise) but *findable*. Two tiers, both reusing existing state (`myResourceId` from `useCurrentUserResourceId`, the same `task.assignees.some(a => a.resourceId === myResourceId)` predicate as the "My tasks" filter): (a) a **2px `--brand-primary` left-edge accent** (`border-l-2 border-l-brand-primary`, plus `data-has-my-cards`) on any stub holding ≥1 of the current user's cards, with `aria-label` gaining `", contains N of your cards"`; (b) a **secondary clause on the "N columns collapsed" banner** — `· N of your cards hidden`, a `--text-secondary` text button (accessible name `"Expand columns containing your cards"`, 44px mobile touch target) that calls `expandColumn` on the affected stubs. The signal is absent (never wrong) when `myResourceId` is null — a user with no resource identity on the project sees no accent and no banner clause. Reference: `ColumnStub` + the collapsed-columns banner in `BoardView.tsx` (`myCountByStatus` memo).
