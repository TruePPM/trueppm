> Original section: *Custom-field marks are the lowest-priority, opt-in, empty-hiding occupants of a board card (Issue #1989, design pending)*

**Custom-field values on a board card are opt-in per field (`ProjectCustomField.show_on_card`, OFF by default), render dead-last in the card, collapse first into overflow, and are hidden when unset — a custom field may never displace the worst-offender health badge (#1305) or the story-point pill.** This is the design contract from `docs/design/board-card-custom-fields.md` (#1989, pending user approval — the value model `TaskCustomFieldValue` is a prerequisite, so nothing renders until it ships); implement to it, do not re-derive. Seven invariants: (a) **opt-in, off by default** — a flagged-off field is drawer-only; only a Scheduler+ author flips `Show on card` in Settings → Workflow → Fields (`FieldsSection`/`CustomFieldModal`, the existing `canEditStatusesOrFields` gate, no new permission). (b) **render order is fixed and custom fields are LAST** — appended to the comfortable badge `flex-wrap` row *after* assignees, behind health badge · story points · dep/risk chips · labels · assignees; they are the first content to fall into overflow (Alex's card-economy blocker). (c) **hard caps per density** — compact/mobile (rule 193): **0 inline on the 36px bar**, all flagged values behind ONE trailing `⊕N` `CardPeekButton` (rule 256, glyph-only bar per #1924/#1925); comfortable: **≤3 inline** in `ProjectCustomField.order`, remainder in a single `+N more` peek; detailed: **all inline**. Counts populated fields only. (d) **empty → render nothing** — no `—`, no placeholder chip, zero overflow count (Priya's condition); a `required`-but-empty field is NOT a card scold (that is the drawer/validation surface). (e) **type-aware treatment** — SINGLE/MULTI_SELECT → neutral chip with the option `color` as a dot/tint *behind the label text* (never color-only, WCAG 1.4.1); BOOLEAN → neutral `✓` glyph chip (never green — green is health), false renders nothing; TEXT/NUMBER/DATE → `Label: value` key:value in `tppm-mono` for number/date, value truncated with `title`+`aria-label` (rule 255); USER → initials pill disambiguated from assignees via an `aria-label` role prefix (`"Reviewer: AB"`). (f) **every mark carries an `aria-label`** naming field+value (the visible label may drop at comfortable density). (g) **a board-level master switch `Show custom fields on cards` (default ON, per-user board view preference in `BoardSettingsPanel`)** lets board residents mute the whole class in one click without project-settings access — the OSS consent lever (Morgan); person/number fields are shown but must not be framed as imposed productivity columns (org-policy visibility governance is Enterprise, out of scope). Reference: `docs/design/board-card-custom-fields.md`, `features/board/BoardCard.tsx`, `features/settings/project/ProjectWorkflowPage.tsx`.
