# Rule 281 — A view's Label facet is the shared LabelFacet + labelFilter.ts — do not hand-roll a fourth label filter, and do not re-declare the ?fl= param key (ADR-0620)

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *AppShell owns the only `<main>`; the 404 keeps the shell (Issue #2184)*

**A view's Label facet is the shared `LabelFacet` + `labelFilter.ts` — do not hand-roll a fourth label filter, and do not re-declare the `?fl=` param key (ADR-0620).** Four surfaces filter by label (Board, Table/Grid, Product Backlog, and the Schedule per #2384) and each keeps its **own** filter model on purpose — unifying them would have to migrate the Grid's `?owner=`/`?status=` params and break every bookmarked Grid link, a real cost for no user-visible gain. What *is* shared, and must stay shared, is: (a) `LABEL_PARAM` (`'fl'`) — defined once in `components/filters/labelFilter.ts` and **imported** by `boardFacets.ts`; a second `'fl'` literal is how the four views drift apart; (b) `taskMatchesLabels` — **OR within** the facet, which the caller then **ANDs** with its other predicates; (c) `countTasksByLabel` — counts over the **rows already loaded**, never the catalog's server-side `taskCount`, because the number answers "how many rows *here*" and a project-wide count beside a view-scoped filter misleads; (d) `pruneUnknownLabelIds` — applied at the point of *use* only, so a `?fl=` naming a deleted label degrades to "no filter" instead of hiding everything, while the stored value survives for the saved-view tombstone (#2385). Three UI invariants: the option list is the project's **full catalog** with a **visible `0`** on unused labels (a zero-result pick must be deliberate, not a surprise — this is deliberately *not* the Board's "labels present on loaded cards" behavior); filtering is **client-side** so it works offline with no spinner (offline surfaces a chip-strip note, never a blocked control); and the label **name always renders beside its swatch** in the option row, trigger, and chip (rule 6 / WCAG 1.4.1). New consumers pass `footerExtra` for view-specific panel controls rather than forking the component. Reference: `components/filters/{LabelFacet,LabelChip,labelFilter}.*`, `features/grid/{filters.ts,ChipStrip.tsx,GridView.tsx}`, `features/project/backlog/{filter.ts,hooks/useGroomingFilters.ts}`, `docs/adr/0620-label-filter-beyond-the-board.md`.
