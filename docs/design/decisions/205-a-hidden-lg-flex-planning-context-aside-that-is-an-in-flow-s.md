# Rule 205 — A hidden lg:flex planning/context aside that is an in-flow sibling in a flex-row page MUST be suppressed while a non-modal (aria-modal="false") detail drawer is open in the same layout region — the drawer is absolute right-0 and silently occludes the aside regardless of DOM order

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *In-flow rail beside a non-modal detail drawer (Issue 1291)*

**A `hidden lg:flex` planning/context aside that is an in-flow sibling in a `flex-row` page MUST be suppressed while a non-modal (`aria-modal="false"`) detail drawer is open in the same layout region — the drawer is `absolute right-0` and silently occludes the aside regardless of DOM order.** The `SprintPlanningRail` on the Product Backlog (issue 1291) is the reference: the page root is `relative flex flex-row`, the rail is a `w-[320px] shrink-0` in-flow right column, and `StoryDetailDrawer` is `absolute right-0 w-[480px]` (rule 89/164, non-modal so the list stays usable). Because the drawer overhangs the rail by ~160px, rendering both leaves planning context (capacity, milestone) hidden *behind* the drawer with no signal it is there. Gate the aside on "no drawer open" — `{plannedSprint && !selectedStory && <SprintPlanningRail …/>}` — so it cleanly re-appears on drawer close; the rail's utility while a drawer is open is marginal (the user is focused on that one story). Extend this to any future `flex-row` page that combines an in-flow rail with an absolutely-positioned non-modal detail drawer: the in-flow sibling yields to the overlay. (A truly modal drawer with a backdrop does not need this — the backdrop already signals the rail is dismissed.)
