# Rule 208 — A *categorical identity* color (role chip, methodology accent, group-avatar swatch — a hue that carries no on-track/at-risk status meaning) is single-sourced in lib/identityColors.ts and applied via the style prop, NEVER as a raw bg-[#hex]/text-[#hex] arbitrary-value Tailwind class

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Inline text control that is a row's sole open/edit affordance must meet 44px (Issue #1346)*

**A *categorical identity* color (role chip, methodology accent, group-avatar swatch — a hue that carries no on-track/at-risk status meaning) is single-sourced in `lib/identityColors.ts` and applied via the `style` prop, NEVER as a raw `bg-[#hex]`/`text-[#hex]` arbitrary-value Tailwind class.** This is the rule-158 `programColor.ts` precedent generalized: any "N distinct, meaningless hues" surface draws its hex from `IDENTITY_SAGE`/`IDENTITY_AMBER`/`IDENTITY_VIOLET` or the `IDENTITY_SWATCHES` array, and a tinted chip uses `tintedChipStyle(hex)` (a 10% wash behind solid accent text — the `${hex}1a` alpha equivalent of the old `bg-[#hex]/10 text-[#hex]`). The reason is **not** dark-mode adaptivity — an identity hue is theme-static by definition, the same in light and dark — it is (a) single-sourcing so one hue lives in one place, and (b) keeping raw `bg-[#hex]`/`text-[#hex]` literals out of the tree so the `design-system-v2` arbitrary-color gate (`BASELINE_ARBITRARY`) stays at floor. A *semantic status* color is the opposite case: it MUST go through a status token (`text-semantic-at-risk`, `bg-brand-primary-light`, …), never `identityColors` and never an arbitrary hex. The line: does the color mean a state (→ token) or an identity (→ `identityColors` + `style`)? Reference: `lib/identityColors.ts`, the `ROLE_PALETTE` `style` threading in `WorkspaceRolesPage.tsx`/`WorkspaceMembersPage.tsx`, `IDENTITY_SWATCHES` in `WorkspaceGroupsPage.tsx`, ADR following rule 158.
