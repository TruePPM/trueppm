> Original section: *Offline-queued write affordance (Issue #1159)*

**An offline-queued write (a mutation the app defers to a durable queue while `!navigator.onLine`, replaying on reconnect) reuses the shared calm-offline "pending sync" vocabulary — it never invents a new offline signal, and it never disables or relabels the action button offline.** The vocabulary, established by the board card-status queue (ADR-0220) and extended to blocker flags (ADR-0247), is fixed so every offline surface reads as one product: (a) a passive **pending badge** — `role="status"`, `bg-semantic-at-risk-bg text-semantic-at-risk` (the same amber as the shell `SyncStatusBadge` / `OfflineBanner`), a 12px `aria-hidden` cloud-off glyph, and a full `aria-label`/`title` ("… queued — it will save when you reconnect."), with an optional `compact` variant that drops the visible "Pending" text but keeps the accessible name (rule 6 — color is never the only signal); (b) the mutating control **keeps its normal label and stays enabled** offline — flag/save/unblock *enqueue* instead of firing a live PATCH; disabling or relabeling it ("Flag when online") reads as *deferred/blocked*, the opposite of the reassurance the queue provides. The global `OfflineBanner` already carries the "you are offline" state, so the per-control surface stays quiet — one short helper line (`text-xs text-neutral-text-secondary`, e.g. "Offline — this will be saved and synced when you reconnect.") and the badge, never a toast per enqueue. (c) Announce the two discrete transitions on a visually-hidden `role="status" aria-live="polite"` region — *queued* on enqueue and *synced* on a **successful** flush only; drive the "synced" cue off a flush-success signal (never a `pending → absent` transition), because a conflict yield also clears the pending op and already shows its own conflict toast — announcing "synced" there would contradict it (rule 220 — announce what changed, not a running value). (d) An optimistic patch that fabricates a server-stamped field (a `blocked_since`/age not yet assigned) must render as a neutral "queued" label, never a fake precise value ("just now"/"0s"). Reference: `features/blocker/BlockerPendingBadge.tsx`, `features/blocker/offline/{blockerQueue,blockerOutboxStore,useBlockerOffline}.ts`, and `BlockerSection.tsx`; the flush is mounted once in `AppShell` (`useBlockerOffline`), not in the drawer, so a queued write syncs even when its originating surface is unmounted.
