# Rule 265 — A control disabled behind an Enterprise upsell badge must carry an aria-describedby pointing at an sr-only span that states the Enterprise requirement — the visual EnterpriseBadge alone never reaches a screen-reader user, who otherwise hears only "unavailable" with no reason

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *A field's contextual-help affordance is the shared `FieldHelp` component, not a hand-rolled tooltip (Issue #1975)*

**A control disabled behind an Enterprise upsell badge must carry an `aria-describedby` pointing at an `sr-only` span that states the Enterprise requirement — the visual `EnterpriseBadge` alone never reaches a screen-reader user, who otherwise hears only "unavailable" with no reason.** A `disabled`/`readOnly` radio, checkbox, or button whose only explanation is a neighboring badge glyph strands the *why* for non-visual users; wire the input's `aria-describedby` to one `sr-only` span (e.g. `<span id="…-enterprise-hint" className="sr-only">Enforce requires TruePPM Enterprise.</span>`) so the disabled state announces its gate. Applies to every Enterprise-gated form control in `features/settings/` (the `INHERIT/SUGGEST/ENFORCE` override-policy radios are the canonical case — the `ENFORCE` row is Enterprise-locked in OSS). `WorkspaceCalendarPage.tsx` (#1987) is the reference; `WorkspaceMethodologyPage.tsx`'s and `WorkspaceMcHistoryPage.tsx`'s Enforce radios predate this rule and should be backported. Reference: `features/settings/workspace/WorkspaceCalendarPage.tsx`, `features/settings/components/EnterpriseBadge.tsx`.
