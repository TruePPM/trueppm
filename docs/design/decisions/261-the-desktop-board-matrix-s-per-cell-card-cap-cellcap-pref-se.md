# Rule 261 — The desktop board matrix's per-cell card cap (cellCap pref + selectVisibleCards) is OPT-IN (default off), NEVER caps a WIP-breached cell, NEVER collapses an exception card, and exposes overflow through a rule-210 disclosure that keeps the count in text — a tidy board must never cost a signal

> Original section: *Board per-cell card cap is opt-in, exception-aware, and never hides a signal (Issue #1967, ADR-0420)*

**The desktop board matrix's per-cell card cap (`cellCap` pref + `selectVisibleCards`) is OPT-IN (default off), NEVER caps a WIP-breached cell, NEVER collapses an exception card, and exposes overflow through a rule-210 disclosure that keeps the count in text — a tidy board must never cost a signal.** A busy phase×status cell (`BoardCellImpl`) otherwise stacks every card unboundedly and blows out its matrix row. The cap tidies it, bounded by five invariants a refactor must preserve: (a) **opt-in** — `cellCap: number \| null` is a per-user client pref in `useBoardToolbarPrefs` (`trueppm.board.toolbarPrefs.v1`, additive like `zoom`/`groupBy`, `null` = off is the default); the "Cap tall cells" control lives in the CalmToolbar More⋯ menu (no new always-on chrome — VoC judged the value "thin", so it adds zero board noise). (b) **breach exemption is toggle-independent** — a cell whose `wipState(tasks.length, wipLimit)` is `at`/`over` is never capped, computed from the RAW band (not the `showWip`-gated display band) per rule 176, so an overloaded pile stays fully visible whether or not WIP chips are shown; because a capped cell is therefore always under-WIP, there is no breach signal left to preserve on it. (c) **exceptions never collapse** — `isExceptionCard` keeps critical-path, blocked (dependency or human flag), late (negative float), and the current user's own cards above the fold; the visible calm remainder respects the cell's current sort order and only its tail overflows (so a priority sort keeps the top cards), and the cap only engages when it would hide ≥ `MIN_OVERFLOW_TO_COLLAPSE` (2) cards. (d) **rule-210 disclosure** — "+N more" is a real `<button aria-expanded aria-controls>` sourcing state from an explicit per-cell toggle (never hover/`group-hover`/`focus-within`), neutral-toned, with the hidden count in the accessible name (`Show N more cards`) and a `.tppm-mono` count in text (rule 6, color/glyph never the only signal), `focus:` (not `focus-visible:`) ring. (e) **keyboard reach preserved (rule 105)** — the expanded state is ephemeral (not persisted) and auto-expands when keyboard focus lands on a hidden card OR a drag drops into the cell, so a card is never stranded out of tab reach and its `···` "Move to…" menu stays reachable. Desktop matrix only for the opt-in cap — `MobileBoard` (rule 193) does not get the `cellCap` pref (it does get the always-on render ceiling; see the #1538/#2340 amendment below, which supersedes "unchanged" as of 2026-11-15). The selection logic is a pure, unit-tested `features/board/cellCap.ts`; treat an absent signal field (EVM/SLA for low-privileged viewers) as "not an exception" (fail-open to *showing*, never hide because a signal was unreadable). Reference: `features/board/cellCap.ts`, `BoardCellImpl`/the More⋯ "Cap tall cells" toggle in `BoardView.tsx`/`CalmToolbar.tsx`, `useBoardToolbarPrefs.ts`.

**Amendment (#1538, #2340) — always-on render ceiling.** Independent of this opt-in pref, a cell (desktop) or status column (`MobileBoard`) never mounts more than `BOARD_RENDER_CEILING` (50) `BoardCard`s; DOM size must not scale with project size. A `cell-ceiling-more` / `mobile-column-more` button ("N of M shown · show 50 more") reveals `RENDER_CEILING_STEP` more per press. It is applied *after* this cap, the Expand toggle and the drag-over show-all, so none of them can defeat it, and it also applies to WIP-breached cells (the breach notice and counts read the full list). `selectRenderWindow` reuses `selectVisibleCards`, so exception cards are never hidden, and adds exactly the keyboard-focused card (which is also the just-dragged/just-moved card) to the window in its original position, never the cards ahead of it (rule 105). `MobileBoard` passes `myResourceId: null`, so on phones only critical/blocked/late cards are exempt, not the user's own. The Queue and Backlog lists are not windowed (#5002). Chosen over per-cell `useVirtualizer` because the phase × status matrix has no single scroll element per cell and dnd-kit droppables are the cells themselves; windowing by count keeps drop targets and keyboard DnD intact. Reference: `features/board/cellCap.ts`, `boardView/MobileBoard.tsx`.
