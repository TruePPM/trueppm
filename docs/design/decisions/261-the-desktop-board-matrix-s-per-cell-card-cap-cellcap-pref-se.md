> Original section: *Board per-cell card cap is opt-in, exception-aware, and never hides a signal (Issue #1967, ADR-0420)*

**The desktop board matrix's per-cell card cap (`cellCap` pref + `selectVisibleCards`) is OPT-IN (default off), NEVER caps a WIP-breached cell, NEVER collapses an exception card, and exposes overflow through a rule-210 disclosure that keeps the count in text — a tidy board must never cost a signal.** A busy phase×status cell (`BoardCellImpl`) otherwise stacks every card unboundedly and blows out its matrix row. The cap tidies it, bounded by five invariants a refactor must preserve: (a) **opt-in** — `cellCap: number \| null` is a per-user client pref in `useBoardToolbarPrefs` (`trueppm.board.toolbarPrefs.v1`, additive like `zoom`/`groupBy`, `null` = off is the default); the "Cap tall cells" control lives in the CalmToolbar More⋯ menu (no new always-on chrome — VoC judged the value "thin", so it adds zero board noise). (b) **breach exemption is toggle-independent** — a cell whose `wipState(tasks.length, wipLimit)` is `at`/`over` is never capped, computed from the RAW band (not the `showWip`-gated display band) per rule 176, so an overloaded pile stays fully visible whether or not WIP chips are shown; because a capped cell is therefore always under-WIP, there is no breach signal left to preserve on it. (c) **exceptions never collapse** — `isExceptionCard` keeps critical-path, blocked (dependency or human flag), late (negative float), and the current user's own cards above the fold; the visible calm remainder respects the cell's current sort order and only its tail overflows (so a priority sort keeps the top cards), and the cap only engages when it would hide ≥ `MIN_OVERFLOW_TO_COLLAPSE` (2) cards. (d) **rule-210 disclosure** — "+N more" is a real `<button aria-expanded aria-controls>` sourcing state from an explicit per-cell toggle (never hover/`group-hover`/`focus-within`), neutral-toned, with the hidden count in the accessible name (`Show N more cards`) and a `.tppm-mono` count in text (rule 6, color/glyph never the only signal), `focus:` (not `focus-visible:`) ring. (e) **keyboard reach preserved (rule 105)** — the expanded state is ephemeral (not persisted) and auto-expands when keyboard focus lands on a hidden card OR a drag drops into the cell, so a card is never stranded out of tab reach and its `···` "Move to…" menu stays reachable. Desktop matrix only — `MobileBoard` (rule 193) is unchanged. The selection logic is a pure, unit-tested `features/board/cellCap.ts`; treat an absent signal field (EVM/SLA for low-privileged viewers) as "not an exception" (fail-open to *showing*, never hide because a signal was unreadable). Reference: `features/board/cellCap.ts`, `BoardCellImpl`/the More⋯ "Cap tall cells" toggle in `BoardView.tsx`/`CalmToolbar.tsx`, `useBoardToolbarPrefs.ts`.
