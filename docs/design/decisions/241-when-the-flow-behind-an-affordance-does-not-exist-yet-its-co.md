# Rule 241 — When the flow behind an affordance does not exist yet (its connect/manage screen is a separate unbuilt issue), the seam is a passive, non-interactive <span> label — "Coming soon" — never a disabled <button>

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Gated affordance for an unbuilt flow — a passive label, not a disabled button (Issue #1420, ADR-0291)*

**When the flow behind an affordance does not exist yet (its connect/manage screen is a separate unbuilt issue), the seam is a passive, non-interactive `<span>` label — "Coming soon" — never a disabled `<button>`.** This is the complement to rule 122's disabled-control recipe: rule 122 applies when a control *exists but is momentarily unavailable* (keep it a focusable `<button disabled>` with an explanation). When there is *nothing to click yet at all*, a disabled button is a **phantom affordance** — it advertises an action that has no destination, sits in the tab order promising a dialog that never opens, and is exactly the dead-click friction a contributor churns on (VoC 🟡). Use a plain label span: no `role`, no `tabindex`, no handler, out of the tab order. Pair it with a passive **connected/active state** that mirrors the page's existing "connected" pill (`ConnectionPill`) rather than inventing a new one, so the surface is forward-compatible: when the real flow lands (#1421), the label span becomes the live button and the passive state gains its manage action, with no restructure. The affordance must stay a **text label, not color-only** (Active/Coming soon words carry the state; any status dot is `aria-hidden`), and a trust/reassurance badge row uses `text-neutral-text-primary` (not `-secondary`) on `surface-sunken` to clear WCAG AA — `-secondary` there is 4.36:1, below the 4.5:1 floor. Reference: `SourceStatus` + `AvailableSourcesSection` in `features/me/ConnectedAccountsPage.tsx`.
