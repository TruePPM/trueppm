# Rule 172 — The project view row is a grouped, method-filtered bar + a single methodology-adaptive health cluster — both project-scoped chrome that self-suppresses off-project and on settings routes

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *v2 view row — grouped view bar + methodology-adaptive health cluster (Issue #1167, ADR-0128)*

**The project view row is a grouped, method-filtered bar + a single methodology-adaptive health cluster — both project-scoped chrome that self-suppresses off-project and on settings routes.** Shell slice 3 of the v2 redesign (ADR-0128). Reference: `features/shell/ViewTabs.tsx`, `HealthCluster.tsx`, `healthClusterModel.ts`, `methodologyTabs.ts`. **Amended by ADR-0134 (rule 174):** the view row is no longer its own row — `ViewTabs`/`ProgramTabs` + the health cluster now share the single unified shell bar (`TopBar`) with the context affordances, and the tab strip lives inside `ShellNavScroller`. The grouping, the methodology filter, the health-cluster semantics, and the off-project/settings suppression below are all unchanged by that move.
 - **Grouping is visual, not structural.** Route segments are unchanged (rule 108 / ADR-0030) — links stay `/projects/:id/:view`. The PLAN / TRACK / PEOPLE assignment lives in `methodologyTabs.ts` (`VIEW_GROUPS`); `groupedVisibleViews(methodology)` applies the ADR-0041 methodology filter *within* each group and drops fully-filtered groups (never render an empty group label). `overview` leads and `settings` trails **standalone** (outside the groups). The role gate for `resources` (Team, role ≥ SCHEDULER) stays in `ViewTabs`. Each group is a `<div role="group" aria-label="Plan views|Track views|People views">`; the visible mono header (`PLAN`/`TRACK`/`PEOPLE`, the rule-36/101 token `text-xs font-semibold tracking-widest uppercase text-chrome-text-secondary`) is `aria-hidden` so the group name is not double-read (rule 171). The `<nav>` keeps `aria-label="View"` (shared with `BottomNav`; do not rename — it churns the e2e nav-name specs for no a11y gain). The `{METHOD} Workspace` tag (`MethodWorkspaceLabel`) is `hidden xl:inline` and lives at the left edge of the TopBar right cluster (first to drop as width tightens).
 - **One bordered, fixed-slot health cluster replaces the three free-floating badges.** Build the segments from the pure `healthClusterModel(...)` selector (a discriminated union — never branch on raw nulls in the view). The three segments adapt to methodology: **Agile** = Sprint · Points · Velocity; **Waterfall** = Forecast · At-risk · Critical; **Hybrid** = Sprint · Forecast · Critical. Slots are **fixed** — a zero/empty segment renders a calm static read ("0 critical", "—", "No active {iteration}"), never vanishing, so the cluster never reflows. The cluster carries `data-testid="health-cluster"` for e2e (Chromium prunes the named `role="group"` from its a11y tree, so Playwright `getByRole('group')` can't see it — query the testid, keep the `role="group" aria-label="Project health"` for screen readers).
 - **The Forecast (P80) segment is NEUTRAL, not amber.** A forecast date is informational, not a risk state — render the value `tppm-mono text-neutral-text-primary`, label `text-neutral-text-secondary`. This **supersedes the pre-v2 rules 21/39** (the standalone P80 *pill* used an outlined-at-risk style; the unified cluster does not — color is reserved for the actual at-risk/critical *signals*, rule 8). The null/"—" no-value read uses `text-neutral-text-disabled` (sanctioned by rule 119 for a no-value placeholder, with a `title` explaining why — "Run the scheduler").
 - **At-risk / Critical segments are `text-semantic-at-risk` / `text-semantic-critical`, pair the count with the word, and are static at 0.** A count > 0 is a button opening a `role="menu"` task popover (kept local to the cluster so it reads as one bordered unit, not a nested bordered pill); a count of 0 is a non-interactive static read (no dead drill-down button). Never color-only (rule 7/120/145).
 - **Velocity / Points respect the ADR-0104 privacy gate.** When `ProjectVelocity.velocity_suppressed` is true, the Velocity segment renders a **content-free privacy wall** (rule 168): a lock glyph + "Kept to the team", **no number** — the client never holds the value, the team owns the policy. The Points segment is **throughput-neutral** (#1161): points when `committed_points != null`, else an item count (`committed_task_count`), else the segment is omitted entirely — never an empty "Points" badge. Velocity surfaces `excluded_count` (ADR-0113) as a `· N excl` affordance. The "Sprint" noun comes from `useIterationLabel().singular` (ADR-0111/0116), never the hard-coded string.
 - **Below `md` (phones only)** the cluster collapses to a single `Health ▾` dropdown (rule 109) expanding the same segments; the cluster proper is `hidden md:flex` and the dropdown is `md:hidden`. The expanded cluster holds from the tablet breakpoint up (`md`, ≥ 768px) so the 768–1024px tablet range keeps the P80 forecast inline (issue #1562) — it does **not** collapse at `lg` any more.
