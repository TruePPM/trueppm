# Rule 196 — Methodology cascades Workspace → Program → Project but is NOT-NULL at every scope, so inheritance is POLICY-driven, not override-presence driven — never reuse the InheritableSelectField/null-sentinel pattern for it

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Methodology cascade (ADR-0107, issue 955 / issue 1169)*

**Methodology cascades Workspace → Program → Project but is NOT-NULL at every scope, so inheritance is POLICY-driven, not override-presence driven — never reuse the `InheritableSelectField`/`null`-sentinel pattern for it.** Unlike `iteration_label` and the sharing toggles (where `null` on a lower scope means "inherit"), `methodology` carries a concrete `AGILE`/`WATERFALL`/`HYBRID` at every level. The inheritance switch is the **workspace** `methodologyOverridePolicy` (`suggest` | `inherit` | `enforce`), exposed on `WorkspaceSettings`. The per-scope picker is therefore a plain radio group whose **editability is gated on the policy**, not a tri-state inherit control: `locked = ws.methodologyOverridePolicy === 'inherit'` (OSS never has an active Enterprise `enforce` provider, so `enforce` behaves like `suggest` on the client — only `inherit` locks). When locked, the picker is read-only and **displays `project.effective_methodology` / `program.effective_methodology`** (the server-resolved workspace default), NOT the scope's own stored override; when unlocked, it shows and edits the scope's own `methodology` and surfaces `inherited_methodology` as informational context. The server is the source of truth — a methodology PATCH under lock returns **403** — so the client lock is a render-gate that spares a doomed save, layered on top of the existing Admin+ `canEdit` gate (`editable = canEdit && !locked`). **Tab/view gating reads the SERVER-RESOLVED value, never the raw override**: `ViewTabs`, `ViewsMenu`, `BottomNav`, and `MethodWorkspaceLabel` all read `project.effective_methodology` (default `'HYBRID'` until loaded) so a workspace `inherit` lock correctly hides the other methodology's chrome. The Enterprise-only `enforce` policy radio is `disabled` with an `EnterpriseBadge` and its click is a no-op (it must never become the selected value on the OSS surface). Reference: `WorkspaceMethodologyPage`, `ProjectMethodologyPage`, `ProgramGeneralPage` methodology row, and the `effective_methodology`/`inherited_methodology` fields on `useProject` + the `Program` type.
