# Rule 240 — A control whose icon can imply a disabled/off/muted state (a slashed bell, a crossed-out eye, a muted speaker, a strikethrough) must reserve that glyph for a REAL such state driven by a server/preference fact — never render it as the resting appearance of an empty count

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Status-affordance glyphs: a "disabled/off/muted" glyph means an actual disabled state, never an empty one (Issue #1707)*

**A control whose icon can imply a disabled/off/muted state (a slashed bell, a crossed-out eye, a muted speaker, a strikethrough) must reserve that glyph for a REAL such state driven by a server/preference fact — never render it as the resting appearance of an empty count.** The `NotificationBell` (`features/shell/NotificationBell.tsx`) rendered the muted-bell glyph `🔕` whenever `count === 0` and the active bell `🔔` only when `count > 0`; the slashed bell is the universal "notifications turned off" symbol, so the default resting state (what every user sees most of the time) falsely read as *notifications disabled* even though no mute state exists. The fix: one plain active `BellIcon` (`components/Icons.tsx`, the SVG house style — never an emoji, which renders inconsistently across platforms) in **all** states; unread is conveyed by the count **badge** (`aria-hidden`, count carried in the button `aria-label` per rule 171) plus the `text-brand-primary` accent (color is never the sole signal — rule 6/1.4.1 — the badge digits and `aria-label` carry it). The icon shape never swaps between empty and non-empty. A genuine account-wide muted state now ships as **Do Not Disturb** (#1707, ADR-0292): the bell adds a **distinct crescent `MoonIcon` corner chip** — never a slashed bell — gated on the real `user.dnd_enabled` fact, and the DND state is carried in the button `aria-label` (rule 6); the count badge is unchanged. The preferred remedy for a real muted/DND state is a **semantically-different** glyph (a moon/quiet-mode mark), not a bell-off, because DND that keeps the in-app inbox live is not "notifications off". General principle: an "empty" data state and a "turned off" control state are different meanings and must not share a glyph. Reference: `NotificationBell.tsx`, `MoonIcon`/`BellIcon` in `Icons.tsx`.
