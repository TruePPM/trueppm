> Original section: *Mobile bottom rail caps at 5 slots; overflow goes to a BottomSheet, never a scroller (Issue #1464)*

**The `< md` `BottomNav` rail renders at most 5 `flex-1` cells: up to 4 primary tabs plus a "More" `<button>` in slot 5 when the reachable set exceeds 5 (ADR-0196). Overflow views open in a reused `BottomSheet` (`MoreSheet`) as ≥44px `NavLink` rows — NEVER a horizontal `overflow-x` scroller (that is the desktop strip's job, ADR-0134 rule 3; off-screen tabs are undiscoverable and fail the gloves/glare touch case).** The rail shares the desktop *set* of reachable views but not its order: compose the set the same way the desktop bar does — `groupedVisibleViewsForUser(effective_methodology, hidden)` where `hidden = user.hidden_views ∪ surfaceHiddenViews(effective_surface_visibility)` (ADR-0139 hide now applies on mobile; ADR-0193 `reporting` hides `reports`), then apply the `resources`→Scheduler+ role gate and prepend `overview` / append `settings` (both standalone, never hideable). Then split with the pure `selectMobileNav(reachable, methodology)` (`bottomNavItems.ts`) which orders methodology-priority-first (`MOBILE_PRIMARY_PRIORITY`) then canonical, caps at 5, and returns `{primary, overflow}`. Keep this mobile ordering **out of** `methodologyTabs.ts` (that file owns the desktop grouped bar and churns under ADR-0195). Two invariants: (a) `overview` always leads and `today` is always primary — do not let desktop group order (PLAN-first) bury Today (regresses #1324); (b) when a surface parked in the overflow is the active view, the More button must read active (`text-brand-primary font-medium`) and enrich its `aria-label` to `` `More, ${label} selected` `` so a view living in More (e.g. Settings) still reads as the active surface (issue 539). The More button is a dialog trigger — use `aria-haspopup="dialog"` + `aria-expanded`, NOT `aria-current` (that keyword is for the current-page link; use it on the primary tab `NavLink`s and the active overflow row instead). `BottomSheet` traps focus but does not restore it — the caller returns focus to the More button (`moreButtonRef.current?.focus()`) in `onClose`. When ≤5 views are reachable, render them all as tabs and omit More.
