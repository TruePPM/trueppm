# Rule 267 — A realtime membership/role change that targets the *current user* announces via a neutral toast.info with generic copy — never name a numeric-ordinal value the WS payload has not yet resolved to a label

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *A field's contextual-help affordance is the shared `FieldHelp` component, not a hand-rolled tooltip (Issue #1975)*

**A realtime membership/role change that targets the *current user* announces via a neutral `toast.info` with generic copy — never name a numeric-ordinal value the WS payload has not yet resolved to a label.** When `useProjectWebSocket` receives `member_added`/`member_role_changed`/`member_removed`, it invalidates `['project-member-self', projectId]` so every role gate (`canEdit`, `canManageScope`, Monte Carlo row…) reconciles instead of rendering write affordances that then 403 for up to the 5-min self-role staleTime (#2039). When the event's `payload.user_id` equals the current user (read from `['current-user']`, the same pattern the `task_updated` self-echo guard uses) AND the event is `member_role_changed`, it fires `toast.info('Your role in this project changed.')`. Three invariants: (a) **`info`, never `success`/`error`** — one message serves both promotion and demotion, and a role change is neither a success nor a failure; `success` would read congratulatory on a demotion, `error` would imply a failed action. (b) **generic copy — do not name the new role from the WS ordinal.** The payload carries only the numeric `role`; the human label arrives asynchronously via the invalidated self-role refetch, so naming it in the toast would either be wrong or require blocking on the refetch (gold-plating). (c) **toast only on `member_role_changed`, not `member_added`/`member_removed`** — the self-role query invalidation happens for all three, but a self add/remove is an access-boundary change surfaced by the `ProjectShell` unavailable gate (rule via #2040), not a role toast. Reference: `hooks/useProjectWebSocket.ts` (membership-events branch), `components/Toast/toast.ts`.
