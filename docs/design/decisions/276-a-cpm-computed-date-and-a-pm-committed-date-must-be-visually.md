# Rule 276 — A CPM-*computed* date and a PM-*committed* date must be visually distinct wherever a "no committed date" flag can fire — the computed value carries a non-color cue and a non-title-only accessible qualifier, so a cell showing the computed date never silently contradicts a flag/advisory that says the date isn't committed (sibling to rules 234/235)

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *AppShell owns the only `<main>`; the 404 keeps the shell (Issue #2184)*

**A CPM-*computed* date and a PM-*committed* date must be visually distinct wherever a "no committed date" flag can fire — the computed value carries a non-color cue and a non-`title`-only accessible qualifier, so a cell showing the computed date never silently contradicts a flag/advisory that says the date isn't committed (sibling to rules 234/235).** The root cause of the #317/#2312-2314 contradiction was that `TaskScheduleStrip`'s START cell rendered `task.start` (CPM `early_start`, auto-filled for every task) looking identical to a committed date, directly above/beside a flag saying "no committed start" — the user sees a concrete date and disbelieves the flag. When `isMissingCommittedStart(task)` holds (`!plannedStart && !isSummary && status ∈ {IN_PROGRESS,REVIEW,COMPLETE}` — the single shared predicate in `missingCommittedStart.ts`, used by BOTH the row chip and the drawer, so the two surfaces never drift), the computed value gets **three** cues, because no two of them reach every user: (a) a **dotted** underline — deliberately NOT the **dashed** underline that means "editable" on `DurationCell` (#2106), since the value is read-only-and-computed, not editable; (b) a `title` for pointer users AND a visually-hidden qualifier (`<span className="sr-only"> (computed, not committed)</span>`) so the meaning reaches screen-reader users too (a `title` alone is not accessible — rules 22a/121); (c) a **visible `computed` qualifier chip** beside the value (`ComputedStartValue`, #2379 — `rounded-chip px-1 py-px text-xs uppercase` on the rule-8b `bg-semantic-at-risk-bg text-semantic-at-risk` pair, matching `MissingCommittedStartChip`). The chip is what a **sighted pointer-free user** gets: (a) is a subtle line and (b) is hover-only or AT-only, so before the chip the cell still read as committed on touch — the very contradiction the rule exists to remove. The chip is `aria-hidden` and the fuller sr-only qualifier is retained (rule 216): "computed" is already carried accessibly, so announcing the chip too would double-read it, and "(computed, not committed)" is clearer than a bare "computed". The value wraps (`inline-flex flex-wrap`) rather than clipping — at the 480px drawer width a 4-across grid cell cannot hold the date and the chip on one line. The cue is scoped to non-milestones (a milestone's Date is a committed point, not a computed span endpoint). It pairs with the **advisory** (`role="status"`, advisory tone rule 138, amber rule-8b tokens `bg-semantic-at-risk-bg text-semantic-at-risk border-semantic-at-risk/80`) in the strip's `belowGrid` slot that names the gap and offers the two shared `useCommitStartOrTodo` remediations (Set committed start / Move to To Do) — the drawer is the *secondary* fix home (the row chip #2313 is primary; the far-right drawer must not be the sole home for a left-edge triage flag). The advisory lives in the editable strip only, so a Viewer sees the computed cue (informational) but no action buttons. Reference: `features/schedule/{missingCommittedStart.ts,TaskScheduleStrip.tsx,MissingCommittedStartChip.tsx}` (#2314/#2379, ADR-0603).
