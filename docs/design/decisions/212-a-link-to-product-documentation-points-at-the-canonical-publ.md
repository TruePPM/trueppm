# Rule 212 — A link to product documentation points at the canonical published docs site (https://docs.trueppm.com/...), NEVER an in-app /docs/... path

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Responsive rail/sidebar collapse: conditional-render on useBreakpoint, do NOT CSS-hide a duplicated control set (Issue #539)*

**A link to product documentation points at the canonical published docs site (`https://docs.trueppm.com/...`), NEVER an in-app `/docs/...` path.** The `docs/` and `packages/website/` trees are built and served by the Docusaurus/Astro site at `docs.trueppm.com` — the React app's router has no `/docs/...` route, so an in-app `<a href="/docs/administration/mcp-server">` is a dead link that 404s inside the SPA shell (or falls through to the not-found boundary). Render external documentation links as `<a href="https://docs.trueppm.com/<section>/<page>" target="_blank" rel="noopener noreferrer">` with the standard rule-4 `focus-visible` ring (a doc link is a standalone interactive control; the older settings text-links that omit the ring, e.g. `WorkspaceEmailPage`, predate rule 4 and are not the pattern to copy). Keep the path in step with the file's location under `packages/website/src/content/docs/` (`packages/website/src/content/docs/administration/mcp-server.md` → `/administration/mcp-server`). Reference: `ApiTokensManager.tsx` (the MCP "MCP server setup →" link in the connect panel), `WorkspaceEmailPage.tsx` (external issue links use the same `target`/`rel` pattern).
