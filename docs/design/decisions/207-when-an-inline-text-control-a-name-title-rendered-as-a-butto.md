> Original section: *Inline text control that is a row's sole open/edit affordance must meet 44px (Issue #1346)*

**When an inline text control (a name/title rendered as a `<button>`) is the *sole* open/edit affordance for a list row or group header — i.e. the row itself is not the click target — that control MUST meet the 44px touch target (rule 5), not just the text bounding box.** Wrap it `inline-flex min-h-[44px] items-center` (a negative `-my-*` keeps the *visual* header height compact while the hit area still reaches 44px), or — the alternative — make the entire row the click target the way `StoryRow` does. A bare `text-sm px-1 py-1` text button is ~28px tall and fails rule 5 on the one element a touch user must hit. This surfaced on the Product Backlog `EpicHeader` (#1346): clicking the epic *name* opens its detail drawer (the name is the edit affordance, mirroring how a story row opens its drawer), but the epic header row — unlike a `StoryRow` — is not itself clickable, so the name button carries the whole burden of the touch target. Pair the open affordance with the same **selection ring** the sibling rows use while the drawer is open (`selected ? 'ring-2 ring-inset ring-navy-700 dark:ring-reversed'` on the row, rule 164) so the open/selected state reads consistently across stories and epics. Reference: the epic-name button + `selected` prop in `EpicHeader.tsx`, `StoryRow` in `ProductBacklogPage.tsx`.
