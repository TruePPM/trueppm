# Rule 219 — A bulk-action control that displays an affected count (N) must derive its enabled/visible state — and, where it can, its N — from the *actionable subset* for that verb, not the raw filtered total; when no row in the current filter is actionable for that verb the control hides (or disables), mirroring the per-item gate

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Mobile bottom rail caps at 5 slots; overflow goes to a BottomSheet, never a scroller (Issue #1464)*

**A bulk-action control that displays an affected count `(N)` must derive its enabled/visible state — and, where it can, its `N` — from the *actionable subset* for that verb, not the raw filtered total; when no row in the current filter is actionable for that verb the control hides (or disables), mirroring the per-item gate.** When a surface gates a single-item action by an actionability predicate (status, permission), its bulk counterpart over the same set must apply the same predicate. Showing the raw filtered `N` on a bulk button whose server-side effect is only a subset produces a dishonest affordance — it promises `N`, delivers fewer, and in the worst case (a terminal-only filter) renders a dead control that promises `N` and does `0`, plus a confusing count/result mismatch between the button, the confirm dialog, and the result toast. When the client only holds the current page (so it cannot compute the exact server-wide actionable count), gate visibility on the filter that *can* contain actionable rows and let the confirm-dialog body copy + the result toast carry the true processed count; prefer a server-provided actionable count when one is available. Reference: the dead-letter inspector bulk bar (`DeadLetterInspectorPage.tsx` — `canBulkRequeue` gates Requeue-all to `dead`/`pending_retry`/all, `canBulkDrop` hides Drop-all under a `dismissed` filter; #695, ADR-0210), mirroring the per-task `canRequeue`/`canDrop` gate in the same file.
