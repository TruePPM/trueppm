# Rule 282 — Every Grid toolbar facet is the shared MultiSelectFacet, all three are multi-select, and their params are comma-separated lists parsed by one codec (ADR-0624)

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *AppShell owns the only `<main>`; the 404 keeps the shell (Issue #2184)*

**Every Grid toolbar facet is the shared `MultiSelectFacet`, all three are multi-select, and their params are comma-separated lists parsed by one codec (ADR-0624).** Owner · Status · Label read left→right in the toolbar and in the same order in the chip strip, and they are literally one control with three option lists — the trigger, panel, roving-tabindex keyboard model and 44px option row live in `components/filters/MultiSelectFacet.tsx`; `LabelFacet` / `OwnerFacet` / `StatusFacet` supply only options and copy. Do not add a fourth facet by copying a panel: three copies of a roving tabindex drift within one release (this rule exists because #2383 built the model once inside `LabelFacet` and #2387 immediately needed two more). Six invariants: (a) **one parser, one serializer** — `parseIdList`/`serializeIdList` in `components/filters/facetParams.ts`, which `labelFilter.ts` delegates to; a **single value is a one-item list**, which is the entire back-compat story for pre-existing `?owner=`/`?status=` bookmarks (no redirect, no version bump). (b) **`taskMatchesOwners` accepts a resource id *or* a name** — new links are id-based (a rename must not break a shared URL) but `?owner=` shipped as a name match and those links exist; dropping name matching would silently break them while the arity claim still "passed". (c) **the option catalog is the full domain with visible `0` counts over loaded rows** — Owner = the project's *resource pool* grouped `On these rows` (by count desc, name tiebreak) then `All members`; Status = every `TaskStatus` in **fixed pipeline order, never re-sorted by count**, zero-counts kept and selectable. A short list is not a feature: "nobody is assigned" and "that person has no rows here" must stay distinguishable. (d) **one panel at a time, three separate tab stops** — the host owns an `openFacet` state (a facet cannot know a sibling opened); `←`/`→` deliberately do *not* move between triggers because they fight the text cursor in the toolbar's search input. (e) **the chip strip renders one chip per *value* in toolbar order** with per-facet focus re-seating — removing the last Status chip lands on the *Status* trigger, not a single shared fallback two controls away. (f) **the multi-facet empty state names each facet's standalone count and offers to drop the one that recovers the most rows** — with AND-across, an empty intersection otherwise reads as a broken filter. Do **not** virtualise the option list: virtualising a roving-tabindex list unmounts the focused option as it scrolls out and drops focus to `body`; cap and scroll instead. Reference: `components/filters/{MultiSelectFacet,OwnerFacet,StatusFacet,LabelFacet,facetParams,ownerFilter,statusFilter}.*`, `features/grid/{filters.ts,ChipStrip.tsx,GridEmptyState.tsx,GridView.tsx}`, `docs/adr/0624-grid-owner-status-facets.md`.
