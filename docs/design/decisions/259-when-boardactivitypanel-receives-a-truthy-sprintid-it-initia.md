# Rule 259 — When BoardActivityPanel receives a truthy sprintId, it initializes filters.scope = 'sprint' and renders the role="group" aria-label="Activity scope" toggle ("This sprint" / "Whole board"); with no sprint the toggle is omitted entirely (never an empty control group) and scope is 'board'

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *The board activity rail opens sprint-scoped by default; `scope` is view context, not filter state (Issue #1946, ADR-0412)*

**When `BoardActivityPanel` receives a truthy `sprintId`, it initializes `filters.scope = 'sprint'` and renders the `role="group" aria-label="Activity scope"` toggle ("This sprint" / "Whole board"); with no sprint the toggle is omitted entirely (never an empty control group) and scope is `'board'`.** Three invariants a refactor must preserve: (a) **`scope` is NOT filter state** — it is deliberately excluded from `isFiltered` and from the `DEFAULT_FILTERS` reset, so **"Clear" preserves the current scope** (`onChange({ ...DEFAULT_FILTERS, scope: filters.scope })`); scope is a view context (which cards' activity is shown), not a narrowing filter, and resetting it on Clear would yank the user out of their sprint. (b) **label-vs-value split** — the sprint-transition event-type chip is *labeled* **"Scope changes"** for findability (the `entered_sprint`/`exited_sprint`/`moved_sprint` events PO/SM watch) while its underlying `TypeGroup` value stays `'sprint'`; never rename the value (it is the server `type=` param contract). (c) **empty-state precedence** — a type/actor/time filter narrowing to zero must win over the sprint-scope empty copy ("No matching activity in this sprint." not "No activity in this sprint yet."), or an active filter reads as an empty sprint and the user never thinks to clear it. Density note: the whole filter row (scope, type, time) uses the shared 28px `Chip` (`h-7`); this is an accepted, documented density for the `BoardActivityFilters` bar — if the 44px touch floor (rule 5) is ever enforced here, lift the **entire** row's hit area, never single out one group (uniformity beats a lone compliant control). Reference: `features/board/activity/BoardActivityFilters.tsx`, `BoardActivityPanel.tsx`, `useBoardActivity.ts`.
