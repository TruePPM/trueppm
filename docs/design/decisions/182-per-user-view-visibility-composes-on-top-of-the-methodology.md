# Rule 182 — Per-user view visibility composes on top of the methodology filter, never instead of it, and Overview is never hideable

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Per-user view visibility — "Customize views" (Issue 220, ADR-0139)*

**Per-user view visibility composes on top of the methodology filter, never instead of it, and Overview is never hideable.** The "Customize views" menu (`ViewsMenu.tsx`, mounted in the `TopBar` right cluster before `MethodWorkspaceLabel`; self-suppresses off-project and on `/settings/*` like `ViewTabs`) toggles only views that survive `groupedVisibleViews(methodology)` — a view the methodology preset hides (ADR-0041) never appears as a toggle. The effective bar is `groupedVisibleViewsForUser(methodology, hiddenViews)` (methodology filter → personal hidden-set filter → role gate, in that order). `overview` (`STANDALONE_LEADING`) is rendered outside the personal filter and has no toggle — this is the structural "nav never empty" guarantee (no runtime min-count check). A hidden view's route still renders (cosmetic hide only — never a 404/permission change); it stays reachable via the menu and a ⌘K "Go to {label}" jump (`useCommandItems`, `current` group, `tag: 'View'`). The hidden set is the per-user **global** `UserProfile.hidden_views` (server fact on `/auth/me/`, read via `useCurrentUser().hidden_views`; written via `useUpdateHiddenViews` PATCH to `/auth/me/profile/` with the full desired set, optimistic local state reverted on error). Toggle rows are `role="menuitemcheckbox" aria-checked` with an eye/eye-off glyph swap as the WCAG 1.4.1 signal (label dimming alone is not enough; hidden-label color floor is `neutral-text-secondary`, never `-disabled` — rule 169). "Reset to {methodology} default" clears only the methodology-visible hidden keys, preserving global hides for views not shown on this project. Render metadata (label + icon) is shared via `viewMeta.ts` (`VIEW_TAB_META`) so the bar, the menu, and the palette never drift; the server-side hideable vocabulary lives in `profiles/constants.py::HIDEABLE_VIEW_KEYS` (keep the two in sync). Mobile `BottomNav` does **not** apply the personal set in 0.3 (deferred). The `/me/settings/general` variant (`ViewVisibilitySection.tsx`) is the same preference as a plain `role="switch"` form (no methodology context → lists all hideable keys, "Reset to default" clears all). Reorder and a future admin-pin/force-hide are out of scope (the admin-lock is Enterprise; this seam — the single composition function — is where it would register, with a *visible* disclosure indicator, never a silent lockout).
