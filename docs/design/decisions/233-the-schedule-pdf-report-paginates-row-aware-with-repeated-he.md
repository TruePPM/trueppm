# Rule 233 — The schedule PDF report paginates ROW-AWARE with repeated headers — it never slices the rasterized bitmap at a fixed pixel height

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Client-rasterized export surfaces — SVG stroke + row-aware pagination (Issue #1694, ADR-0276)*

**The schedule PDF report paginates ROW-AWARE with repeated headers — it never slices the rasterized bitmap at a fixed pixel height.** The single-column (chart-fits-one-page-wide) Layout-A report breaks only on safe boundaries (between whole Gantt rows, before the CP card, between CP-list grid rows, before the keep-together footer) and repeats the header a continuation page needs: a Gantt continuation re-composites the frozen **Activity + date-scale** header band from the source bitmap (pixel-accurate, so bars stay aligned to dates); a CP-chain continuation stamps a **"Critical Path Chain (Continued)"** running header as real `pdf.text`; the bottom-right caption is **"Page n of N"**. The layout tags its blocks with `data-print-vmark` markers (`gantt` / `gantt-rows` / `cp` / `cp-list` / `footer`) + stamps `data-print-gantt-row-count` / `data-print-cp-row-count`; the rasterizer **measures** the marker rects (`getBoundingClientRect` on the off-screen-but-laid-out surface) — never stamps text-driven block heights from React — and feeds the pure, unit-tested `scheduleVerticalPlan.ts` planner. The wide multi-column (#1440) horizontal-banding path is unchanged and keeps its "Sheet n of N" wording. Masthead/KPI/legend appear on page 1 only. Reference: `scheduleVerticalPlan.ts`, `exportSchedulePdf.ts::{readVFlowGeometry,paginateVerticalReport}`, the `data-print-vmark` markers in `SchedulePrintLayout.tsx`.
