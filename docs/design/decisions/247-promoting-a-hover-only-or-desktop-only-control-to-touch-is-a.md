# Rule 247 — Promoting a hover-only or desktop-only control to touch is a touch-target-and-focus change, not just a visibility flip — audit size, hit area, and focus restoration when you make a control visible/active below md (#1770)

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Modal focus traps: multi-state dialogs re-seat via focusKey; nested confirm dialogs own their own trap (Issue #1776)*

**Promoting a hover-only or desktop-only control to touch is a touch-target-and-focus change, not just a visibility flip — audit size, hit area, and focus restoration when you make a control visible/active below `md` (#1770).** Removing `hidden md:*` or adding `max-md:opacity-100` surfaces a control that was previously mouse-only; on a phone it now must clear three bars it didn't before: (a) **Size** — the tap target is ≥44px on mobile. A flat desktop `h-8` (32px) is wrong once the control is a primary mobile affordance; chrome controls follow the responsive-shrink pattern their TopBar siblings use (`TimerChip`/`NotificationBell`: `h-11 w-11 md:h-7`), i.e. `h-11 md:h-8`. (b) **Hit area** — a row/card affordance that *can't* resize (a `w-4` drag handle, a `w-6` `···` glyph) gets a 44px touch zone via a mobile-scoped transparent pseudo-element: `relative max-md:before:absolute max-md:before:content-[''] max-md:before:-inset-[14px]` (16px + 2×14px = 44px) — scope it to `max-md:` so the invisible zone never captures clicks on desktop where the control is hover-hidden. This mirrors `BoardCard`'s always-on `before:inset-[-10px]`. (c) **Focus restoration** — a control that moves from an anchored popover (`useFocusTrap`, which restores focus to its trigger on close) to a shared `BottomSheet` must restore focus itself: `BottomSheet` deliberately leaves close-side restoration to the caller, so the mobile branch keeps a `triggerRef` and `.focus()`es it when the sheet transitions open→closed (an `isMobile`-gated effect), or focus drops to `<body>` after submit/cancel/scrim/Escape — an asymmetry with the desktop path the same component guarantees. Gate the breakpoint with `useBreakpoint() === 'sm'` (`< md`), render exactly one shell (`open && !isMobile` popover vs `isMobile` sheet) so there is no double focus-trap and no duplicate-`id` collision, and scope any shared roving-focus `querySelector` to the form element (a `formRef`), not the shell, so it resolves under either surface. Reference: `features/timeentry/QuickLogTime.tsx`, `features/board/BoardCard.tsx` (`before:inset-[-10px]`), `features/grid/OutlineRow.tsx`, `components/ui/BottomSheet.tsx`, `hooks/useBreakpoint.ts`.
