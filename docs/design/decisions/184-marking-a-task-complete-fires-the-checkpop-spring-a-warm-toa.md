# Rule 184 — Marking a task complete fires the checkpop spring + a warm toast from the completion *call site's* success path — never from the generic edit mutation — and the contributor surface (My Work) gets a one-tap checkbox

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Task-complete celebration (Issue 1226, ADR-0126)*

**Marking a task complete fires the checkpop spring + a warm toast from the completion *call site's* success path — never from the generic edit mutation — and the contributor surface (My Work) gets a one-tap checkbox.** Completion is the v2 "moment of delight": the check element plays `motion-safe:animate-checkpop` (rule 181, one-shot, cleared on `animationend`) and `toast.warm("Nice — {name} done.")` fires (rule 183). Wire it at each completion call site's `mutate(…, { onSuccess })` — `MyWorkTaskRow.completeTask` (the checkbox + the picker's Complete entry, `useMyWorkStatusUpdate`) and `TaskListRow.handleToggleComplete` (Space / context-menu, `useToggleComplete`, **only when transitioning INTO complete**, never un-completing) — **NOT inside the generic `useUpdateTask` / `useMyWorkStatusUpdate` hook bodies**, which also serve non-completion edits (name/dates/other status moves) and would over-fire. The spring fires immediately on click for snappy feedback; the warm toast fires on confirmed success (the mutation is optimistic with rollback — never celebrate a reverted completion). My Work's checkbox is a 44px touch target on mobile / compact on md+ (`h-11 w-11 md:h-7 md:w-7`), `aria-pressed`, disabled-when-complete (un-complete via the status picker), the 18px box carrying the sage fill + `✓` when complete. The schedule task list has no checkbox (completes via Space/menu) so it gets the warm toast only; board complete is a follow-up.
