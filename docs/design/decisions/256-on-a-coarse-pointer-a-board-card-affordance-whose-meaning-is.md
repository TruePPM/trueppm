> Original section: *A board-card affordance whose meaning is hover-only or truncated must promote to a tap-to-peek on coarse pointers (Issue #1947)*

**On a coarse pointer, a board-card affordance whose meaning is otherwise hover-only (a `title`/`aria-label` on a display span) or truncated (a clipped title) must promote to a tap-to-peek `CardPeekButton` (`features/board/CardPeekButton.tsx`), gated on `useIsCoarsePointer()` so the fine-pointer render stays byte-identical.** `title=`/`aria-label` are unreachable on touch and a `truncate` line silently drops its tail there, so on mobile (where boards force compact density, rule 193) the compact card's worst-offender health badge and its truncated title strand meaning the user cannot recover. The fix is NOT to persist a mobile comfortable-density override — rule 193 forces compact deliberately; the fix is a real `<button aria-expanded aria-controls>` that toggles a portaled `role="note"` popover carrying the full text (rule-253 disclosure mechanics: `createPortal` to `document.body`, `position:fixed` from the trigger rect, flip-above + horizontal clamp, close on Escape/"Got it"/outside-pointerdown/scroll(capture)/resize, return focus to trigger, `before:inset-[-12px]` ≥44px hit target, rule-4 focus ring, `stopPropagation` so the card-open handler never fires). Four invariants: (a) **coarse-only** — every new trigger is gated on `useIsCoarsePointer()`; on a fine pointer the branch collapses to today's exact DOM (no button, no aria), so desktop — including desktop *compact* density — is byte-identical. (b) **title disclosure is a dedicated end-of-title glyph** — an ellipsis (`MoreHorizontalIcon`, never an emoji, rule 242) `<button>` mounted **only** when `useIsCoarsePointer() && useIsOverflowing(titleRef)`; when the title fits, render nothing (rule 122); the title text itself is never the trigger — the card body stays the task-open target. (c) **zero added height** — the closed peek is portaled, so it adds no layout and the 36px compact bar height is unchanged whether or not the affordance is present. (d) **tone stays on the trigger, peek stays neutral, color is never the sole signal** — the badge trigger keeps its semantic tone (`cardSignalToneClass`), the peek surface uses neutral tokens only, and the peeked text is the full `srText` sentence (never color-only). Reference: `features/board/CardPeekButton.tsx`, `features/board/BoardCard.tsx` (compact branch), `hooks/useIsOverflowing.ts`.
