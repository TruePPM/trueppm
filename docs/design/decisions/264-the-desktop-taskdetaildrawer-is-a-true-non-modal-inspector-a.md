**The desktop `TaskDetailDrawer` is a TRUE non-modal inspector (`aria-modal="false"`, no Tab focus-trap, no scrim) so the Gantt/Board behind it stays live and clickable — parity with the backlog/risk drawers (rules 89/164/185, ADR-0051) and reconciling the code to rule 185, which already forbade the desktop scrim. Mobile stays a modal 85vh bottom sheet (`aria-modal="true"` + `useFocusTrap`). Four invariants a refactor must preserve (#1978, ADR-0437):** (a) **non-modal desktop, modal mobile** — the trap engages only at the `sm` breakpoint via `useFocusTrap(isMobile && isOpen && !anyGuardOpen)` on the mobile shell ref (mirroring `StoryDetailDrawer`); the desktop shell is `aria-modal="false"` with no trap and no backdrop. (b) **a swap must not silently clobber a dirty draft** — the drawer renders a local `renderedTask` that normally tracks the `task` prop but deliberately *lags* it during a swap-while-dirty: when the host moves selection to another task while the name/notes draft is dirty, the incoming task is parked as `pendingTask` and the guard is raised, keeping the current task + its draft on screen; a **clean** swap reseeds instantly (the fast cross-reference path) and a server update to the *same* task never reseeds (identity unchanged → the concurrent-edit banner surfaces it). **Never auto-save on swap** — that violates the #1977 no-auto-flush contract. (c) **the swap guard offers three verbs — Keep editing (Escape) · Discard & open · Save & open (primary, initial focus) — all of which resolve the pending swap** (Save/Discard advance to `pendingTask`; a failed save holds the dialog open with its inline `role="alert"` error and keeps `pendingTask`). While a Save is in flight **every** dismissal path — buttons, backdrop, AND Escape — is inert (`keepSwapEditing` no-ops on `isSaving`); a mid-save cancel must never race the pending `onSuccess` into swapping to the abandoned task. It is the shared `UnsavedChangesDialog` extended with an optional `onSaveAndContinue` + contextual copy (rule 217) — not a hand-rolled dialog. Because the host already moved its selection before the drawer saw the swap, **Keep editing** calls the drawer's `onSwapCanceled(keptTaskId)` so the host restores the prior selection highlight (Schedule/Board/Sprints wire it to `setSelectedTaskId(keptId)`; a host with no persistent selection needn't). (d) **focus-restore on close is best-effort, never `<body>` (WCAG 2.4.3):** the drawer captures the opener on open and on close walks a ladder — captured opener if still connected/visible → optional host `getRestoreTarget(taskId)` → the app `<main>` (made `tabIndex=-1`) → never `<body>`. Desktop-only; mobile restore is the bottom-sheet trap's own job. `getRestoreTarget` is the documented host extension point for a precise target (Board card / canvas viewport); when unwired the captured-opener → `<main>` fallback still never strands focus. Reference: `features/schedule/TaskDetailDrawer.tsx`, `components/dialog/UnsavedChangesDialog.tsx`, `hooks/useFocusTrap.ts`, `features/project/backlog/components/StoryDetailDrawer.tsx` (the sibling non-modal contract).
