# Rule 272 — A read-only / locked control names the remedy *specific to its lock reason* and the control that performs it — never one generic message that is wrong for some of the states it covers

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Custom-field marks are the lowest-priority, opt-in, empty-hiding occupants of a board card (Issue #1989, design pending)*

**A read-only / locked control names the remedy *specific to its lock reason* and the control that performs it — never one generic message that is wrong for some of the states it covers.** When a single read-only branch is reachable for more than one reason, the guidance (aria-label + `title`) must **branch on the reason**, because the fix differs per reason and a shared message is actively misleading for the states it does not apply to. The bug this prevents (#2174): the weekly `TimesheetCell` had one `!editable` branch written for the multi-entry case, so once a week was submitted **every** locked cell announced "…, N entries — edit on My Work" — wrong remedy (submission is a week-level marker; the fix is *Reopen week*, not My Work) and broken grammar on the single/empty cells the branch was never meant to cover ("0 entries", "1 entries"). The cell now takes a `lockReason: 'multi-entry' | 'submitted'` prop and branches: `submitted` → "week submitted, reopen to edit (Reopen week, top right)" naming the real top-right control; `multi-entry` → "N entries — edit on My Work". Three rules fall out: (a) **name the actual control** that unlocks the state (its button label + where it is), not a generic "you can't edit this"; (b) **precedence when a cell qualifies for two reasons** goes to the one whose remedy actually works — a multi-entry cell stays `multi-entry` even on a submitted week, because reopening would not unlock it (ADR-0224 keeps ≥2-entry cells read-only); the grid computes `lockReason={!cell.editable ? 'multi-entry' : submitted ? 'submitted' : undefined}`. (c) **pluralize any count in the copy** (`entryCount === 1 ? 'entry' : 'entries'`) and render a value-bearing locked cell focusable (so the guidance is heard in SR focus mode) while an *empty* locked cell is inert/non-focusable with a muted `·` (no per-blank-day tab stop, no "0 entries" announcement). Reference: `features/timesheet/{TimesheetCell.tsx,TimesheetGrid.tsx}` (#2174).
