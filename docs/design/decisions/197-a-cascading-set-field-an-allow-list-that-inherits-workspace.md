# Rule 197 — A cascading set field (an allow-list that inherits Workspace → Program → Project) is a TRI-STATE override (null = inherit, [] = explicit empty, [...] = explicit set), rendered with InheritableMultiSelectField — never collapse the empty set and the inherit sentinel into one

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Inheritable set (allow-list) field (ADR-0153, issue 976)*

**A cascading set field (an allow-list that inherits Workspace → Program → Project) is a TRI-STATE override (`null` = inherit, `[]` = explicit empty, `[...]` = explicit set), rendered with `InheritableMultiSelectField` — never collapse the empty set and the inherit sentinel into one.** This is the set analog of the `InheritableToggleField`/`InheritableSelectField` family (rule for ADR-0135/0144): the lower scope's own column is `string[] | null` where `null` means "inherit the parent's resolved value" and `[]` means "explicitly allow nothing" — two distinct states the UI must keep separate (an empty allow-list with attachments on is a real, deliberate "no file can be uploaded" policy, surfaced as a `role="note"` warning keyed off the **resolved effective** value, not the raw override). `InheritableMultiSelectField` wraps an inherit/override `role="radiogroup"` pair around an `AttachmentTypesChecklist`: "Inherit (N types)" emits `null`; "Override" **seeds the checklist from the inherited set** (`onChange(value ?? inherited)`) so it opens on reality, not empty; a non-blocking delta line (`Same as parent` / `Narrower than parent (removed: …)` / `Wider than parent (added: …)`) compares the override to `inherited` and is informational only — it never prevents diverging. Below Admin (`!canEdit`) it collapses to a read-only comma-joined summary + provenance + "View only.", one composite `aria-label` with `aria-hidden` children (rule 171). The checklist itself uses **native `<input type="checkbox">` + `<label htmlFor>`** grouped under `<fieldset><legend>`, where the legend is a group checkbox that goes `indeterminate` on partial selection and toggles all children; the **permanent security denylist** (`text/html`, `image/svg+xml`, `application/xhtml+xml`) renders in an "Always blocked" group as DISABLED `aria-disabled` rows that are **NOT real inputs** — they can never enter the value, mirroring the server's subtract-the-denylist guarantee in the UI. The catalog + `labelForMime` fallback live in `lib/attachmentTypes.ts` (keep in step with the backend system default; unknown server MIMEs fall back to the raw string). The Workspace (root, non-null) uses a bare `Toggle` + bare `AttachmentTypesChecklist`; Program/Project use `InheritableToggleField` + `InheritableMultiSelectField`. The client allow-list that gates the task-drawer upload validator is the project's **server-resolved** `effective_allowed_attachment_types` threaded into `AttachmentDropZone`/`useTaskAttachments` — there is no static client-side MIME Set anymore (the old `ALLOWED_ATTACHMENT_MIMES` is gone). When the resolved `effective_attachments_enabled` is false, the drawer keeps listing/downloading existing files but replaces the add-controls with one muted `role="note"` line (shown only to users who would otherwise have the controls). Reference: `InheritableMultiSelectField`, `AttachmentTypesChecklist`, `WorkspaceAttachmentsPage`/`ProgramAttachmentsPage`/`ProjectAttachmentsPage`, `AttachmentSection`/`AttachmentDropZone`, and `lib/attachmentTypes.ts`.
