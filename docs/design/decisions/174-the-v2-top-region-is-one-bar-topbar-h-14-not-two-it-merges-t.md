**The v2 top region is ONE bar (`TopBar`, `h-14`), not two — it merges the former context row + view row; the nav tabs scroll, the right cluster is pinned, and wayfinding is adaptive to rail state.** ADR-0134 supersedes the two-row split of ADR-0127/0128. Reference: `features/shell/TopBar.tsx`, `ShellNavScroller.tsx`. There is no `ContextBar.tsx` (deleted). The bar is `flex items-center` (never wraps): a `shrink-0` left group (mobile hamburger / desktop rail-re-open ≡), the adaptive identity, the `flex-1 min-w-0` nav scroller, then the `ml-auto shrink-0` right cluster (`MethodWorkspaceLabel` · `HealthCluster` · `CreateMenu` · `TaskRunIndicator` · `PresenceAvatarStack` · `NotificationBell` · `UserMenu`).
 - **Adaptive identity.** The `Breadcrumb` renders in the bar ONLY when the rail is not persistently visible: always on mobile (the rail is a drawer), and on desktop only when `sidebarCollapsed` (where it is the sole wayfinding and the hidden rail freed the width). When the rail is open on desktop it is `md:hidden` — `display:none`, which removes it from the a11y tree; **never `aria-hidden` on a still-rendered nav, and never a base-`hidden` that would also strip it on mobile.** It duplicates the rail's highlighted program/project otherwise — do not render it always-on.
 - **Scrollable nav, never icon-only, never clipped.** `ShellNavScroller` wraps `ViewTabs`/`ProgramTabs` in an `overflow-x-auto min-w-0` region so the ~950–975px grouped strip scrolls horizontally below ~1440px instead of clipping or dropping labels. Tab **text labels never degrade to icon-only** (VoC 🔴 + WCAG 1.1.1); the group labels drop before the strip scrolls. The active tab (`[aria-current="page"]`) is auto-scrolled into view on route change. Scroll affordances (edge fade `from-chrome-surface to-transparent` + chevron) render **only when the strip overflows** in that direction; chevrons are pointer-only (`tabIndex={-1}`) — the tabs are a `<nav>` of links (NOT a `tablist`), so sequential Tab focus + the browser's scroll-focused-into-view is the keyboard path, not arrow-key roving tabindex. The `HealthCluster` stays pinned (never behind a tab scroll); it collapses to `Health ▾` only on phones below `md` (rule 172/109), staying expanded with P80 inline across the tablet range (issue #1562).
 - **Tab focus ring is `ring-inset`, not offset, inside the scroller.** Because `overflow-x-auto` forces `overflow-y: auto`, an offset focus ring (`ring-offset-1`) on an `h-full` tab is clipped top/bottom (WCAG 2.4.7). `ViewTabs`/`ProgramTabs` links therefore use `focus-visible:ring-2 focus-visible:ring-inset focus-visible:ring-brand-primary` (no offset) — the rule-137 precedent for rings in constrained/bordered contexts. Do not reintroduce `ring-offset-*` on tabs inside a scroll region.
 - **Theme toggle has exactly one home: `UserMenu`.** The standalone `ContextBar`/shell `ThemeToggle` is removed; do not re-add a second always-on theme control to the bar.
