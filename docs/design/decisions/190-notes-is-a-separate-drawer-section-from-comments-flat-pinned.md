# Rule 190 — Notes is a SEPARATE drawer section from Comments — flat, pinned-first, immutable rows; never folded into the comment thread

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Task notes (Issue 740, ADR-0143)*

**Notes is a SEPARATE drawer section from Comments — flat, pinned-first, immutable rows; never folded into the comment thread.** The task's why/decision log lives in `NotesSection` (`features/schedule/sections/NotesSection.tsx` + `NotesComposer.tsx`, hooks in `useTaskNotes.ts`), registered on the **activity** tab at **priority 480** — just above Comments (500) — so the record-of-decisions reads before the discussion. Notes differ from Comments deliberately: no threading/replies, no @mention, no reactions/acks, no attachments; each row is one author + timestamp + body, ordered pinned-first then newest (the server orders; the client does not re-sort). Pin is open to any MEMBER+ (`usePinNote`); edit is author-only within the window (rule 192); delete is author-or-ADMIN. All write controls gate on `editable = canEdit ?? canEditTask(userRole)` (rule for ADR-0133) — a Viewer sees every note but no composer/pin/edit/delete. The **freshness signal** is the server-annotated `latest_note_at` (mapped to `task.latestNoteAt`), surfaced as a `📝 {relative}` chip on the board card (`BoardCard`, non-compact only) and on the schedule row name's composite title/aria-label + a `📝` marker (`TaskListRow`) — the Gantt bar is canvas-rendered so it carries no DOM tooltip; the row name is the carrier. WS `task_note_*` events invalidate `['task-notes', taskId]` **and** `['tasks', projectId]` (so peers' freshness chips refresh). The `decision` field exists on the `TaskNote` type as the #748 seam but is **never surfaced** in this UI.
