# Rule 109 — The health surface is a single all-width status chip + role="dialog" popover — NOT a responsive md:flex / md:hidden split

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.
>
> Original section: *Shell Navigation Rules (Issues #204–#205)*

**The health surface is a single all-width status chip + `role="dialog"` popover — NOT a responsive `md:flex` / `md:hidden` split** (issue #205; tablet breakpoint #1562; reshaped to the chip in #1644, ADR-0128 §B progressive disclosure). `HealthCluster.tsx` renders one `data-testid="health-cluster"` chip `<button>` at **every** width (no breakpoint-gated dual render): a health **dot** (`aria-hidden`, rule 6), the worst-state **word** (`On track` / `On watch` / `At risk` — the non-color signal, rule 6; derived from the project-wide `at_risk_count` / `critical_count` on `useShellStats`, independent of the methodology segment set), an optional **neutral** P80 forecast fragment (`hidden sm:inline-flex`; neutral even inside a red/amber chip, rule 172), and a caret. Clicking it toggles a popover (`role="dialog"` `aria-label="Project health"`, `shadow-pop` pop-surface exception to rule 1) whose rows are exactly the methodology's `healthClusterModel` segments — forecast band (P50 + P80 rows, neutral, `Details ›` opens the MC panel, issue #196), at-risk/critical drill groups, sprint/points/velocity — with the ADR-0104 velocity privacy wall honored (rule 168, no number when suppressed). The popover **must** trap focus with `useFocusTrap` (rule 206): focus in on open, Esc closes + restores focus to the chip, outside pointer-down closes. **Do NOT reintroduce the pre-#1644 `hidden md:flex` expanded cluster or the `md:hidden` "Health ▾" phone dropdown** — the all-width single control is deliberate (both to reduce the surface and to avoid the rule-211 `hidden`-toggle double-render, where the same `getByRole` control resolves to two DOM nodes). The chip word colors clear WCAG 1.4.3 in both modes (at-risk `#92400E` / critical `#B91C1C` light, `#FB923C` / `#F87171` dark; on-track word is neutral `text-neutral-text-secondary` with the green carried by the dot).
