# Rule 239 — The schedule/board PDF export carries a SELECTABLE invisible-text layer over the raster — every content string a reader needs (row labels, KPI values, the critical-path chain, board cards/columns) must be marked data-print-text="<role>" on the print layout, or it will not be selectable/searchable/screen-reader-perceivable (ADR-0289, #1687)

> **Decision record.** Moved out of `packages/web/CLAUDE.md` by #2433 (ADR-0653): precedent bound to one surface, not a general invariant. It is still binding for the surface it governs.

> Original section: *Responsive table→card reflow for the task Grid (Issue #1701)*

**The schedule/board PDF export carries a SELECTABLE invisible-text layer over the raster — every content string a reader needs (row labels, KPI values, the critical-path chain, board cards/columns) must be marked `data-print-text="<role>"` on the print layout, or it will not be selectable/searchable/screen-reader-perceivable (ADR-0289, #1687).** The export is still a `html-to-image` raster (the visual layer), but `pdfTextLayer.ts` now stamps a real jsPDF text run in **rendering mode 3 ("invisible")** over each marked element's measured box, re-projected through the *same* per-page scale/offset transform each pagination branch already computes (single page, vertical header-repeat, week-snapped label-strip + chart band, plain banding, board banding). The rules: (a) new content in `SchedulePrintLayout.tsx` / `BoardPrintLayout.tsx` that a person would read on paper **must** get a `data-print-text` marker (roles: `masthead`/`kpi`/`row`/`cp`/`footer` for schedule, `masthead`/`column`/`lane`/`card`/`footer` for board) — decorative swatches, `title`-tooltip-only bars, and duplicate strings stay unmarked; (b) markers are emitted in **DOM document order = logical reading order** (masthead → KPIs → rows → CP chain → footer), because jsPDF cannot emit a PDF/UA StructTree — content-stream order *is* the reading-order guarantee; (c) the collector uses **`getBoundingClientRect`** (measured, not layout constants) so it serves both the schedule's fixed-pitch rows and the board's variable-height cards, and skips zero-area rects so jsdom/unmeasured surfaces just get no layer (raster still exports); (d) `stampTextLayerForPage`/`setPrintDocumentMetadata` are `typeof`-guarded so the hand-rolled jsPDF test double is unaffected unless it opts in by stubbing `text`/`setLanguage`/`setProperties`. Full PDF/UA structure-tree tagging is **deferred** (needs a server-side renderer, which reverses ADR-0159). Reference: `packages/web/src/features/export/pdfTextLayer.ts`, `exportSchedulePdf.ts`, `exportBoardPdf.ts`, the `data-print-text` markers in both print layouts.
