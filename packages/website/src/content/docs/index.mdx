## Start with the engine, not the platform

You should not have to install a platform to find out whether its scheduling is real. TruePPM's engine is a **separate Apache 2.0 Python package** — the same code the platform runs on, versioned in lockstep. No server, no database, no account:

```bash
pip install trueppm-scheduler
```

```python
from datetime import date, timedelta
from trueppm_scheduler import schedule, Project, Task, Dependency

result = schedule(Project(
    id="p-1", name="Verify me", start_date=date(2026, 1, 5),
    tasks=[
        Task(id="design", name="Design", duration=timedelta(days=5)),
        Task(id="build",  name="Build",  duration=timedelta(days=10)),
        Task(id="docs",   name="Docs",   duration=timedelta(days=3)),
    ],
    dependencies=[Dependency(predecessor_id="design", successor_id="build")],
))

print(result.critical_path)                                            # ['design', 'build']
print(next(t for t in result.tasks if t.id == "build").early_finish)   # 2026-01-23
print(next(t for t in result.tasks if t.id == "docs").total_float)     # 12 days, 0:00:00
```

Fifteen working days across two weekends, computed on a Mon–Fri calendar — and `docs`, off the critical path, carries twelve days of slack before the date moves. Check it against MS Project. That is why the engine ships on its own.

All four dependency types, lead/lag on every link, multi-calendar composition, cycle detection with the offending path, and Monte Carlo with per-task sensitivity. [Full engine reference →](/features/scheduler/) · [View on PyPI →](https://pypi.org/project/trueppm-scheduler/)

## 5-minute local demo

:::tip[Just want to look, not install?]
Two zero-config paths — a hosted read-only demo at `try.trueppm.com` and a
one-command local demo (`docker compose -f docker-compose.demo.yml up`) — **ship
with the 0.4 beta**; the [**Try it**](/getting-started/try-it/) page previews
them. Until 0.4 tags, the dev stack below is the fastest way to a populated
instance — six persona logins, full write access.
:::

```bash
git clone https://gitlab.com/trueppm/trueppm.git && cd trueppm
docker compose up -d
docker compose exec api python manage.py seed_demo_project --with-personas
# Web UI → http://localhost:5173   (six persona logins, password: demo)
# API    → http://localhost:8000/api/schema/swagger-ui/
```

The persona password is `demo` because the local Docker stack runs with `DEBUG=True`; on a non-dev install the seed prints a one-time random password unless you set `TRUEPPM_DEMO_PASSWORD`. See [`seed_demo_project`](/administration/management-commands/#seed_demo_project).

Just want the math, not the platform? That's [the engine package](#start-with-the-engine-not-the-platform) above.

**Stack:** Django 5.2 + Channels · React 19 + Vite · PostgreSQL 16 + ltree · Apache 2.0

## Ready for teams of people — and agents

Software teams increasingly run work across people *and* AI agents: an agent drafts, a human reviews. That breaks a fifty-year assumption baked into every project tool — that a task takes days and a person does one thing at a time. TruePPM's scheduling-first engine is built to model it honestly, and the difference between *effort* (work content) and *duration* (elapsed time) is the seam that makes it possible.

Starting in **0.5**, TruePPM will represent AI agents as first-class *resources* — separating effort from duration so an agent's throughput and round-the-clock availability no longer have to masquerade as an 8-hour human day, and giving a team a **team-owned** read on when its own review queue, not authoring, has become the bottleneck. The engine depth — sub-day scheduling, a probabilistic human-fallback branch, and reporting whose true unit is the length of the human-bound critical path — will follow in 0.6.

One principle is load-bearing here, and it is why we built the pillar the way we did: that review signal belongs to the **team**, opt-in to roll upward — never a management dashboard. See [**Team ownership is not surveillance**](/overview/team-ownership-not-surveillance/). AI that *does* the scheduling for you — auto-optimization, cross-program agent leveling — is the enterprise layer, after 1.0. TruePPM plans *for* hybrid teams; it does not take the plan out of their hands.
