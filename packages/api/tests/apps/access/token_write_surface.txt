# Token-reachable write surface — pinned inventory (#2772).
#
# Every route in this file accepts POST/PUT/PATCH/DELETE from a personal access
# token carrying the full scope — `api:full`, the DEFAULT scope for a newly minted
# token since #4388 (apps/projects/models.py, _default_api_token_scopes), or
# `legacy:full`, the same scope under its original name, which every token minted
# before #4388 carries. Both names authorize exactly the same routes
# (`has_full_scope`), so this inventory is the same for either. The scope
# taxonomy that would let a write be withheld is 0.6 work (#2661); until then,
# "has a token" means "can write here".
#
# READ THIS BEFORE TRUSTING THE FILE'S HISTORY (#2877/#2878). Until 0.4 the walker
# that generates it decided reachability from class-level `permission_classes`, and
# `TokenReadOnlyMethods` is contributed at *runtime* by `McpReadableViewMixin`. So
# the ~50 unsafe routes on the eight MCP-wrapped viewsets (tasks/, projects/,
# risks/, labels/, sprints/, programs/, backlog-items/, board-config/) were listed
# here while they actually 403'd every token. #2877 made them genuinely writable and
# produced NO diff in this file — the tripwire could not see the widening it exists
# to report. Those lines became true in 0.4; they were aspirational before it.
#
# Seven routes left the set in the same change: the six `api-tokens/` ones plus
# `me/credentials/<provider>/`. Credential management is session/JWT-only since
# #2878 (`IsNotTokenAuthenticated`), so a leaked token can no longer mint sibling
# tokens, revoke the owner's live ones, or overwrite the owner's connected-account
# credential. `me/connections/<source>/` left later, in #4532 (same credential, a
# different viewset); its `/sync/` trigger is a read-only pull and stays token-writable.
#
# Three more left the set in #3551: the SSO provider admin routes
# (`workspace/sso/providers/` and its item + `test-connection/`). Provider config is
# session/JWT-only for the same reason — an admin's leaked token could set
# `auto_create_members` with an ADMIN `default_role`, widen `allowed_email_domains`,
# or rotate the IdP secret, and one SSO login at the widened domain then mints a
# durable ADMIN session that revoking the token does not touch.
#
# Three more left the set in #4461, which also fixed the walker: it read only
# class-level `permission_classes`, so a guard added per-action through a
# hand-rolled `get_permissions` (exactly what `WebhookViewSet`/
# `ProgramWebhookViewSet` do for `create`/`update`/`partial_update`, and what
# `ProjectShareLinkListCreateView` already did for its POST branch since #2939)
# was invisible to it — the same blind spot #2877 recorded above, from the other
# side. `projects/<project_pk>/webhooks/$` and `programs/<program_pk>/webhooks/$`
# left the set because POST — their only unsafe method — now refuses a token
# caller; their detail/`test/` routes stay listed below because DELETE and the
# test-ping POST remain token-reachable on purpose. `projects/<project_pk>/
# share-links/` left the set too: its POST has refused a token caller since
# #2939, but the old walker could not see that either, so this line had been
# stale since before #4461 touched anything.
#
# One more left the set in #4462: `ws/ticket/`. Minting a WebSocket ticket is
# session/JWT-only since `IsNotTokenAuthenticated` was added to
# `WebSocketTicketView` — a ticket opens a live socket the consumer authenticates
# exactly once, at connect, so a PAT-minted ticket would have no later revocation
# lever that could reach the open socket, unlike the grants above.
#
# Eighteen more left the set in #3847: the membership family. A workspace invite
# (create/delete/resend/resend-all), member role change and removal, group membership
# and group->project grants, `transfer-ownership`, project `transfer/` and program `transfer-sponsorship/` (each promotes a member to OWNER), the create path of the project and
# program membership viewsets, team membership PATCH (`teams/.../members/<pk>/`, which can grant team ADMIN), and the workspace export trio all mint authority (or
# exfiltrate data) that revoking the leaked token does not undo, so they refuse a token
# caller. `workspace/export/` left the set; its `<job_id>/` and `/download/` GETs were
# never in it (safe methods). Project/program `export/` stay listed on purpose: only the
# workspace export was ruled on (#3847); the others are a deliberate non-goal. `projects/.../members/<pk>/` and `programs/.../members/<pk>/`
# stay listed on purpose: their DELETE (removing access, or self-removal) remains
# token-reachable; only create/update/partial_update are session-only.
#
# None of these routes writes an AgentAction row (#2749). A machine-authored
# write is attributed to the token's human owner via historicaltask.history_user.
# That is the gap 0.5 (#2745, #2749) closes — this file is its checklist.
#
