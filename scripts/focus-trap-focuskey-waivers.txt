# Each line waives ONE focus trap the detector flags but that does not violate
# web rule 362, and says why. Format, tab-separated:
#
#     <path>::<refName><TAB><reason>
#
# A waiver is a claim that the pending-flag `disabled=` the detector saw is
# OUTSIDE this trap container, is validation-only, or belongs to a phase swap
# that unmounts rather than disables. It is not a claim that the dialog is
# unimportant, and it is not a place to park work.
#
# THIS LIST ONLY SHRINKS. Two ratchets enforce that, and both are in the gate:
#   * an entry that no longer matches anything fails as STALE — fixing a trap
#     forces its line out of this file rather than leaving a fossil behind;
#   * the entry count may not exceed WAIVER_BASELINE in the script.
# Adding a line means lowering nothing and raising the baseline, which the gate
# refuses. If a genuinely new false positive appears, tighten the detector.
#
# Be honest about what a waiver buys: like `--update-baseline` on the docs gate,
# it cannot stop a wrong answer. What it removes is the silence.
#
