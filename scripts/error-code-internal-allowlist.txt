# Codes raised with a `code=` keyword that never reach the response body (#4376).
#
# DRF's exception_handler collapses `code` to a Python-side attribute on the
# ErrorDetail string subclass when `detail` is a plain string (or a dict whose
# value is a string, including a field-keyed ValidationError) — the wire body
# is just {"detail": "..."} or a field-keyed message, with no sibling `code`
# key. errors.md's "Codes that exist in code but not on the wire" section
# (#2550) explains this at length and names a few of these by example; this
# file is the complete, checked list the #4376 audit's AST scan found.
#
# One "<code>\t<reason>" per line. This is NOT a waiver for an integrator-facing
# code — a new literal `Response({"code": "...", "detail": "..."})` or
# `warnings.append({"code": "...", ...})` dict belongs on errors.md, not here,
# and scripts/check-error-codes-documented.py cannot tell the difference. A
# human decides on each new failure.

# ADR-1153 actual-date rules (actual_date_rules.py) — raised via
# `_raise_actual_date_violation`, which wraps each in
# `serializers.ValidationError({field: ErrorDetail(message, code=...)})`: a
# field-keyed ValidationError, so `code` is lost.
actual_dates_out_of_order	Field-keyed ValidationError (ErrorDetail on `actual_finish`) — #2550 shape.
actual_date_in_future	Field-keyed ValidationError (ErrorDetail on the checked field) — #2550 shape.
actual_date_outside_span	Field-keyed ValidationError (ErrorDetail on the checked field) — #2550 shape.
actual_finish_requires_signoff	Field-keyed ValidationError (ErrorDetail on `actual_finish`) — #2550 shape.
